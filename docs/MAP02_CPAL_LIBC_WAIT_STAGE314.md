# MAP02 Stage314 — opt-in libc poll entry/return phases on the proven native CPAL callback thread

**Research-only Draft / DO NOT MERGE.** Stacked on [Stage313 Draft PR #434](https://github.com/stanmasked/vandal-hearts-switch-remaster/pull/434), whose actual [GitHub Actions #39601213885](https://github.com/stanmasked/vandal-hearts-switch-remaster/actions/runs/39601213885) proved the exact native Linux CPAL thread via a **private same-process kernel TID bridge**. In that source-verified trial at requested 21ms a genuine CPAL callback occurred **once before first guest input, then zero times** in the guest window. That same native Linux thread sampled sleeping in `poll` in 93/93 guest task samples, with zero CPU tick growth. At 22ms the proven CPAL task had **690 pre-input callback markers**, **2265 during input**, 8 CPU ticks of growth, yet was still sampled sleeping in `poll` in 93/93 task observations. Thus `poll` sleeping is not by itself a hardware or OS failure.

## Stage314 purpose and exact controlled code scope

Test whether the proven CPAL native thread makes progress through **exported libc userspace wait boundaries**, and whether any call remains observed in flight at the last bounded 200ms sample. The prior source-pinned original experimental Linux NeXium ELF SHA256 `e5ddfc61ac9435dc5a6e2dcd569766db0c444bbdeef8a3fa6a65c9c2e9fc6f25` and generated-original-ROM-free research NRO SHA256 `371c9fd9f1f41ad87cbb5f7f96a3e5e9d56878f8cfff2bf7fea2c17120c2611b` remain **byte-identical** in both independent 21/22ms trial jobs.

The new independent `LD_PRELOAD` experimental shim starts from Stage313, preserving the original Stage305 exported ALSA operation return-class counters, Stage311 13 exported ALSA begin/end/negative-return counters, Stage308 per-TLS true CPAL marker, and Stage313 private once-per-native-thread `SYS_gettid` join. Four additional libc symbol wrappers (`poll`, `ppoll`, `epoll_wait`, `epoll_pwait`) call the exact corresponding next real symbol with the **same original function arguments** and record only `begin`, `return`, `negative-return` counts per already-anonymized TLS alias via relaxed atomic counters. The four-by-three counters occupy a newly bounded 64-ALIAS region at existing private mmap byte offset **54784**, with compile-time offset and 65536-byte size assertions.

The only additional code in the actual callback process is before/after user-space libc exported-function calls. The existing Stage309 CPAL callback hook is *unchanged*. The existing Stage313 one-time `SYS_gettid` during first TLS alias creation may occur on a real-time callback and is explicitly intrusive. The libc wrappers may be intrusive as well, changing scheduler decisions, symbol resolution, Pulse/ALSA behavior or the 21/22ms outcome. **These are requested Pulse hints, not exact hardware-buffer latency measurements.**

## Exact source provenance and expected report

An external Python observer reads original Stage311 ALSA counters and Stage308 CPAL tag counters **and** the Stage314 libc wait-phase counters from the exact same private mmap at the **same 200ms monotonic sample times**. The Stage313 separate `/proc` collector continues to establish true native thread identity via a **private-only TID**; no raw native TIDs/PIDs, thread names, raw PCM, kernel arguments, fd arrays, socket addresses, memory pointers, filenames or the process map are uploaded.

A source-only Stage314 auditor **re-executes the Stage313 real original ELF/NRO, Stage312 Linux task audit, Stage311 ALSA source, Stage310 callback P/L and Stage308 private tagged native-thread join** before accepting the new libido wait rows. It checks monotonic unsigned counters, actual 21/22ms input/final markers and exact equality of 200ms ALSA, CPAL and libc source observation timestamps. For every libc function and anonymous TLS alias (not only audio), the report includes begun/returned/negative-returned deltas, number of source snapshots with entered-but-not-yet-returned calls, sampled maximum in-flight and last sampled in-flight calls. Only aliases with **positively source-verified CPAL callback markers before input** are described as CPAL owned.

A tagged CPAL alias can have zero additional wait calls in the guest window but a pending call that started before input. That would support an observable **finite-trace boundary** but **not** prove that the call is a permanent block or that it should have awakened. Any snapshot can see independently sampled relaxed atomics between the begin and return increment. Some glibc internals or libraries call direct `syscall`, use `select`/`pselect`, futex/eventfd or hidden symbols that these four wrappers do not intercept; **no wrapper coverage means no visibility, not no actual waiting**. No eventfd wake origin, exact kernel stack, poll return-time duration or definitive CPAL root cause is obtained here.

No PS1 game ROM/official soundtrack, Nintendo Switch speaker/DAC, production audio repair, changes to `main`, original source/game, upstream NeXium or published binary replacements are part of Stage314.
