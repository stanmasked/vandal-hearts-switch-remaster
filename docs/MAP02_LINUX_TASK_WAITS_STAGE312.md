# MAP02 Stage312 — actual Linux /proc task state and categorized wait-channel audit

**ROM-free research only. Experimental Draft; DO NOT MERGE.** This extends successful [Stage311 PR #423](https://github.com/stanmasked/vandal-hearts-switch-remaster/pull/423), [real Actions #39595844148](https://github.com/stanmasked/vandal-hearts-switch-remaster/actions/runs/39595844148) (2/2 valid source-reparsed 21ms/22ms guests). Baseline: 21ms had **zero CPAL callback entries after input** while a separate high-rate ALSA userspace alias made **287343 `snd_pcm_writei` calls, all returned**. At 22ms the direct native TLS callback alias completed **2264 `snd_pcm_writei` entries/returns** and an independent ALSA alias made **289940 successful `writei`**. The original research optical 8-page CRC was unverified at 21ms and passed at 22ms. Stage311 found no sampled permanently outstanding exported `snd_pcm_writei` in either case; it did **not** establish ALSA root cause.

## New independent read-only observer

Stage312 preserves the **exact same Stage309 opt-in compiled new NeXium ELF** SHA-256 `e5ddfc61ac9435dc5a6e2dcd569766db0c444bbdeef8a3fa6a65c9c2e9fc6f25`, and the **exact unchanged original generated ROM-free NRO** SHA-256 `371c9fd9f1f41ad87cbb5f7f96a3e5e9d56878f8cfff2bf7fea2c17120c2611b`. It leaves the Stage311 experimental 13-symbol ALSA entry/return shim, Stage308 opt-in CPAL callback marker, virtual 48k PulseAudio capture, generated guest input, P/L tracing, and guest optical check unchanged.

The new launcher starts the existing, previously used [Stage302 read-only Linux task sampler](https://github.com/stanmasked/vandal-hearts-switch-remaster), **only on the NeXium child process**, before the guest-input timestamp. It samples `/proc/<pid>/task/<tid>/stat`, `comm` and `wchan` approximately every 250ms using ordinary unprivileged filesystem reads—**no ptrace, perf permissions, thread signals, host source modifications, ALSA probe in the callback or extra modified CPAL code**.

The process ID and native thread IDs are used only transiently inside the private runner to find `/proc` files. They are **never emitted**. Recorded source CSV uses one-per-run anonymous task alias and reduces thread names to either `AUDIO_NAMED` (an audio/CPAL/ALSA substring) or `UNATTRIBUTED`; raw names, OS stack traces, memory pointers, filesystem path details and arbitrary wait symbols are never published. The kernel states (e.g., running, interruptible sleep) are recorded from the original `/proc` stat; `wchan` is normalized to a short predefined wait-category allowlist or `UNKNOWN/OTHER`.

## What can actually be concluded

A separate Stage312 auditor **first re-executes the true Stage311 source-verified CPAL P/L, ALSA callback marker and 13-function exported ALSA phase audit** on the real new-host ROM-free guest; it rejects a changed original receipt, host ELF SHA, guest markers or shortened source samples. It then independently source-reparses the previously validated Stage302 task CSV and compares the guest first-input/final-observation timestamps with the Linux task clock. It computes per-anonymous-task CPU tick growth, state histogram, categorized wait histogram, number of consecutive task snapshots sharing the same state or wait category and presence of name-based audio hints.

**Hard attribution boundary:** Stage312's anonymous `/proc` task IDs and Stage308's process-local `__thread` CPAL/ALSA aliases are **two different namespaces**. There is deliberately no identity bridge. A task named "audio" is **not** a source-proven CPAL thread, even if its CPU tick count changes. A kernel `futex` or `ep_poll` wait-channel category at one, several or many 250ms snapshots is **not** evidence of a permanently blocked callback or causal `snd_pcm_writei` deadlock. A task may be legitimately sleeping or waiting for work. Empty `wchan` can be due to kernel access restrictions. Even when 21ms has no callback, it is not possible to identify its unobserved owner by matching Linux task data to the (absent) CPAL markers.

The read-only task observer itself adds scheduling overhead; the 21ms/22ms Pulse latency settings are requested hints, not exact hardware period measurements. The workflow does **not force the outcome to replicate Stage311** and must report the true result. This investigation cannot validate physical Nintendo Switch DAC/audio, actual Vandal Hearts licensed ROM/music fidelity, a production audio repair, any permanent kernel deadlock, or a CPAL scheduler root cause.
