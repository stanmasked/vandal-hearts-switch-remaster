# MAP02 NeXium virtual PCM negative control

This is a **research-only, Draft, DO NOT MERGE** child of the validated
MAP02+native audio prototype in PR #196. It performs no changes to game C code,
the MAP02 renderer, audio engine, Switch input loop, `main`, or the regular
Makefile. The game and binary build contract remain exactly as previously
validated. Only a stdlib-only virtual PCM contrast tool, eleven synthetic
negative tests and a separate GitHub workflow are added.

## Why add a video-only control?

PR #196 already passed exact-head NeXium: MAP02 frame/input checks, an
`AUDIO ACTIVE` guest status marker, and 45.123 s of nonzero virtual PulseAudio
PCM (RMS 638.094, 1,528,968 samples with abs(amplitude)>=256). That confirms
virtual monitor data but does not by itself rule out sounds generated by the
emulator or host environment.

This new workflow first captures the untouched video-only MAP02 NRO and then
the experimental MAP02+native audout NRO sequentially, with the **same
headless NeXium runner, PulseAudio null sink, output format and analysis
thresholds**. The shared workflow manifests both NRO SHA-256 values and rejects
identical or mismatched binaries.

## Exact scope of the verifier

`tools/verify_map02_audio_control.py` requires:
- A complete and distinct pair of same-run SHA-256-verified control/audio NROs
  with run ID, attempt and Git source SHA.
- At least 30 seconds of stereo 48-kHz, 16-bit raw PCM from *each* NeXium run.
- The video-only control's virtual PCM has RMS < 32 and fewer than 9,600
  amplitude samples >=256; otherwise reject the comparison.
- The audio-enabled run's virtual PCM has RMS >=32, at least 9,600 amplitude
  samples >=256, RMS at least 5 times the control, and an observed NeXium
  PulseAudio sink input.
- A result explicitly labeled `CONTROLLED_VIRTUAL_AUDIO_CONTRAST` only if all
  conditions pass. Unknown manifest schema, missing bytes or invalid recordings
  fail closed; a report still records the rejection.

`tests/test_verify_map02_audio_control.py` has eleven asset-free synthetic
tests for quiet control, silent experiment, loud control, missing sink, too-short
recordings, hash mismatches, identical NROs, incomplete stereo frames and
invalid run identity.

**A passing contrast is not a perfect controlled experiment.** The captures
are sequential rather than sample-aligned, their guest activity and emulator
timing can vary, and monitor output is not a speaker. The gate does not claim
original music identity, a specific STUDIO_C reverb tail, auditory fidelity,
or output on a physical Nintendo Switch. Those remain distinct next stages.

Full verification is in `.github/workflows/map02-audio-negative-control.yml`.
Keep parent PR #196 and this test-only child Draft until independent review.
