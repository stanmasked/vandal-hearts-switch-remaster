# MAP02 — строгая привязка исходных граней к пакетам GPU FT4

Инструмент `tools/verify_map02_source_native_ft4_join.py` объединяет
**два ранее независимо проверенных приватных комплекта**, не копируя
оригинальные игровые ресурсы в репозиторий:

1. [MAP02 private frame bundle](MAP02_PRIVATE_FRAME_BUNDLE.md):
   декодированная карта (187264 байта), 1-МиБ эталон VRAM, журнал
   исходных граней и наблюдённые значения GTE.
2. [Native GPU capture](MAP02_NATIVE_GPU_CAPTURE.md):
   отдельный захват реальных шагов `DrawOTag` PC-порта с GPU-пакетами
   и снимками VRAM до/после каждой операции.

При наличии подлинных данных инструмент сможет проверить, как
конкретная исходная грань `(record_index,face_index)` соотносится
с обработанным GPU-пакетом. **Он не создаёт исходные данные сам.**

## Привязка разных часов

`gState.frameCounter` игровой логики и `s_drawFrame` GPU backend
нельзя считать одним и тем же счётчиком. Даже совпадение номеров
не удостоверяет общий момент времени.

Создайте `gpu-face-join.json` **в приватной папке исходного MAP02
bundle** со следующим содержимым:

```json
{
  "schema": "vh.map02.source-native-ft4-join.v1",
  "source_frame": 411,
  "gpu_draw_frame": 12,
  "bundle_manifest_sha256": "<64 lowercase hex>",
  "native_events_sha256": "<64 lowercase hex>"
}
```

Здесь `source_frame` — номер из `bundle.json`,
а `gpu_draw_frame` — номер именно того вызова `DrawOTag`,
которому соответствует захват. **411 и 12 — вымышленные примеры**.
Связь этих номеров должна быть независимо установлена при локальном
захвате. SHA-256 вычисляется от **точных байтов файлов**
`bundle.json` и `gpu-native-events.jsonl`.

Из корня ремейка:

```sh
python3 -m tools.verify_map02_source_native_ft4_join \\
  /private/map02-frame /private/map02-gpu-capture \\
  > /private/map02-source-gpu-join-report.json
```

## Что обязано совпасть

Сначала повторно проходят **обе независимые проверки**:
целостность карты и журналов, все 12 исходных координат,
точные номера граней, компьютерная модель оригинального GTE,
UVWH, CLUT, texture window, а также полные последовательные
пары снимков VRAM. Подменённый файл не допускается до связывания.

Для каждой исходной *normal terrain* грани программа собирает
пакет `POLY_FT4` в оригинальном GPU-порядке:
`face[0], face[1], face[3], face[2]`.
Соответствие требует точного равенства:

- восьми экранных координат GPU XY;
- восьми чисел UV:
  `(u,v), (u+w,v), (u,v+h), (u+w,v+h)`;
- оригинального `tpage` и `CLUT`;
- четырёх значений `GP0(E2)` texture window.

Каждая исходная грань должна иметь **ровно один кандидат** среди
записанных FT4; ни один GPU-пакет не должен подходить двум
исходным граням. Нельзя связывать только по GFX, UV, глубине
или порядку пакетов в `DrawOTag`. Если кандидат отсутствует
или одинаковый пакет встречается несколько раз, результат
**отклоняется как неоднозначный**, а не угадывается.

Также сравниваются реальные 16-битные слова **текстуры и
индексируемых элементов CLUT** из статичного MAP02 bundle с
`gpu-NNNN-vram.bin` непосредственно **до выбранного примитива**.
Сравниваются адреса, используемые обеими VRAM, чтобы изменение
индекса текстуры не могло скрыть иной выбор палитры.

При этом сравнение **всей** видеопамяти не требуется:
предыдущие полигоны могли изменить область целевого
кадрового буфера, не затронув текстуры проверяемой грани.

## Что этот этап не устанавливает

- Наличие подходящего GPU-пакета и совпадающих байтов **не
  удостоверяет** подлинность события: оба журнала могут быть
  изготовлены вручную, а SHA подтверждает только целостность
  предоставленных файлов.
- Статичный VRAM bundle может не соответствовать реальным
  текстурам во всех фазах кадра. Если нужные слова между
  снимками изменились, проверка справедливо откажет.
  Для такого случая потребуется объединение с
  [per-submission VRAM timeline](MAP02_VRAM_SUBMISSION_TIMELINE.md).
- Результат не доказывает полноту всего `DrawOTag`,
  реальный порядок поступления исходных `AddPrim`, AVSZ4-глубину
  у конкретного GPU-пакета или точность физического GPU PS1.
- Диагностический регистратор ограничен 64 записями.
  Если предел достигнут, нельзя удостоверить отсутствие
  второго совпадающего пакета; проверка отказывает.
- Дополнительные GPU-примитивы — спрайты, элементы UI,
  сторонние FT4 — допустимы, если они **не создают
  неоднозначности** для предъявленных исходных граней.
- CI использует только воспроизводимые вымышленные MAP02,
  GTE и VRAM, не подлинный игровой захват и не запуск игры
  на Nintendo Switch.

Результат — **только агрегированные счётчики и хеши**:
число сопоставленных граней, проверенных исходных слов
VRAM и флаги проверок. Отчёт не содержит исходных
координат, цветов, материалов или игровых ресурсов.
