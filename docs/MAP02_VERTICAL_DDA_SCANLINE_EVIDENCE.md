# MAP02 — доказательства вертикального отсечения строк в DDA

Опциональный инструмент `tools/instrument_map02_vertical_dda.py`
наблюдает **четыре действительно выполненные ветки**
оригинального `dda_part` в закреплённом PC-порте
`HalmyLyseas/VandalHearts-PcPort`
(`14552fffa0e0b47e02b57592e274fc6e7a649923`).

Это продолжение
[предыдущей диагностики текстурных пропусков и горизонтального отсечения](MAP02_NATIVE_RASTER_SKIP_REASONS.md).
Генерируются отдельные `libgpu.vertical.c` и
`pc_raster.vertical.c`, а оригинальные исходники
остаются неизменными.

## Что наблюдается

| Код | Участок оригинального DDA | Проверяемый результат |
|---|---|---|
| 4 | Перевёрнутый обход, `y < clipT` | Выполнен `break` из-за нижнего относительно направления обхода выхода за верхнюю границу drawing area |
| 5 | Перевёрнутый обход, `y > clipB` | Выполнен `continue`: отрисовка этой строки пропущена |
| 6 | Прямой обход, `y > clipB` | Выполнен `break`: дальнейшие строки ниже области рисования не обрабатываются |
| 7 | Прямой обход, `y < clipT` | Ветка `dda_span` не выполнялась для строки |

События записываются **только для выбранного Y** и
содержат выбранный X как идентификатор диагностической
точки, а также номер кадра `DrawOTag`, порядковый номер
GPU-примитива и его тип.

**Важное разграничение:** событие подтверждает, что
отрисовка *строки* была отброшена/пропущена оригинальным
DDA-кодом. Оно **не подтверждает**, что выбранный X
на этой строке лежал внутри треугольника до вертикального
отсечения. Таким образом, это не полноценное доказательство
покрытия или точной причины отсутствия конкретного пикселя.

## Сборка и локальное выполнение

Из корня репозитория ремейка:

```sh
python3 -m tools.instrument_map02_vertical_dda \
  /private/VandalHearts-PcPort/platform/pc/src/libgpu.c \
  /private/VandalHearts-PcPort/platform/pc/src/pc_raster.c \
  --output-dir /private/dda-vertical-build
```

Обе созданные копии необходимо собрать **вместе**,
вместо оригинальных файлов PC-порта, с флагами:

```text
-DVH_MAP02_GPU_CAPTURE
-DVH_MAP02_PUTPIXEL_SCOPE
-DVH_MAP02_RASTER_SKIP_TRACE
-DVH_MAP02_DDA_VERTICAL_TRACE
```

Последний флаг требует предыдущего регистратора
`VH_MAP02_RASTER_SKIP_TRACE`; несовместимая
конфигурация отвергается при компиляции.

Установить приватные переменные окружения:

```sh
export VH_MAP02_GPU_CAPTURE_DIR=/private/dda-capture
export VH_MAP02_GPU_CAPTURE_FRAME=12
export VH_MAP02_PUTPIXEL_DIR=/private/dda-capture
export VH_MAP02_PUTPIXEL_FRAME=12
export VH_MAP02_PUTPIXEL_X=30
export VH_MAP02_PUTPIXEL_Y=30
```

Пути должны быть действительными и приватными;
значения координат и кадров **придуманы для демонстрации**.
Доступны прежние журналы VRAM, `PutPixel`,
а также `putpixel-native-skips.jsonl`
с расширенными кодами 1–7.

Валидатор остаётся прежним:

```sh
python3 -m tools.verify_map02_raster_skips \
  /private/map02-source /private/dda-capture \
  > /private/dda-vertical-report.json
```

Нужны локальные `gpu-raster-skips.json` и
все SHA-256-связанные исходные комплекты MAP02/GTE,
FT4/UV/CLUT/OT и снимки VRAM из предыдущих этапов.

Отчёт содержит только хеши и агрегированные
счётчики по четырём веткам, включая число
наблюдений, согласованных с конкретными исходными
гранями MAP02. Он не содержит цветов, координат,
геометрии или игровых ресурсов.

## Границы достоверности

- Счётчик равен числу фактически записанных событий
  выбранной строки, а не количеству всех отброшенных
  пикселей или всей видимой площади.
- Выбор X не доказывает, что треугольник покрывал этот
  X. Для такого вывода потребуется отдельно
  восстановленная граница DDA на выбранной строке.
- Пропущенная строка не показывает, был ли тексель
  прозрачным: выборка текстуры для неё не выполнялась.
- Тесты CI работают на синтетических журналах.
  Ни настоящий кадр MAP02, ни физическая PS1 GPU,
  ни Nintendo Switch с оригинальными ресурсами
  этим результатом пока не проверены.
- Исходный регистратор ограничен 64 событиями
  и отказывает при достижении лимита в валидаторе.
  Подлинность происхождения предоставленных журналов
  SHA-256 сама по себе не удостоверяет.

Следующим этапом должна стать проверка
**геометрических интервалов покрытия в DDA**:
наличие пересечения с выбранным X внутри строки
до и после горизонтальных/вертикальных ограничений.
