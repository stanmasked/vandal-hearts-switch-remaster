# Vandal Hearts Remake — Stage334 independent genuine NeXium capture witness

Stages328–333 analyzed two previously collected, successfully source-audited original NeXium runs. [Stage333 #39174673214](https://github.com/stanmasked/vandal-hearts-switch-remaster/actions/runs/39174673214) confirmed that the second source first reverses its previous-call median ordering after deleting five earlier calls, while the first source's final successful call is shorter than every previous retained call. These are bounded guest software service-call measurements, not audible sound.

Stage334 resumes **new live capture collection**. The existing `Experimental NRO runtime smoke test` builds and runs the original game NRO under NeXium using its already established guest sound events and host PulseAudio null-sink PCM capture. **No game or SPU instrumentation changes.** A new final source manifest step runs *after* the original independent Stage304/305 PCM checks and after the Stage325 unchanged-source verification, before the original artifact upload.

`tools/audit_nexium_stage334_capture_manifest.py` reopens **nine already produced original per-run evidence files**: the two guest software CSVs, Stage320/322 receipts, two host clock CSVs, Stage325 receipt, and strict Stage304/305 receipts. It recomputes the exact Stage322 guest call history from source bytes, verifies the original Stage320 last-call CSV SHA, recomputes Stage325 host clock pairs, checks exact event/byte/epoch identity to strict Stage304 and requires successful source-authentic Stage305. Then it writes a *compact* `source-guest-host-stage334.json` manifest into `runtime-evidence`, which is already included in the original workflow artifact `nexium-runtime-evidence`.

The manifest records **all four newly observed original source SHA-256 hashes**, guest software last-call duration, prior successful-call median (when an authentic baseline is available), rank/comparison counts, and host wall-clock/monotonic/file-size event *deltas*. It does **not** publish absolute host or guest timestamps, original PCM content or music assets. It explicitly declines to align guest clocks with host PCM, DAC, speakers or physical Nintendo Switch sound.

Unlike Stages328–333, Stage334 **does not require the new capture's final call to be shorter than its prior-call median**. Such a disagreement is valuable authentic new data, not a synthetic verification failure. Ten synthetic acceptance/rejection tests cover unchanged original sources, a slower new call, altered source bytes, forged prior receipts, mismatched Stage304 and the absence of absolute clock epochs in the compact report.

The actual new [NeXium workflow #39175592570](https://github.com/stanmasked/vandal-hearts-switch-remaster/actions/runs/39175592570) **completed successfully**, with the original NRO guest execution, host PCM capture, strict Stage304/305, unchanged Stage325 clock source and the final Stage334 source receipt all independently successful.

New original guest normal `PlayBuffer` last-call service bracket: **18,486,979 guest software ns**. Lower median of preceding successful retained calls: **32,374,948 guest software ns**. Host wall event intervals: **324 ms / 4,221 ms**; host monotonic intervals: **324,470,642 ns / 4,220,779,386 ns**. Host PCM file-size deltas: **63,436 / 820,420 bytes**. No guest-host timing synchronization follows.

Subsequently, the [independent three-original source replay #39176524278](https://github.com/stanmasked/vandal-hearts-switch-remaster/actions/runs/39176524278) also **passed 13/13 source and negative-control tests** and independently recomputed the third original archived Stage334 receipt exactly.
