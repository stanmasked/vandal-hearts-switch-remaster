# MAP02 v45 — bounded user-owned PRS preflight before HD texture integration

**Verified CI:** [GitHub Actions № 38915750567](https://github.com/stanmasked/vandal-hearts-switch-remaster/actions/runs/38915750567), GCC and Clang **SUCCESS**.

The v45 preflight is a read-only Python tool for a legitimate user-supplied
\`M_MAP02.PRS\`. It does **not** attempt to run the game, replace any
textures or upload the decompressed original geometry.

## Production-source facts

Pinned public PC-port: \`HalmyLyseas/VandalHearts-PcPort\` at
\`14552fffa0e0b47e02b57592e274fc6e7a649923\`.

In \`src/states/game_setup.c::LoadMap\`, \`gState.mapNum == 11\` selects
\`CDF_M_MAP02_PRS\` and its **28×12** storage grid (map area 24×12).
Actual raw \`MapTileModel\` instances are **304 bytes** each: 22 SVECTOR
(8 bytes each), 18 little-endian signed GFX IDs, 18 four-vertex faces,
18 shade bytes, one face count and one height. The full file must decode
to **336 × 304 = 102,144 bytes**.

The original \`src/maps/unpack.c::ProcessMapFileData\` reads a 32-bit
little-endian compressed-byte count from the first 4 bytes and invokes
\`UnpackMapFileData\`, which has no output buffer length parameter.
**Do not give untrusted or damaged files to the original unchecked C
decompressor.** The bounded v45 implementation instead validates the
compressed and output limits before writing any buffer.

## Use on a locally owned file

Run from the repository root:

\`\`\`bash
python3 tools/preflight_map02_prs_v45.py \
  /private/path/to/M_MAP02.PRS \
  --output /private/path/to/map02-v45-preflight.json
\`\`\`

The report contains input and decoded SHA-256 checksums, input sizes,
model/face counts, the histogram of actually encountered game GFX IDs,
coverage by v24 local slots and the missing-slot histogram. It does not
export model vertices, bitmap pixels, or original compressed bytes.

- If the file is sector-padded with **only zeros**, explicitly add
  \`--allow-zero-padding\`; at most 4,096 padding bytes are accepted.
- The input is capped at 2 MiB compressed, decoded data at precisely
  102,144 bytes, and the \`--output\` path is created exclusively
  (no silent overwrite).
- Malformed or structurally unsafe files return **exit code 1** with
  \`[v45-preflight] REFUSED:\`.
- A valid result returns 0 but has status
  \`structurally_valid_unverified_source\` and
  \`retail_map_authenticity_proven: false\`. Correct structure and a
  filename alone **do not authenticate** a retail game file.

The JSON reports \`HD_replacement_approved: false\` unconditionally.

## V24 lookup coverage — important distinction

The checked-in \`tests/fixtures/vh_map02_hd_lookup_v24.h\` was copied
from the user's existing v24 table; it contains 120 entries and 96
canonical masters. The original game uses global GFX IDs and v24 local
slots are addressed by subtracting **400**. A face with global GFX 641
corresponds to slot 241, global 643 corresponds to slot 243. Local slot
242 is deliberately **not** a v24 entry and must never be invented.

The \`.PRS\` model format stores face GFX, vertex indices and shade,
**not** the live texture-page IDs, CLUTs and polygon UVs. Those
are obtained at runtime from \`gGfxTPageIds\`, \`gGfxClutIds\` and
\`gGfxSubTextures\` in \`RenderMapTile\`.

Consequently, preflight reports **potential slot coverage based on
global GFX-400**, not verified texture coordinates. Any global GFX below
400 is classified separately, and GFX at or above 400 that has no
entry is reported as an unmatched candidate rather than silently
treated as an HD texture. This is a diagnostic accounting tool, **not
an automatic renderer/asset authorization gate**.

## What CI actually proves

The v45 workflow \`.github/workflows/map02-v45-bounded-prs-preflight.yml\`
uses a clearly labeled **synthetic** 28×12 map input generated by the
previously verified v44 executable test, with two example faces:

- Global GFX 641 → protected local v24 slot 241 (tpage 5, CLUT 31978).
- Global GFX 643 → protected local v24 slot 243 (tpage 5, CLUT 31850).

The production C \`UnpackMapFileData\` and \`ProcessMapFileData\` are
executed in the same process as original \`RenderMapTile\`,
\`libgte.c\`, \`libgpu.c\`, and \`pc_raster.c\` in GCC and Clang builds.
The new independent Python decompressor then parses **the exact PRS
fixture emitted by this executed C program**; FNV64 of all 102,144
decoded bytes must match the original fixture's native C fingerprint.

Additional verification:

| Check | Result |
|---|---|

| C vs Python full synthetic 336-tile map | Identical |

All six native-vs-Python token fixtures are **literal,
absolute dictionary reference, relative reference, literal run,
overlapping relative reference and overlapping absolute reference**.
The original decoder is called only with **padded, trusted, static
synthetic fixtures**, never with arbitrary files.

For the synthetic rendered scene, framebuffer FNV64 remains:
native \`2f82ee4738d5fe61\`, hi-res \`4a4c04d1e589f743\`.
These are evidence of the synthetic test, not of original MAP02.

Uploaded GitHub proof artifacts include:

binary, synthetic PRS fixture, aggregate JSON, stderr, symbol/object
evidence, native decoder token results and hashes; no retail assets.

## Remaining explicit gates

1. Obtain a legally possessed, authentic \`M_MAP02.PRS\` **locally**.
   It was **not available** for this v45 run.
2. Run the bounded preflight locally. Review structural validity,
   face/GFX counts, v24 matched and unmatched local slots.
3. Load the same game file in a fully linked playable PC-port using
   legally obtained resources; verify actual mapNum 11 faces and
   \`gGfx*\` UV/CLUT in runtime provenance logs.
4. Only then assess opt-in HD replacement on terrain primitives,
   preserving the original STP, blending and draw order.

This is a stacked **draft** PR and is not merged into \`main\`. No Switch
binary or playable full remake is being claimed.
