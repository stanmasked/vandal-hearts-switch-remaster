# MAP02 — наблюдаемые изменения VRAM при наложении FT4

Инструмент `tools/verify_map02_native_overdraw.py` добавляет
проверку **фактических различий слов BGR555 в приватных снимках VRAM**
до и после обработки уже идентифицированных GPU-пакетов FT4.

Он продолжает цепочку
[привязки исходных граней](MAP02_SOURCE_NATIVE_FT4_JOIN.md) и
[порядка AddPrim/DrawOTag](MAP02_SOURCE_NATIVE_OT_ORDER.md).
**Без достоверных локальных игровых данных и захваченных пар снимков
программа не может исследовать реальный Vandal Hearts.** GitHub CI
использует только синтетические буферы.

## Необходимые файлы

В папке приватного исходного `source_bundle` создать файл
`gpu-native-overdraw.json`:

```json
{
  "schema": "vh.map02.native-overdraw.v1",
  "source_frame": 411,
  "gpu_draw_frame": 12,
  "ot_order_manifest_sha256": "<sha256 gpu-ot-order-join.json>",
  "native_events_sha256": "<sha256 gpu-native-events.jsonl>"
}
```

Номера кадров приведены **только для примера**. Хеши должны быть
вычислены по точным байтам приватных файлов. Комплект
`native_gpu_capture` должен содержать все исходные пары
`gpu-NNNN-vram.bin` размером 1048576 байт с полным
`gpu-native-events.jsonl`.

Команда:

```sh
python3 -m tools.verify_map02_native_overdraw \
  /private/map02-frame /private/map02-gpu-capture \
  > /private/map02-overdraw-report.json
```

## Что действительно проверяется

Сначала должны успешно завершиться предыдущие проверки:
подлинной структуры карты как *предъявленного* файла,
проекции по скомпилированной модели PC GTE,
UV/tpage/CLUT/texture window,
сопоставления граней с уникальными GPU-пакетами,
согласованности VRAM непосредственно до их отрисовки,
предъявленного порядка OTZ/LIFO и SHA-256 всех журналов.

Затем программа:

- Проверяет, что **снимок после предыдущей зарегистрированной
  операции побайтово совпадает со снимком перед следующей**.
  Обнаруженный промежуточный эффект, которого нет в журнале,
  приводит к ошибке, а не к догадке о его причине.
- Для каждой сопоставленной исходной грани FT4 считает
  число **изменившихся 16-битных слов VRAM** между её
  `before` и `after`.
- Отдельно считает **уникальные слова**, которые изменялись
  более чем одной исходной гранью в этом захвате.
  Таким образом можно наблюдать повторную запись по
  одному VRAM-адресу в нескольких операциях FT4.
- Подсчитывает переходы 15-го бита BGR555
  `0 → 1` и `1 → 0`. Само изменение этого бита
  **не доказывает работу проверки маски GPU** или конкретный
  режим STP/ABR.
- Считает, какие изменения находятся внутри или вне
  **экранного ограничивающего прямоугольника (AABB)**
  пакета FT4. Это лишь диагностический признак, поскольку
  преобразование экранных координат в VRAM-адреса может
  зависеть от GPU drawing state.
- Не засчитывает изменения от **неидентифицированных**
  спрайтов, тайлов или чужих FT4 как наложение
  двух исходных граней MAP02.

JSON-отчёт содержит только SHA-256, количества наблюдаемых
изменений и явные признаки недоказанных свойств. Оригинальные
координаты, BGR555-цвета, снимки VRAM, камера и текстуры не
публикуются.

## Ограничения

**Наблюдаемое изменение слова — не то же самое, что точная
пиксельная растеризация.** Если GPU записал тот же самый
цвет, изменение памяти не будет наблюдаться. Если слово
не изменилось, нельзя заключать, что причиной была
прозрачность, STP/ABR, проверка маски или отсечение.

Обратно, повторное изменение одного адреса не доказывает,
что это один и тот же пиксель исходных пересекающихся
FT4: на запись влияют drawing offset, drawing area,
состояние буфера и другие GPU-примитивы. Экранный AABB
не равен фактической области заполнения FT4 по
треугольному DDA и правилам half-open clipping.

Равенство соседних снимков также **не исключает** скрытые
изменения и восстановление памяти между захватами.
Сам журнал и номера кадров не аутентифицированы,
а ограничение исходного регистратора в 64 записи
не гарантирует полноту целого кадра.

Проверка STP/ABR, GPU mask-test/write и идентичности
физической PlayStation потребует отдельно исполняемой
оригинальной функции `PutPixel`, параметров GPU
состояния и реального сравнения кадров. Эти свойства
**здесь не заявлены**.

Тесты CI включают синтетические перекрывающиеся FT4,
повторную смену одного VRAM-слова, переходы бита 15,
посторонние отрисовки, потерянную непрерывность снимков,
повреждённые SHA и неверный порядок GPU-пакетов.
