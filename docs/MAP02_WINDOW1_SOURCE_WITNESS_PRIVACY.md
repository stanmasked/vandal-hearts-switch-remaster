# MAP02: cross-window LoadImage and source FT4 witness integration

This stage sits directly above the local per-window LoadImage filename
fix in [Draft PR #382](https://github.com/stanmasked/vandal-hearts-switch-remaster/pull/382).
The parent already demonstrated that an upload at **global event 65**
must be named `window-001/gpu-0001-upload.bin` (local event index 1)
and compiled the pinned PUBLIC original PC-port `libgpu.c` in two-window
opt-in capture mode. The source-to-native window witness is the next
consumer of that format.

## New complete byte-backed synthetic integration fixture

`test_source_ft4_and_witness_survive_window1_loadimage_transfer` creates
a **66-record / 33-operation** bounded native GPU capture using full
1-MiB **invented** BGR555 VRAM snapshots:

- window 000: exactly 64 events, 32 DRAW pairs, with one uniquely matching
  source-keyed FT4 polygon, texture page and palette words;
- window 001: 2 events, one preceding-frame `LoadImage` pair with
  local `gpu-0001-upload.bin` payload and the full cross-window VRAM
  endpoint;
- complete native window status: 32 DRAW, 1 transfer, all hooks present,
  no truncation or incomplete OT walk; exact verification of 32 adjacent
  operation VRAM bridges;
- source claim binds the source event and native window index by SHA-256,
  the native full-VRAM auditor independently verifies the actual bytes,
  and the source-window binder enforces distinct source-vs-PC frame clocks,
  unique FT4 signature, exact source VRAM materials and OT ordering;
- the private-only witness publisher then creates a SHA-256-bound witness
  with exclusive file publication and the verifier rechecks it.

**Important:** the expensive original source/GTE `verify_bundle` is
mocked **only in this test**, while all native window VRAM snapshots,
upload content, file-name checks and witness hashing use actual locally
generated bytes. Passing the fixture is **not** proof of original retail
Vandal Hearts MAP02, PS1 GPU equivalence or source provenance.

The test then changes the valid second-window upload name to the legacy
incorrect **global** `gpu-0065-upload.bin` and asserts the complete
published source witness is refused.

## Fail-closed private CLI error redaction

Previously `tools.verify_map02_source_native_windows` and
`tools.publish_map02_native_window_source_witness` surfaced the text of
raw file verifier exceptions, which could include owner-private source
or VRAM filenames and directories in stdout/stderr or CI logs.

Both entrypoints now emit a generic error and return nonzero without
disclosing the private path or the content of the untrusted capture.
Two direct CLI tests cover the source-window join and both witness
publish/verify modes using deliberately sensitive synthetic path names.

## Acceptance

The dedicated CI checks all 15 native GPU window tests, all 11
source/native FT4-witness and redaction tests, and all three source-pinned
instrumentation contracts. Original game bytes and licensed artwork
are not provided or uploaded. The parent pinned public PC-source C
compilation stays separately verified. All changes stay Draft:
`main` unchanged and the HD asset replacement gate stays closed.
