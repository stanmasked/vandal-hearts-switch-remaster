# MAP02 — Catalina 10.15 ABI metadata for actual C texture helpers

This stage extends the verified, asset-free Catalina-targeted three-face
C11 frame-build proof in Draft PR #354. That earlier stage inspected the
**main standalone frame fixture only**, not the generated programs that
the original-MAP02 PC source/VRAM validators actually compile.

## Three real C helper programs

`tools/map02_catalina_helper_macho_audit.py` reconstructs genuine checked-in
synthetic helper source using the **verbatim** `TPageOrigin` and
`SampleTexture` function bodies from the *pinned public PC port*:

1. **Full 4-bpp page differential** — actual harness from
   `tools/verify_map02_pc_vram4_equivalence.py`, run with deterministic
   invented VRAM: 32 GPU register cases × 65,536 texels, i.e. 2,097,152
   exact BGR555 comparisons.
2. **Three FT4-specific bindings** — actual harness from
   `tools/verify_map02_pc_vram4_ft4_binding.py` using the existing,
   entirely invented C frame fixture. It runs and verifies 196,608 samples
   plus two rejected CLUT/texture-window mutations.
3. **Owner-private timeline Source-to-PC verifier** — the actual compiled
   C helper generated by
   `tools/verify_map02_private_timeline_pc_vram4.py`. This is compiled
   without supplying any source/VRAM/private input bytes; it is executed
   only with **empty stdin** and must fail immediately with its existing
   `missing input` exit code and no output. **No fake successful retail
   capture is invented.**

Every native compiler invocation uses Apple Clang targeting
`-arch x86_64 -mmacosx-version-min=10.15`; generated binaries are
ephemeral and inspected in-place before removal using **both**
`lipo -archs` and `otool -l`. All three must have the exact `x86_64`
slice and `LC_BUILD_VERSION minos 10.15` (or legacy equivalent).
`otool -L` must show **system dylib dependencies only**:
`/usr/lib/` or `/System/Library/`. An `@rpath`, relative DLL,
third-party Homebrew dylib or absent dependency list fails closed.

The source tool's only user input is the *already obtained* **public**
`pc_raster.c` from commit
`14552fffa0e0b47e02b57592e274fc6e7a649923`, verified using
Git blob SHA-1
`ba8a05d161ad778c0b75e452ff0a11ed163c65cd`.
No installed games or private disc are read.

## Command for a connected Intel Mac (without the owner's disc)

```bash
python3 -m tools.map02_catalina_helper_macho_audit \
  /path/to/public/VandalHearts-PcPort/platform/pc/src/pc_raster.c
```

Run from the project repo with a working Apple Clang and macOS 10.15 SDK
target flags supported by the local command-line tools. The output is
sanitized JSON with compiled/executed helper counts, an exact minimum
deployment target, dynamic library category, and explicit false flags
for actual Catalina execution and real PlayStation data.

## Acceptance boundaries

GitHub CI uses **real `macos-15-intel` machines** and both Python 3.9
and 3.11, plus a Linux negative control. Even if these tests pass:

- A 10.15 minimum deployment target means a **build target**, not an
  observed successful run on macOS 10.15.7.
- A system-only dylib dependency list does not by itself prove all
  referenced imported functions existed on the older OS.
- Python 3.9/3.11 packaging, Xcode availability, user hardware and
  filesystem behavior must still be checked on the owner's Mac.
- Actual retail PlayStation frame records, GPU state, private VRAM,
  original game content and Nintendo Switch execution are **not**
  represented by any of these fixtures.

Keep separate Draft PRs; no merges or private asset publication.
