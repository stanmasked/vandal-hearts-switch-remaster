# Vandal Hearts Remake — этап №232: связь предзапусковой сборки с реальными журналами аудио

> **Аппаратный статус — `HARDWARE NOT TESTED`.** Инструмент проверяет непротиворечивость **файлов** и сообщений оператора, но не имеет доступа к физической Nintendo Switch. Подлинность дат, слышимость музыки и независимость запусков требуют ручной проверки.

## Что именно связывается

После [этапа №231](SWITCH_AUDIO_STAGE231_SD_REINSERT_READBACK.md) у оператора есть два host-side файла:

- `before-reinsert-231.json` — исходный NRO, Git SHA, GitHub run/attempt и SHA-256, полученные до ручного безопасного отсоединения SD;
- `reinsert-review-231.json` — сообщение о повторной сверке того же NRO после заявленного переподключения карты.

Оба JSON должны храниться **вне исходного evidence bundle**, а их два SHA-256 должны быть независимо сохранены до анализа. Положительный JSON №231 **не является подписью** и не доказывает истинность заявления о переподключении.

После настоящего исполнения NRO по [первому протоколу №219](SWITCH_AUDIO_STAGE219_FIRST_RUN_PROTOCOL.md) должен появиться отдельный *расширенный* evidence bundle с неизменённым NRO, настоящими диагностическими CSV и новым `audio-evidence-manifest.json`, а также заполненными оригинальными `operator-v2.json` и JSON-карточками сессий №222.

**Нельзя требовать совпадения SHA-256 старого и нового манифеста:** новый манифест закономерно содержит добавленные CSV. Сверяются неизменные идентификаторы **NRO, полный Git SHA, размер бинарника и исходный URL GitHub run**; целостность новых CSV проверяется отдельно.

## Новый инструмент

[`tools/link_switch_audio_device_evidence.py`](../tools/link_switch_audio_device_evidence.py) последовательно:

1. Проверяет независимые SHA-256 двух исходных host-side файлов и строго разбирает их схемы. Подделанный аппаратный `PASS`, отсутствие информации или расхождение run, attempt, Git SHA, NRO, размера либо привязки `recheck → baseline` приводит к `INVALID_EVIDENCE`.
2. Проверяет, что расширенный bundle содержит тот же NRO и Git SHA, а `ci_run_url` указывает на тот же номер GitHub Actions run.
3. Повторяет **полный аудит №222**, включая сценарии H01–H07, чтение всех оригинальных CSV, проверку их SHA-256, звуковых наблюдений и идентичности карточек.
4. Сопоставляет заявленное начало каждой физической сессии с моментом второй host-проверки SD. Если карточка датирована **раньше** повторной проверки, выводит `INVESTIGATE` с `SESSION_CLAIM_BEFORE_VERIFIED_SD_RECHECK`.
5. Выводит идентификаторы исходных CSV и их SHA-256, контрольные хеши двух host-side файлов, контрольный хеш послетестового манифеста, статус аудита и незакрытые вопросы. Все входы только читаются.

Никакой новый CSV, NRO, карточка или результат аппаратного теста не создаются автоматически.

## Команда после реальных испытаний

Когда все материалы получены и сохранены **как оригиналы**, выполните:

```sh
python3 tools/link_switch_audio_device_evidence.py \
  /path/to/post-run-verified-bundle \
  --observations /path/to/operator-v2.json \
  --cards-dir /path/to/session-cards \
  --baseline /safe/outside/before-reinsert-231.json \
  --baseline-sha256 INDEPENDENT_64_HEX_SHA256_OF_BASELINE \
  --recheck-report /safe/outside/reinsert-review-231.json \
  --recheck-sha256 INDEPENDENT_64_HEX_SHA256_OF_RECHECK \
  > /safe/outside/device-evidence-link-232.json
```

Для добровольных дополнительных тестов можно явно добавить `--require-h06` или `--compare-builds`. Без их настоящих свидетельств результат останется `INCONCLUSIVE`. Никогда не отключайте консоль или SD под нагрузкой ради искусственной ошибки.

## Значение ответов

| Поле `result` | Интерпретация |
| --- | --- |
| `READY_FOR_INDEPENDENT_MANUAL_REVIEW` | Байты и самозаявленные сессии непротиворечивы; требуется ручной разбор настоящих запусков |
| `INCONCLUSIVE` | Не хватает карточек, измерений или обязательного сценария |
| `INVESTIGATE` | Противоречивое время, слышимые дефекты, конфликт операторских показаний или ошибок CSV |
| `INVALID_EVIDENCE` | Изменился контрольный SHA-256, NRO, Git SHA, run ID/attempt, манифест или иной обязательный источник |

Завершение с кодом `0` означает только наличие структурированного отчёта — даже если `result: INVESTIGATE`. Код `2` означает, что надёжный отчёт вообще невозможно составить из этих файлов. Физический `PASS` не возвращается **никогда**.

## Ограничения

- JSON №231 и операторские карточки — **неподписанные записи**. Их SHA-256 предотвращают незаметную позднюю замену **только при независимом сохранении хешей**.
- Отметка времени повторного SD-чтения и время запуска являются данными, указанными компьютером и человеком; точная хронология не подтверждается доверенным аппаратным счётчиком.
- Программа не подтверждает физическую SD-карту, запуск NRO на Switch, наличие воспроизводимого аудио, правильность субъективного прослушивания, сон/HOME или два независимо проведённых запуска.
- Старую host-квитанцию нельзя автоматически считать свидетельством нового запуска; под одну сборку допустимы многие сессии, но их действительную независимость устанавливает испытатель.
- Если исходные файлы отличаются, **сохраните оба оригинала** и исследуйте причину, а не переписывайте журналы ради прохождения проверки.

[22 синтетических host-регрессии](../tests/test_link_switch_audio_device_evidence.py) проверяют совпадающие NRO и CSV, изменённый манифест с новыми сессиями, неполные/противоречивые карточки, ошибочные SHA, подмену run и attempt, CI URL, неверные даты, повреждённые CSV, JSON с повторяющимися ключами, H06 и отсутствие любых изменений исходных доказательств. Тесты входят в `make test` и `make test-audio-stream`.

**Следующее действие человека после проверки:** открыть оригинальные аудиожурналы на физической консоли, оценить звук и сценарии H01–H05 и подписать независимый акт. До этого статус остаётся `HARDWARE NOT TESTED`.

## Этап №233 — безопасное получение сырых CSV с SD

Для подготовки фактических материалов первого запуска разработан [импорт №233](SWITCH_AUDIO_STAGE233_RAW_SD_CAPTURE.md) через `tools/capture_switch_audio_sd_csv.py`. Утилита сверяет NRO с исходным планом SD №218, **только читает** выбранные номерные CSV из `switch/vandal-hearts-remake/`, отказывается от `.tmp` и некорректных/меняющихся файлов, переносит первичные байты в новый отдельный bundle с манифестом SHA-256 и повторно сверяет источник. Режим `verify` сравнивает готовый bundle со свежими чтениями той же SD, не меняя оригиналы. Для дальнейшего аудита №219–232 по-прежнему нужны реальные карточки сессий и независимая физическая проверка звука. `HARDWARE NOT TESTED` остаётся без настоящего запуска консоли.
