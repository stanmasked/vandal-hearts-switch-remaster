# MAP02 — локальное сравнение кадров BGR555 (PS1 ↔ PC)

Это инструмент измерения **различий двух необработанных экранных кадров**,
а не средство получения игры, кадров или подтверждения их происхождения.
В публичный GitHub не попадают изображения, ресурсы или пиксели.

## Подготовка данных

Понадобятся независимо полученные пользовательские кадры одного состояния
MAP02: `reference.bgr555` (заявленный PS1-ориентир) и
`candidate.bgr555` (заявленный PC-порт). Каждый файл содержит ровно
`width × height × 2` байт: 16-битные little-endian BGR555-пиксели
без BMP/PNG-заголовков, с битом STP на позиции 15. Перед сравнением
необходимо отдельно убедиться в единой видимой области, ориентации,
моменте захвата, палитре и разрешении. Инструмент **не делает**
масштабирование, выравнивание, цветокоррекцию или догадки о палитре.

В приватном каталоге создаётся `frames.json` вида:

```json
{
  "schema": "vh.map02.private-bgr555-frame-comparison.v1",
  "frame": 411,
  "width": 320,
  "height": 240,
  "pixel_format": "bgr555_le",
  "images": {
    "reference.bgr555": {
      "sha256": "СЮДА_64_СИМВОЛА_SHA256",
      "frame": 411,
      "origin": "ps1_reference_claimed"
    },
    "candidate.bgr555": {
      "sha256": "СЮДА_64_СИМВОЛА_SHA256",
      "frame": 411,
      "origin": "pc_port_candidate_claimed"
    }
  }
}
```

Фактические SHA-256 каждого файла можно вычислить локально командой
`sha256sum`. Числа в примере иллюстративны, не являются данными
реального захвата. Все три файла должны остаться **приватными**.

```sh
python3 -m tools.compare_map02_private_bgr555_frames /private/map02-frame-pair \
  > /private/map02-frame-differential-summary.json
```

Сводка содержит хеши входов и карты различий, число одинаковых и
отличающихся полных 16-битных пикселей, число изменённых строк
и блоков 16×16, количество несовпадений STP, сумму абсолютных
ошибок трёх 5-битных каналов и максимальную ошибку на пиксель.
Она **не содержит** цветов, координат отдельных пикселей,
локальных путей, сырых кадров или авторских игровых ресурсов.

## Что проверяется и что остаётся неизвестным

- Точная длина каждого BGR555-файла, отсутствие символьных ссылок,
  FIFO и повреждённых/меняющихся файлов.
- SHA-256 каждого файла, строго заданный формат и одинаковый номер
  кадра. Пропущенные и лишние поля, дубли JSON и ложные типы отклоняются.
- Различие STP-бита считается отдельно от ошибки цветовых каналов:
  пиксель, отличающийся только STP, всё равно считается несовпадающим.
- Хеш карты различий не раскрывает положения отдельных пикселей.
- Метки `ps1_reference_claimed` / `pc_port_candidate_claimed`
  являются **утверждениями оператора**, не аттестацией эмулятора или
  оригинальной PlayStation.
- Даже **ноль различий** не доказывает розничное происхождение кадров,
  полную аутентичность игры, временную согласованность VRAM или
  эквивалентность GPU PlayStation. Для такого утверждения нужны
  независимые свидетельства процесса, игровых ресурсов и захвата.

CI запускает только синтетические маленькие кадры, включая тесты
STP, ошибок каналов, подмены SHA-256, неверных размеров и путей.
Реальных PS1/PC кадров в CI нет. HD-подмена остаётся запрещённой.


## Привязка меток кадра к приватной проверке запущенного ELF

После получения обоих кадров и отдельного двухточечного
`DrawOTag`/FT4/VRAM-журнала можно запустить второй, более строгий
**локальный** аудитор. Он повторяет исходное BGR555-сравнение
**до и после** независимого `audit_map02_launch_two_word_binding.py`,
который перепроверяет приватную квитанцию запуска, статические
инструментальные символы, факт наблюдения Linux ELF в `/proc`,
записи GPU/DDA и два разных VRAM-слова.

```sh
python3 -m tools.bridge_map02_private_frame_native \
  --frame-pair /private/map02-frame-pair \
  --native-capture /private/native-gpu-logs \
  --source-capture /private/source-ft4-evidence \
  --launch-receipt /private/launch-receipt.json \
  --preflight-report /private/preflight.json \
  --executable /private/verified-pc-elf \
  --compiler gcc > /private/map02-frame-native-join.json
```

Требуется строгая проверка **обоих** признаков оригинального
зафиксированного процесса: `native_elf_image_observed` и
`native_probe_symbols_inspected`. Кадр в `frames.json` обязан
совпадать с `source_frame` и `native_gpu_frame` записи исходной
FT4/VRAM-сессии. Проверяются стабильность файлов кадров и JSON
на протяжении независимого повторного анализа, SHA-256
исходного журнала GPU, совпадение двух VRAM-слов и запрет HD.
В итоговом отчёте находятся лишь SHA-256 и агрегированные
счётчики; приватные файлы не публикуются.

**Критическая граница доверия:** совпадение номера кадра, SHA-256
и даже нулевые различия BGR555 **не связывают сами байты
скриншотов причинно с запущенным процессом**. Приватный
отладочный бинарник мог просто скопировать готовые файлы
(что показывают существующие синтетические тесты).
Поля `frame_bytes_causally_bound_to_executed_game`,
`retail_disc_resources_authenticated`,
`ps1_reference_capture_authenticated`,
`pc_port_frame_capture_authenticated`,
`ps1_hardware_pixel_equivalence_verified`
и `hd_replacement_authorized` всегда `false`.
Следующий реальный шаг — независимый доверенный канал захвата
обеих кадровых поверхностей из известных процессов, а не
повторение самосогласованного журнала.

## Создание приватной пары из проверенного кадра живого ELF

Чтобы избежать ручного копирования неподтверждённого PC-кадра,
можно использовать `tools.prepare_map02_private_frame_pair`.
Требуются отдельно полученный **сырой** BGR555 reference-файл
размером 1024×512×2 байта, ранее захваченный приватный
`process-frame.bgr555` с квитанцией, GPU-журнал того же запуска
и исходный SHA-проверенный Linux ELF.

```sh
mkdir -m 700 /private/map02-verified-pair
python3 -m tools.prepare_map02_private_frame_pair \
  --reference-bgr555 /private/original-claim/reference.bgr555 \
  --live-frame /private/live-elf-frame \
  --gpu-journal-dir /private/live-elf-gpu-journal \
  --executable /private/pinned-native-elf \
  --frame-pair-dir /private/map02-verified-pair \
  > /private/pair-generation-summary.json
```

Каталоги источников и результата должны быть раздельными,
закрытыми для других пользователей; эталонный файл — только
`0600`, без дополнительных жёстких ссылок. Каталог результата
должен существовать и быть **пустым**. Инструмент проверяет
изображение через два полных независимых повтора квитанции
запуска и GPU-журнала, затем записывает приватную тройку
`reference.bgr555`, `candidate.bgr555`, `frames.json`.
При несовпадении хешей, подмене файлов либо ошибке данные
новой тройки удаляются.

Вывод содержит только хеши и агрегированные показатели.
**Метка PS1-эталона остаётся утверждением пользователя:**
наличие настоящей игры, происхождение эталона от PlayStation,
точный момент игрового кадра и эквивалентность рендеринга
не удостоверяются. Пиксели и исходные ресурсы остаются локальными.
Тесты под GCC и Clang используют исключительно синтетический
Linux C11 ELF и искусственный эталон.
