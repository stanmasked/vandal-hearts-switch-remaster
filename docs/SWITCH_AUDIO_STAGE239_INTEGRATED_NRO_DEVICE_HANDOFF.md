# Vandal Hearts Remake — этап №239: однозначная передача интегрированного NRO на Switch

**Статус: `HARDWARE NOT TESTED`.** Эта инструкция не свидетельствует об испытаниях на физической Nintendo Switch.

## 1. Одна основная сборка, один проверяемый бинарник

Начиная с этапа №238, основной кандидат для аппаратного тестирования — `vandal-hearts-prototype.nro` из успешного workflow **Switch tactical prototype with integrated audio** (файл `.github/workflows/switch-tactical-music-nro.yml`). Его музыкальный тракт использует нативный `libnx/audout`, а не необязательные SDL2/OpenAL. Сборки `audout-audio-switch-probe.nro` и `Switch toolchain readiness` остаются отдельными диагностическими/альтернативными объектами; нельзя объединять их выводы или хеши с выводами основного кандидата.

Исходная успешная сборка этапа №238: [run 39022002964](https://github.com/stanmasked/vandal-hearts-switch-remaster/actions/runs/39022002964), artifact **12097456224**. Это **историческая** привязка, а не утверждение, что коммит или run по-прежнему являются текущим HEAD.

До физического запуска нужно зафиксировать:

| Поле | Заполняется из первичного источника |
| --- | --- |
| Git SHA | 40 символов из конкретного CI run |
| Workflow run ID / artifact ID | со страницы выбранного успешного run |
| Имя NRO | `vandal-hearts-prototype.nro` |
| SHA-256 NRO | `tactical-native.sha256` из **того же** CI artifact |
| Локально вычисленный SHA-256 | вычислить из **фактически скачанного NRO** |
| SHA-256 после копирования | вычислить из **фактического NRO на SD** |
| Модель Switch, режим homebrew, HOS, аудиовыход | записывает испытатель |

Нельзя считать совпадение SHA-256 подлинностью, независимой подписью или признаком запуска. Файл `tactical-native.sha256` и NRO получаются вместе из одного артефакта и не являются независимыми сторонами доказательства. Сверяйте конкретный run, коммит и локальные байты. Не берите хеш другого workflow, даже если имя NRO совпадает.

## 2. Воспроизводимая последовательность

1. Открыть успешный [run интегрированного NRO](https://github.com/stanmasked/vandal-hearts-switch-remaster/actions/runs/39022002964), сохранить run ID, artifact ID, полный Git SHA и публикацию SHA-256 самого NRO.
2. Скачать артефакт, распаковать в новый каталог, убедиться, что NRO и `tactical-native.sha256` принадлежат **одному и тому же** run. Вычислить локальный SHA-256 NRO самостоятельно; несовпадение — **STOP**.
3. Выполнить существующую проверку bundle и планирование переноса по [№216–218](SWITCH_AUDIO_STAGE214_DEVICE_HANDOFF.md) и проверку актуальности HEAD по №217. Если выбран исторический run, явно указать это; не маркировать его как текущий.
4. Скопировать только согласованный основной NRO на SD безопасным штатным способом, затем пересчитать SHA-256 **на SD**. Несовпадение — **STOP**, запуск не проводить.
5. Физически запустить Switch и выполнить [№219](SWITCH_AUDIO_STAGE219_FIRST_RUN_PROTOCOL.md): H01 — два независимых запуска и по меньшей мере 1000 наблюдаемых PCM-страниц на каждый CSV; H02 — 10 возвратов HOME; H03 — 5 циклов сна; H04 — один непрерывный прогон 30–60 минут; H05 — независимая проверка сохранности предыдущего CSV при следующем запуске.
6. Вручную отметить слышимую музыку, выбор аудиовыхода, качество, реакцию управления, HOME, сон, штатный выход Plus и точные проблемы. Не выводить это из одних только счётчиков CSV.
7. Читать готовые `audio-diagnostics-XXXX.csv` в `sdmc:/switch/vandal-hearts-remake/` **после штатного выхода**. Файлы `.tmp` не являются исходными свидетельствами завершённого сеанса; исходные CSV не редактировать.
8. Провести уже существующие проверки `verify_switch_audio_bundle.py`, `report_switch_audio_hardware.py`, `assess_switch_audio_first_run.py` и последующий строгий H05-аудит №220–237. Хранить ручные карточки и сторонние квитанции отдельно от неизменяемых исходников.

## 3. Условия STOP / допустимый вывод

- Не сошлись SHA-256 локального NRO, CI-публикации или копии на SD: **STOP, INVALID EVIDENCE**.
- Неизвестны полный Git SHA, run ID, artifact ID или источник файла: **STOP, INCONCLUSIVE**.
- Отсутствуют слышимые проверки, подлинные CSV либо карточки физических сеансов: **`HARDWARE NOT TESTED`**.
- Дефекты аудио, потери данных, ошибка HOME/сна, повреждение CSV: **INVESTIGATE**, без автоматического PASS.
- Все машинные проверки согласованы: **READY FOR INDEPENDENT MANUAL REVIEW**, не аппаратный PASS.
- Статус **физически проверено** устанавливается только отдельным независимым человеческим заключением по реально проведённым испытаниям.

## 4. Известные ограничения

HTTP 403 у необязательных портов SDL2/OpenAL — внешний блокер установки пакетов и не диагноз нативного аудиотракта. Успешный CI, NeXium, хеши NRO и прохождение тестов подтверждают программные условия, но **не слышимость музыки**, не поведение HOME/сна и не физическое выполнение на Switch. Для тестов используйте только законно полученные собственные данные; коммерческие игровые аудиоресурсы не публикуйте.

**Результат этапа №239:** устранена неоднозначность между протоколом №219 и интегрированным нативным NRO №238, зафиксирован единый маршрут передачи на устройство. Физические испытания этим документом не заявляются.

## Этап №251 — исторический CI-артефакт и точный порядок SD-переноса

17 октября 2026 года повторно проверен через GitHub Actions API артефакт №12097456224 из run №39022002964: он **не истёк**, его исходный коммит — `94d978da9cf52038bf5b8da3f2dec67c77d06700`, имя — `vandal-hearts-tactical-with-native-music`. Его `digest` в API относится к **ZIP-архиву**, не к самому NRO. Реальный SHA-256 NRO обязательно считывается из `tactical-native.sha256` и повторно вычисляется для локального бинарника; никакой хеш NRO из ZIP-digest не выводится.

**Разделяйте два сценария.** Для *актуальной* сборки создайте новый успешный integrated-audio run на HEAD, получите именно его NRO/артефакт и выполните `verify_switch_audio_live_preflight.py` №217: инструмент преднамеренно отклоняет все исторические коммиты. Для *исторической* сборки №238 явно пометьте `HISTORICAL_BUILD_NOT_CURRENT_HEAD`; применяйте строгую офлайн-проверку №240 и последующую сверку SD №218, но **не** записывайте результат №217 `MATCHED_CURRENT_HEAD_AT_CHECK_TIME`, если HEAD уже ушёл дальше.

Для уже скачанного NRO и каталога evidence bundle используйте только существующие read-only инструменты (путь SD подставляет оператор, не следует считать его физическим носителем по одному названию):

```sh
python3 tools/verify_switch_audio_bundle.py verify /path/to/evidence-bundle

python3 tools/verify_switch_audio_sd_transfer.py plan /path/to/evidence-bundle \
  --sd-root /path/to/mounted-sd \
  --output /path/outside-bundle/transfer-plan.json

# Здесь оператор вручную копирует согласованный NRO на SD и штатно завершает запись.
python3 tools/verify_switch_audio_sd_transfer.py verify /path/to/evidence-bundle \
  --sd-root /path/to/mounted-sd \
  --plan /path/outside-bundle/transfer-plan.json
```

Файл `audio-evidence-manifest.json` в bundle должен заранее быть создан существующим `verify_switch_audio_bundle.py create` с **точным** проверенным SHA и run URL, а не с номером нового документационного коммита. Не смешивайте исходный интегрированный NRO, отдельную audout-пробу и NRO другой сборки. Успешный результат `DESTINATION_BYTES_MATCH_PLANNED_NRO` доказывает лишь равенство прочитанных файлов, **не** физическую SD, успешный запуск, слышимую музыку, HOME или сон. Финальное состояние до реальных испытаний — `HARDWARE NOT TESTED`.
