# MAP02 — итоговое свидетельство CD/GPU/GTE/процесса

Этот этап НЕ меняет ранее опубликованный GPU/GTE-манифест.
Отдельный, более строгий SHA-256-файл создаётся только при наличии
реального программного события CdRead, совпавшего с пользовательским
сырьевым US-образом, и привязки к уже проверенному GPU и Linux-процессу.

## Обязательные приватные входы

Все четыре каталога должны быть раздельными с правами 0700:

- source-bundle: опубликованный, заново проверяемый исходный GTE/FT4/GPU;
- native-windows: оригинальный DrawOTag с полными снимками VRAM;
- scoped: PutPixel, BlendG1, VRAM-edges, GPU-session и завершённый CdRead;
- handoff: квитанция наблюдения запущенного бинарника через Linux procfs
  и открытого им того же игрового образа.

Также требуется локальный собственный US raw BIN, исходный pinned
PC-port checkout и соответствующий проверенный исполняемый ELF.
Режим отклоняет отсутствие любой части. Не загружайте игровые
сектора, исполняемые файлы, полные VRAM или ключи в публичный GitHub.

## Публикация и повторная проверка

~~~sh
python3 -m tools.publish_map02_cd_bound_witness \
  /private/map02/source-bundle \
  /private/map02/native-windows \
  /private/map02/scoped \
  /private/map02/handoff \
  /private/map02/owned-game-image.bin \
  --upstream-checkout /private/map02/VandalHearts-PcPort \
  --pc-binary /private/map02/pc-port-instrumented \
  --frame <real-GPU-DrawOTag-frame> --publish

# Повторная проверка: та же команда, но БЕЗ --publish
~~~

Номер кадра следует узнать из настоящего захвата, не из CI-примера.
При публикации создаётся строго приватный файл (0600) с именем
gpu-native-map02-cd-process-source-witness.json.
Существующий файл никогда не перезаписывается. Публикация повторяет
все дорогие проверки и выполняет исключительную запись/контроль байтов.

## Что именно связывается

Финальная схема: vh.map02.native-gte-gpu-cd-process-witness.v1.
В неё входят SHA-256 предыдущего GPU/GTE-манифеста, квитанции
Linux-процесса, оригинальной CdRead-квитанции, пользовательского
образа целиком, полезных байтов ресурса CDF_M_MAP02_PRS и общего
идентификатора сеанса. Ни игровых пикселей, ни содержимого CD
в итоговом JSON нет.

Верификатор заново проверяет 12 секторов с LBA 0x1bcc, CRC32
фактического CdRead, источник GTE/FT4, глобальные DrawOTag-номера,
PutPixel/BlendG1, 16-битные значения VRAM и полный хеш окон.
Он требует совпадения сеанса с живым Linux-процессом,
который ранее открыл тот же образ игры.

## Уровень доказательств

Успешный синтетический CI на 208 тестах:
https://github.com/stanmasked/vandal-hearts-switch-remaster/actions/runs/39036557844

В CI выполняются оригинальные CdRead и DrawOTag в отдельных
изолированных тестах. Полный цикл оригинальной игры
LoadCdFile → ContinueLoadingCdFile → DrawOTag на пользовательском
retail-образе пока НЕ выполнен. В синтетических unit-тестах
исходный GTE-верификатор и kernel-процесс могут заменяться
явными тестовыми заглушками; реальный publisher этих замен
не использует.

Совпадение квитанций — это структурная согласованность программных
наблюдений, а не защищённая аппаратная аттестация. Поля
full_original_gameplay_authenticated, original_map02_rendering_proven
и physical_ps1_equivalence_proven всегда false.

HD-подмена остаётся отключённой до проверки настоящей MAP02.
