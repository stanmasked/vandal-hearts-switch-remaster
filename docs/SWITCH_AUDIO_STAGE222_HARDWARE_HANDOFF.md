# Vandal Hearts Remake — этап №222: полный пакет первичных аппаратных доказательств

> **Статус: `HARDWARE NOT TESTED`.** Документ задаёт процедуру передачи доказательств. Синтетические регрессии и GitHub Actions не являются реальным запуском Nintendo Switch.

## Цель и границы

Инструмент [`tools/audit_switch_audio_handoff.py`](../tools/audit_switch_audio_handoff.py) выполняет **офлайн и только для чтения**:

- повторный строгий анализ NRO/CSV и их SHA-256 по неподписанному `audio-evidence-manifest.json`;
- пересчёт [матрицы H01–H07](SWITCH_AUDIO_STAGE221_ACCEPTANCE_MATRIX.md) из **исходных файлов**, а не из заранее подготовленного отчёта;
- SHA-256-инвентаризацию первичного NRO, CSV, манифеста, операторского JSON и индивидуальных карточек;
- сопоставление отдельной карточки каждого запуска с точным SHA NRO, Git commit и проверенным CSV;
- контроль заявленных идентификаторов запусков, порядка и пересечений времён, условий вывода звука, длительности и результатов прослушивания;
- вывод незакрытых противоречий и отсортированного списка повторных испытаний.

Случайный набор JSON, устаревший NRO, скопированные CSV или одинаковые операторские заявления **не становятся доказательством независимых физических запусков**. Статус `READY_FOR_INDEPENDENT_MANUAL_REVIEW` означает только структурную готовность комплекта для независимого человека.

## Структура локальной передачи

```text
hardware-evidence-222/
  verified-bundle/
    audio-evidence-manifest.json
    nro/vandal-hearts-prototype.nro
    session-01/audio-diagnostics-0000.csv
    session-02/audio-diagnostics-0001.csv
  operator-v2.json
  session-cards/
    first.json
    second.json
  report-222.json                 # создаётся отдельно ПОСЛЕ проверки
  MANUAL_ACCEPTANCE.md            # отдельное человеческое заключение
```

Имя карточки — **значение `sessions[].id` в `operator-v2.json`, плюс `.json`**. Если в операторском файле вместо `first` указано `session-01`, соответствующий файл будет называться `session-01.json`. Сами имена raw CSV берутся только из проверенного манифеста: не переименовывайте их ради отчёта.

Скопируйте для каждой независимой сессии [пустой шаблон карточки](SWITCH_AUDIO_STAGE222_SESSION_CARD_TEMPLATE.json) в папку `session-cards` и замените **все** заглушки только настоящими измерениями. Карточка обязательно включает:

| Свидетельство | Назначение |
| --- | --- |
| `session_id`, `launch_id` | Связь с операторским JSON и заявленный уникальный запуск |
| `csv`, `csv_sha256` | Точный исходный CSV и его фактический SHA-256 |
| `git_sha`, `nro_sha256` | Идентичность проверяемой сборки |
| `start_utc`, `end_utc` | Фактические даты/времена с часовым поясом; последовательность без пересечения |
| `console_label` | Неперсональное локальное обозначение консоли (не серийный номер) |
| `launch_mode`, `audio_output` | Application/applet и выбранный слышимый выход |
| `music_audible`, `audio_artifacts`, `normal_exit` | Ручное наблюдение воспроизведения, дефектов и завершения |
| `observer_note` | Краткие фактические наблюдения и условия испытания |

**Не используйте готовые синтетические значения из регрессионных тестов.** Если событие не измерялось, оставьте карточку отсутствующей и получите `INCONCLUSIVE`, а не выдумывайте дату/хеш. Временная последовательность и разные `launch_id` — полезная проверка непротиворечивости, но они **не доказывают**, что приложение действительно запускалось дважды.

## Команда итогового аудита

```sh
python3 tools/audit_switch_audio_handoff.py \
  hardware-evidence-222/verified-bundle \
  --observations hardware-evidence-222/operator-v2.json \
  --cards-dir hardware-evidence-222/session-cards \
  > hardware-evidence-222/report-222.json
```

Сценарий H06 включается только при наличии **безопасного добровольного** теста записи на отдельном носителе:

```sh
python3 tools/audit_switch_audio_handoff.py \
  hardware-evidence-222/verified-bundle \
  --observations hardware-evidence-222/operator-v2.json \
  --cards-dir hardware-evidence-222/session-cards \
  --require-h06 --compare-builds
```

`--compare-builds` требует H07, но **не засчитывает** сравнение двух сборок автоматически: вторую версию необходимо отдельно проверить через `compare_switch_audio_sessions.py` и сохранить ручное заключение. Обычная первичная приёмка одной версии не обязана запускать H06 или H07. Никогда не вызывайте сбой питания ради проверки H06.

## Правила интерпретации

`source_inventory` хранит локально пересчитанные SHA-256, длины и роли зарегистрированных файлов. `session_cards` показывает `SELF_REPORTED_CARD_RECORDED`, `MISSING_MANUAL_CARD` или `CONTRADICTORY_CARD`. `repeated_session_claims` содержит сведения о заявленных разных запусках и `physical_independence: NOT_ATTESTED`.

Отчёт выставляет:

- `INVESTIGATE` — конфликт SHA/NRO/CSV, записи карточки и оператора, перекрытие заявленных времён, повторный `launch_id`, проблема PCM/HOME/звука либо смена указанной консоли; это **не подтверждение физической ошибки**, пока не проверены первичные факты;
- `INCONCLUSIVE` — нет карточки, меньше двух различных подтверждённых заявлений, не выполнен H01–H05, явно запрошены, но не выполнены H06/H07;
- `READY_FOR_INDEPENDENT_MANUAL_REVIEW` — проверенные байты согласованы с заполненными, но **неподписанными** карточками и нет машинных противоречий. Требуется независимый ручной просмотр.

**Код выхода `0` означает только создание отчёта.** `INVALID_EVIDENCE` с кодом `2` означает повреждение/изменение первичного NRO или CSV, неверный операторский JSON, недопустимый/неожиданный JSON карточки, символьные ссылки или иную ошибку строгой проверки. В этом случае нельзя подменять доказательства исправленными CSV; сохраните оригиналы.

`hardware_status` всегда равен `HARDWARE NOT TESTED`: программа не может удостоверить подлинность заявлений, настоящую Switch/SD, работу звука, интервал между перезапусками или независимость сессий. Полный пакет следует передать человеку, который проверит **настоящие** оригиналы на консоли, сведения о сборке по [этапам №216–218](SWITCH_AUDIO_STAGE214_DEVICE_HANDOFF.md) и отдельно оформит дату, подпись, решение и причины отказа.

## Регрессии

[Синтетические host-тесты](../tests/test_audit_switch_audio_handoff.py) проверяют пустые/полные комплекты, хеши, повторные идентификаторы запусков, перекрывающиеся даты, несогласованные аудионаблюдения, подменённые CSV и сборку, необязательные H06/H07, целостность исходных данных и fail-closed. Они включены в `make test` и `make test-audio-stream`. Это **не физические испытания**.

## Этап №223 — архивная передача на другой компьютер

Для передачи результатов №222 другому испытателю без редактирования исходных CSV используйте [архиватор и верификатор №223](SWITCH_AUDIO_STAGE223_ARCHIVE_TRANSFER.md). ZIP содержит только первичные материалы и внутренний индекс SHA-256; **отдельно** сохраните SHA-256 ZIP в независимом канале. Получатель должен проверить `--expected-sha256`, а не принимать хеш, лежащий рядом с архивом, за подтверждение происхождения. Программа заново проверит внутренние файлы и операторские карточки в приватном временном каталоге. Результат `ARCHIVE_BYTES_AND_EVIDENCE_REVERIFIED` не свидетельствует о реальном запуске Nintendo Switch или качестве звука.

Добавлен [строгий аудит №236](SWITCH_AUDIO_STAGE236_H05_OPERATOR_CARDS.md) — `tools/verify_switch_audio_h05_operator_binding.py`. Он **снова** проверяет оригинальные H05 baseline/review и захваченный CSV-архив №235, затем повторяет аудит операторских карточек №222 и сопоставляет старый и новый CSV с двумя отдельными карточками по SHA-256, Git SHA, NRO, порядку, времени и самозаявленному `launch_id`. Нехватка карточек остаётся `INCONCLUSIVE`, противоречивые показания — `INVESTIGATE`; **ни один статус не является физическим PASS**.
