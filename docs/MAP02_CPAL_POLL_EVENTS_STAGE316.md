# MAP02 Stage316 — Source-verified two-position CPAL poll requested and returned event categories

**Research-only / Draft / DO NOT MERGE.** Follows verified [Stage315 PR #440](https://github.com/stanmasked/vandal-hearts-switch-remaster/pull/440), successful independent [GitHub Actions #39606340374](https://github.com/stanmasked/vandal-hearts-switch-remaster/actions/runs/39606340374). During the real 21ms requested Pulse latency run, the *source-proven native CPAL* thread had **zero new callbacks and zero poll returns** after generated ROM-free guest input, yet had already entered `poll` with **two descriptors and timeout -1** (infinite wait). At 22ms exactly two descriptors and infinite timeout were also used, but the native CPAL thread returned from 2918 polls with at least one ready descriptor and delivered 2242 callbacks. An infinite two-descriptor `poll` is therefore a normal active-audio pattern as well as an observed non-returning pattern; Stage315 did not prove why the 21ms wait did not return.

## What Stage316 adds and what it expressly does not capture

Use the *same, independently pinned* original research-only Stage309 experimental Linux NeXium ELF SHA256 `e5ddfc61ac9435dc5a6e2dcd569766db0c444bbdeef8a3fa6a65c9c2e9fc6f25` and unchanged generated ROM-free NRO SHA256 `371c9fd9f1f41ad87cbb5f7f96a3e5e9d56878f8cfff2bf7fea2c17120c2611b`. No source recompilation of either binary, game changes, licensed PS1 ROM, soundtrack or hardware Switch audio are involved.

Stage316 adds an isolated `LD_PRELOAD` research interposer cloned from Stage315. The original 65536-byte private mmap layout is unchanged: the **previously unused bytes** between the original nine ALSA counters and fixed CPAL callback marker offset 32768 contain nine relaxed atomic cumulative event counters per each of 64 anonymous same-process TLS aliases, beginning at fixed byte offset **27664** and ending at 32272. A further two bytes per alias at offset **32272** record compact *last request* and *last completed return* category codes, ending at 32400 and leaving 368 reserved bytes before the fixed CPAL marker. The C build has strict `_Static_assert` for both new offsets, every existing Stage308/311/313/314/315 offset, and original mmap bounds. Both existing ALSA/CPAL and private native Linux-TID identity probes are untouched.

Only exported libc `poll(struct pollfd *, nfds_t, int)` calls **with exactly two descriptors and a nonnull pollfd pointer** are classified. Before forwarding unchanged poll arguments to the real function, the wrapper reads **only the two `events` masks** and increments coarse counters for `POLLIN` or `POLLOUT` requested in anonymous ordinal position 0 or 1. It also stores one compact last-request byte: bit 7 marks a valid two-position snapshot; bits 0..3 mark the two ordinals' requested IN/OUT categories. This byte is refreshed at every `poll` entry (and cleared for other descriptor counts), so a poll already blocked before the guest input retains its own request categories even when its cumulative entry delta is zero. If the call returns, a separate compact last-completed-return byte stores status (ready/timeout/error), returned IN/OUT categories and an aggregate exceptional flag. **The last completed return is explicitly not interpreted as the active call's result.** If the call returns positively (`rc>0`), the wrapper reads **only the two `revents` masks** and counts `POLLIN` / `POLLOUT` returned by ordinal 0 or 1, plus one aggregate "any exceptional result" counter when either ordinal returned `POLLERR`, `POLLHUP`, `POLLNVAL`, or `POLLPRI`.

**Crucial privacy/property boundary:** These two positions are *indices in the call-local pollfd array*, not native Linux FD numbers. No values of `fds[i].fd`, full event masks, file names, pointers, stack traces, actual Linux TIDs/PIDs, PCM bytes, private 65536-byte mmap, or pollfd contents are copied to artifacts. Other `poll` descriptor counts, internal glibc functions, direct syscalls, `ppoll` and epoll readiness-mask details are **outside the event-class counter coverage**. If a caller supplies invalid pointers, the extra userspace `events` reads may be more intrusive than original kernel poll; the experiment is **not suitable for production**. Even valid extra memory reads and relaxed atomics alter timing and symbol interception; a different observed outcome from Stage315 is possible.

The original external non-realtime Stage315 sampler now emits a sixth **sanitized** event category CSV, alongside identical-timestamp ALSA, CPAL, libc-poll entry/return and requested timeout/number-of-descriptors source CSVs every ~200ms. Each alias row includes the nine cumulative event counters and the two compact last-call category bytes; the source auditor validates both encodings and reports the current request separately from the last completed return. As in the corrected successful Stage315 collector, any rare individually relaxed-atomic ALSA intermediate counter inconsistency is retried by sampling the original private map again rather than fabricating values or truncating evidence.

## Fail-closed analysis and no causal claim

Two Ubuntu 24.04 GitHub Actions jobs request separate 21ms and 22ms Pulse hints. Each performs exact ELF/NRO hash verification, real GUI guest capture and independent 8-page generated optical/virtual 48k PCM checks, then executes a Stage316 source auditor. The auditor **first replays the actual full Stage315 source audit**, which recursively verifies Stage314/313/312/311/310 pinned binary source, CPAL callback ownership and private Linux task join. Then it reads the new strict event-category CSV, validates unsigned and nondecreasing per-anonymous-alias counters, original guest-first-input and last-observation boundaries, and exact equality of its monotonic samples with verified Stage315 source. Only a TLS alias **positively tagged and privately matched to native CPAL before input** can be described as a CPAL callback thread.

At 21ms, an already-pending `poll` begun before guest input may have a *zero event category delta* during the guest interval. The auditor must not mistake that for a zero requested-event mask; the last request may have been before the guest window and is recoverable only from cumulative pre-input data. At 22ms, returned `POLLIN`/`POLLOUT` indicate category and anonymous ordinal only; they do NOT establish where the readiness notification originated. No lost wakeup, eventfd producer, exact kernel wait cause, permanent deadlock, 21/22ms causal hardware threshold or Nintendo Switch production audio fix follows from these counters alone.
