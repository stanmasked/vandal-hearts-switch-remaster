# MAP02 Stage316 — Source-verified two-position CPAL poll requested and returned event categories

**Research-only / Draft / DO NOT MERGE.** Follows verified [Stage315 PR #440](https://github.com/stanmasked/vandal-hearts-switch-remaster/pull/440), successful independent [GitHub Actions #39606340374](https://github.com/stanmasked/vandal-hearts-switch-remaster/actions/runs/39606340374). During the real 21ms requested Pulse latency run, the *source-proven native CPAL* thread had **zero new callbacks and zero poll returns** after generated ROM-free guest input, yet had already entered `poll` with **two descriptors and timeout -1** (infinite wait). At 22ms exactly two descriptors and infinite timeout were also used, but the native CPAL thread returned from 2918 polls with at least one ready descriptor and delivered 2242 callbacks. An infinite two-descriptor `poll` is therefore a normal active-audio pattern as well as an observed non-returning pattern; Stage315 did not prove why the 21ms wait did not return.

## What Stage316 adds and what it expressly does not capture

Use the *same, independently pinned* original research-only Stage309 experimental Linux NeXium ELF SHA256 `e5ddfc61ac9435dc5a6e2dcd569766db0c444bbdeef8a3fa6a65c9c2e9fc6f25` and unchanged generated ROM-free NRO SHA256 `371c9fd9f1f41ad87cbb5f7f96a3e5e9d56878f8cfff2bf7fea2c17120c2611b`. No source recompilation of either binary, game changes, licensed PS1 ROM, soundtrack or hardware Switch audio are involved.

Stage316 adds an isolated `LD_PRELOAD` research interposer cloned from Stage315. The original 65536-byte private mmap layout is unchanged: the **previously unused bytes** between the original nine ALSA counters and fixed CPAL callback marker offset 32768 contain nine relaxed atomic cumulative event counters per each of 64 anonymous same-process TLS aliases, beginning at fixed byte offset **27664** and ending at 32272. The former 512-byte Stage311 reserved region after the fixed CPAL marker now holds one aligned 64-bit state per alias at offset **33280**; the Stage311 phase counters remain at 33792 and all other existing offsets are unchanged. The low byte records the active two-position request categories and the next byte records the last completed return. The C build has strict `_Static_assert` for the new state offset, every existing Stage308/311/313/314/315 offset, and original mmap bounds. Both existing ALSA/CPAL and private native Linux-TID identity probes are untouched.

Only exported libc `poll(struct pollfd *, nfds_t, int)` calls **with exactly two descriptors and a nonnull pollfd pointer** are classified. Before forwarding unchanged poll arguments to the real function, the wrapper reads **only the two `events` masks** and increments coarse counters for `POLLIN` or `POLLOUT` requested in anonymous ordinal position 0 or 1. It also stores one compact active-request byte: bit 7 marks a valid two-position snapshot; bits 0..3 mark the two ordinals' requested IN/OUT categories. This byte is set at every `poll` entry (and cleared for other descriptor counts) and **atomically cleared on return**. The next byte separately stores the last completed return's status (ready/timeout/error), returned IN/OUT categories and an aggregate exceptional flag. Both bytes are packed into one aligned 64-bit per-alias state and updated atomically, so a reader cannot combine a stale active request with a newly completed return. A request that began before guest input remains visible only while that call is still active at the sample time. If the call returns positively (`rc>0`), the wrapper reads **only the two `revents` masks** and counts `POLLIN` / `POLLOUT` returned by ordinal 0 or 1, plus one aggregate "any exceptional result" counter when either ordinal returned `POLLERR`, `POLLHUP`, `POLLNVAL`, or `POLLPRI`.

**Crucial privacy/property boundary:** These two positions are *indices in the call-local pollfd array*, not native Linux FD numbers. No values of `fds[i].fd`, full event masks, file names, pointers, stack traces, actual Linux TIDs/PIDs, PCM bytes, private 65536-byte mmap, or pollfd contents are copied to artifacts. Other `poll` descriptor counts, internal glibc functions, direct syscalls, `ppoll` and epoll readiness-mask details are **outside the event-class counter coverage**. If a caller supplies invalid pointers, the extra userspace `events` reads may be more intrusive than original kernel poll; the experiment is **not suitable for production**. Even valid extra memory reads and relaxed atomics alter timing and symbol interception; a different observed outcome from Stage315 is possible.

The original external non-realtime Stage315 sampler now emits a sixth **sanitized** event category CSV, alongside identical-timestamp ALSA, CPAL, libc-poll entry/return and requested timeout/number-of-descriptors source CSVs every ~200ms. Each alias row includes the nine cumulative event counters and the two category bytes from the same atomic state word: the current active request and the last completed return.

The compact bytes are category codes, not raw Linux masks. For the active request, bit 7 is the validity flag and bits 0..3 mean ordinal 0 `POLLIN`, ordinal 0 `POLLOUT`, ordinal 1 `POLLIN`, ordinal 1 `POLLOUT`. The active byte is zero once that `poll` returns. For the last completed return, bit 7 marks a valid two-position call; bits 5..6 encode positive-ready / zero-timeout / negative-error return class; bits 0..3 are the same returned IN/OUT categories; bit 4 means at least one exceptional `POLLERR`, `POLLHUP`, `POLLNVAL`, or `POLLPRI`. A zero return byte means unavailable or the most recent call did not have exactly two valid pollfd positions. The source auditor validates these bit encodings, never reports either byte as a complete `events`/`revents` mask, and samples the active request and completed return from the same atomic state word. As in the corrected successful Stage315 collector, any rare individually relaxed-atomic ALSA intermediate counter inconsistency is retried by sampling the original private map again rather than fabricating values or truncating evidence.

## Fail-closed analysis and no causal claim

Two Ubuntu 24.04 GitHub Actions jobs request separate 21ms and 22ms Pulse hints. Each performs exact ELF/NRO hash verification, real GUI guest capture and independent 8-page generated optical/virtual 48k PCM checks, then executes a Stage316 source auditor. The auditor **first replays the actual full Stage315 source audit**, which recursively verifies Stage314/313/312/311/310 pinned binary source, CPAL callback ownership and private Linux task join. Then it reads the new strict event-category CSV, validates unsigned and nondecreasing per-anonymous-alias counters, original guest-first-input and last-observation boundaries, and exact equality of its monotonic samples with verified Stage315 source. Only a TLS alias **positively tagged and privately matched to native CPAL before input** can be described as a CPAL callback thread.

At 21ms, an already-pending `poll` begun before guest input may have a *zero event category delta* during the guest interval. The active-request byte preserves its requested IN/OUT categories while that call remains in flight, even with zero cumulative delta; once it returns, the active byte is atomically cleared and its return is stored separately. A zero active byte therefore must not be mistaken for an active call with an empty requested-event mask. This is a sampled interposer state, not proof of the exact kernel wait state at every instant or of the root cause of missing audio. At 22ms, returned `POLLIN`/`POLLOUT` indicate category and anonymous ordinal only; they do NOT establish where the readiness notification originated. No lost wakeup, eventfd producer, exact kernel wait cause, permanent deadlock, 21/22ms causal hardware threshold or Nintendo Switch production audio fix follows from these counters alone.
