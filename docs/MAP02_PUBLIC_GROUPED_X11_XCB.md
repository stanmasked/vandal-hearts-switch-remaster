# MAP02 — повторный поиск X11/XCB при компоновке архивов

## Подтверждённая база

Исходные 118 объектных модулей публичного PC-кода без игровых данных образуют `ET_REL` с **520** сильными неопределёнными символами. Реальная системная `libSDL2.a` на Ubuntu дала **1085** (27 исходных ссылок закрыто и 592 добавлено). Последующий настоящий GNU `ld -r` с `libX11.a` дал **996** (150 закрыто и 61 добавлена). [Подтверждение — Actions №39501428111, 29/29 успешных шагов](https://github.com/stanmasked/vandal-hearts-switch-remaster/actions/runs/39501428111).

Эксперимент [PR №380](https://github.com/stanmasked/vandal-hearts-switch-remaster/pull/380) выполняет следующий **последовательный** `ld -r` с `libxcb.a` (итоговое число пока нельзя считать установленным).

## Зачем ещё один способ компоновки

Последовательный порядок `SDL2 ELF → X11.a → XCB.a` не возвращается в X11 после того, как выбранный объект XCB добавил новую ссылку на уже пройденную библиотеку X11. GNU `ld -r` допускает многократное извлечение объектных членов обоих обычных `.a` через `--start-group libX11.a libxcb.a --end-group`.

Новый `tools/check_map02_public_grouped_x11_xcb.py` использует тот же **исходный после SDL2 `ET_REL` (1085 сильных импортов)** и **точно те же копии** системных архивов X11 и XCB, которые проверены предыдущими этапами. Он требует отдельные 0600 приватные входы, проверку ABI/inode/SHA-256, прежний 0600 манифест без публикации имён, новый выходной каталог 0700, реальный GNU `ld -r` и числовые проверки из отчёта.

В CI после последовательного XCB-этапа сравниваются:
- количество неопределённых сильных импортов при последовательном X11 → XCB;
- количество после общего X11/XCB GNU archive group;
- сколько **исходных 1085** ссылок реально закрыто группой и сколько **новых** ссылка появилась.

**Числовой эффект группировки заранее не предполагается:** результат может оказаться лучше, таким же или хуже, чем при последовательной компоновке. Обязательна только проверка реальных счётчиков и хешей.

## Нативные регрессии

Для демонстрации циклической зависимости применяются GCC, GNU `ar`, `nm` и `ld`. Синтетическая исходная программа вызывает экспорт первого архива X11; этот экспорт требует XCB, а XCB требует *другого* члена X11. В обычном порядке остаются две неопределённые ссылки, при повторном просмотре обоих архивов — одна. Дополнительные тесты запрещают символьную ссылку вместо архива, неверный baseline, повтор одного и того же архива и перезапись занятого каталога.

Это проверка **публичного PC-кода без пользовательских ресурсов**. Имена импортов остаются исключительно в закрытом временном манифесте CI и не выводятся в отчёт. Даже успешный GNU archive group создаёт только промежуточный объектный ELF, **не** завершённый исполняемый файл, не подлинную сцену MAP02 и не запуск Nintendo Switch.
