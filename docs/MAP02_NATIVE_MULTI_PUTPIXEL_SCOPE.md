# MAP02 — два слова VRAM в одном нативном DrawOTag

Этот экспериментальный путь дополняет [однопиксельную синхронную
корреляцию](MAP02_PUTPIXEL_DRAWOTAG_CORRELATION.md) и **не** заменяет
анализ независимых приватных сеансов. Он захватывает события ровно
**двух разных** координат VRAM из **одного инструментированного
экземпляра** оригинального публичного PC-порта.

## Генерация из закреплённого PC-источника

Исходники должны точно совпадать с публичным PC-портом на коммите
`14552fffa0e0b47e02b57592e274fc6e7a649923`.
`tools/instrument_map02_multi_putpixel_scope.py` проверяет Git blob SHA
обоих файлов и отказывается перезаписывать существующую папку:

```sh
python3 -m tools.instrument_map02_multi_putpixel_scope \
  /private/VandalHearts-PcPort/platform/pc/src/libgpu.c \
  /private/VandalHearts-PcPort/platform/pc/src/pc_raster.c \
  --output-dir /private/map02-multiscope-build
```

Компилировать `libgpu.multiscope.c` и `pc_raster.multiscope.c`
**вместе**, вместо обычных копий PC GPU, с обоими флагами:
`-DVH_MAP02_GPU_CAPTURE -DVH_MAP02_MULTI_PUTPIXEL_SCOPE`.
Без этих флагов дополнительные функции исключены; оригинальные
`WritePixel` и `DrawOTag` не подменяются. Путь `s_hires`
не инструментирован.

Выбрать приватную директорию и два **разных** слова VRAM:

```sh
export VH_MAP02_GPU_CAPTURE_DIR=/private/map02-two-word-gpu
export VH_MAP02_GPU_CAPTURE_FRAME=12
export VH_MAP02_PUTPIXEL_DIR=/private/map02-two-word-gpu
export VH_MAP02_PUTPIXEL_FRAME=12
export VH_MAP02_PUTPIXEL_X=30
export VH_MAP02_PUTPIXEL_Y=30
export VH_MAP02_PUTPIXEL_X2=35
export VH_MAP02_PUTPIXEL_Y2=35
```

Все пути — заранее созданные локальные папки. Координаты и метки
кадров **синтетические примеры**, не доказанные координаты настоящей
MAP02. Некорректная или одинаковая пара координат отключает запись.
Два адреса разделяют **один глобальный** `step`, один кадр и
`primitive_ordinal` каждого оригинального `DrawOTag`; события
сохраняют точный порядок между точками.

Ограничение — **64 вызова на обе точки суммарно**, не по 64 на
каждую. Достигший лимита журнал отклоняется как потенциально
обрезанный; для GPU-снимков действует отдельный лимит 64 события.

## Приватный манифест и проверка

После завершения приватного двухточечного захвата используйте команду
**проверки с публикацией**. Она вычисляет SHA-256 из реальных файлов,
проверяет всю цепочку GTE/FT4/OT/VRAM/PutPixel до появления
нового манифеста и только затем создаёт его приватно (права `0600`):

```sh
python3 -m tools.publish_map02_multi_capture_manifest \
  /private/map02-source /private/map02-two-word-gpu \
  > /private/map02-public-receipt-summary.json
```

Прежний файл `gpu-putpixel-multi-ot.json` никогда не перезаписывается;
ошибка в исходном журнале, алгоритме `BlendG1`, контрольной сумме
или попытка использовать ссылку для каталога оставляют свидетельство
неопубликованным. Перед исключительным созданием файла инструмент
повторно проверяет контрольные суммы трёх основных приватных входов.
Это контроль согласованности, **не** аппаратное свидетельство
единого исполнявшегося процесса. Формат готового приватного файла:

```json
{
  "schema": "vh.map02.native-putpixel-multi-ot.v1",
  "source_frame": 411,
  "gpu_draw_frame": 12,
  "overdraw_manifest_sha256": "<SHA256 gpu-native-overdraw.json>",
  "native_events_sha256": "<SHA256 gpu-native-events.jsonl>",
  "putpixel_events_sha256": "<SHA256 putpixel-native-events.jsonl>"
}
```

Запуск проверки:

```sh
python3 -m tools.verify_map02_putpixel_multi_scope \
  /private/map02-source /private/map02-two-word-gpu \
  > /private/map02-multi-word-report.json
```

Валидатор обязательно повторяет исходный GTE/FT4/OT/VRAM-аудит,
проверяет совпадение кадров, SHA, строгий JSONL, **общий**
монотонный `step` и `primitive_ordinal`, ровно две различные
координаты, неизменность PC accurate/legacy-режима, оригинальную
арифметику `WritePixel/BlendG1`, непрерывность значения
каждого слова внутри примитива и границы **тех же самых**
полных снимков VRAM для обеих координат. Приписывать вызовы
исходным FT4 можно только по независимо проверенному пакету
и порядку OT. Любая необъяснённая наблюдаемая перемена выбранного
слова у сопоставленного FT4 отклоняется.

Публичный отчёт включает **только агрегаты**, контрольные суммы,
количество выборок и отдельные счётчики для ABR0–ABR3,
повторных записей и временного восстановления слова. Он не
включает значения BGR555, координаты, абсолютные пути, геометрию
или пользовательские игровые байты.

Дополнительный анализ сопоставленных исходных FT4 считает:

- `source_ft4_draws_with_both_words_observed` — количество
  исходных FT4, у которых зарегистрированы вызовы `PutPixel`
  для **обоих** выбранных слов;
- `source_ft4_draws_changing_both_sampled_words` — количество
  FT4 с изменениями **обоих** слов между собственными
  снимками PRE/POST; этот показатель не равен числу вызовов;
- `source_ft4_draws_with_both_words_semitransparent` —
  количество FT4, у которых для каждого из двух адресов
  зарегистрирован хотя бы один `semi=1`;
- `source_ft4_draws_with_interleaved_word_revisit` —
  количество FT4 с наблюдаемым возвратом к уже обработанной
  координате после другой, например `A → B → A` или
  `A → B → B → A`. Непрерывные `A → A → B` этому
  условию не соответствуют.
- `source_ft4_draws_with_both_words_changed_by_putpixel` —
  количество FT4 с **реально зарегистрированными изменившими
  слово вызовами PutPixel** по обоим выбранным адресам. Этот
  показатель может быть больше числа FT4 с изменениями обеих
  точек между снимками PRE/POST: промежуточная запись могла
  быть отменена следующим вызовом.
- `source_ft4_draws_with_both_words_changed_but_one_net_delta` —
  подмножество предыдущих FT4, где оба адреса временно
  менялись через PutPixel, но только **одно** слово отличается
  между полными VRAM-снимками этого примитива. Пример:
  `A: 0 → bit15 → 0` и `B: 0 → цвет` в одном FT4. Это
  доказательство *наблюдённой временной последовательности*,
  а не полноценной пиксельной растеризации.

Все показатели агрегированы **по FT4**; конкретные координаты
и порядок цветов наружу не выводятся. Они выявляют заявленные
совместные записи и пересечение *наблюдений* двух точек, но
не доказывают полное покрытие растеризацией, единственную
причину изменения VRAM или физическую точность PS1 GPU.

## Исполняемые проверки инструментирования

В дополнение к синтетическим Python-проверкам
`tests/test_instrument_map02_multi_putpixel_c11.py` компилирует
порожденный двухточечный наблюдатель вместе с маленьким
**искусственным** C11 `WritePixel`-драйвером. Он проверяет:

- что четыре вызова двух выбранных адресов попали в общий
  JSONL со сквозными `step` и исходными полями
  `frame/primitive_ordinal`;
- что вызов по третьему адресу, события вне заявленного кадра,
  совпадающие либо недопустимые координаты не создают
  лишние записи;
- что 70 последовательных вызовов ограничиваются
  **64 общими записями**, а не 64 для каждой точки;
- что компиляция без опционального флага не оставляет
  диагностические символы в обычном объектном файле.

GitHub Actions дополнительно компилирует
`libgpu.multiscope.c` и `pc_raster.multiscope.c`,
полученные из двух настоящих закреплённых публичных
исходников PC-порта, с включённым и выключенным
наблюдением, и запускает тесты приватной публикации
манифеста. Полный CI предыдущей версии на коммите
`af96c4edf10ea95eb2e2d6c94d65eba344c89f9f` успешно
завершился (GitHub Actions №39059304545); новые изменения
требуют новой проверки. Синтетический драйвер не
воспроизводит карту MAP02 или фактическую
полупрозрачную растеризацию игры.

## Достоверность и пределы

Один согласованный журнал действительно позволяет **проверить
заявленную общую последовательность** наблюдений двух точек лучше,
чем сложение двух независимых запусков. Но совпадающие SHA и
внутренние счётчики **не доказывают фактическое происхождение
журнала** из одного исполнявшегося процесса. Отчёт неизменно
оставляет `native_capture_process_identity_authenticated=false`,
`complete_original_putpixel_stream_proven=false`,
`physical_ps1_pixel_equivalence_verified=false` и
`real_map02_gameplay_authenticated=false`.

Проверка оригинального нативного PC-кода и синтетические тесты
не означают, что реальная MAP02 запущена на Nintendo Switch,
и **не разрешают** включать HD-подмену. Оригинальные игровые
ресурсы остаются только в приватном владении пользователя.
