# Vandal Hearts Remake — Stage345: PCM page ownership and retry data conservation

Stage344 re-hashed eight independently captured real NeXium virtual PCM streams across four original successfully source-verified runs, and measured exact-zero stereo frames and adjacent sample discontinuity indicators. Those indicators cannot prove missing audio frames or an `audout` buffer underrun because there is no independent per-frame reference or physical hardware queue trace.

Stage345 complements that analysis with a **native C stress test of the existing production buffer-lease and recovery code**. It does not alter the audio engine or guess about virtual emulator timestamps. The standalone test `tests/test_vh_audio_page_continuity_stage345.c` compiles together with the real `source/vh_audio_buffer_lease.c` and `source/vh_audio_output_recovery.c` under both GCC and Clang. It exercises 512 different synthesized stereo PCM pages with lengths 1–640 frames, varying sample values, deliberate incomplete submissions, incorrectly released descriptors, 1- or 2-restart recoveries and immutable same-page retries.

The fake audout backend verifies original PCM page pointer, frame count and full-page fingerprint on **every attempt**, including after session stop/reopen. It only advances its accepted stream hash after exact descriptor release, compares its accepted aggregate audio checksum and total frames with an independent expected stream, and insists that the same release is not counted twice. A foreign returned descriptor cannot release the page; a stop without a close cannot clear the lease. A final 3-fault scenario exceeds the existing two-restart limit, proving no false acceptance or page reuse until an explicit full session closure; safe reuse after close and a new successful page is checked separately. The test never synthesizes music anew for a transport retry.

The test is wired into the normal Host SPU regression workflow and runs in an independent `Stage345` GitHub Actions job with release-mode GCC/Clang and each compiler's undefined-behavior sanitizer. Stage345 success verifies **host-only behavior on fault-injected simulated queues**, not actual Switch device ownership, delivery to speakers, audout hardware scheduling, original PS1 soundtrack fidelity, or audible continuity. The prior strict original NeXium Stage299–305/334/336 source validators and game source remain untouched.
