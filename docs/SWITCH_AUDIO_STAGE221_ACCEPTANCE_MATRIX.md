# Vandal Hearts Remake — этап №221: итоговая матрица H01–H07 и план повторных испытаний

**Аппаратный статус: `HARDWARE NOT TESTED` до фактического подтверждения оператором.** Этот инструмент не заменяет запись на физической Nintendo Switch, независимую проверку звука и ручной подписанный протокол.

## Цель

[Инструмент `report_switch_audio_acceptance_matrix.py`](../tools/report_switch_audio_acceptance_matrix.py) принимает **два исходных типа файлов**, которые уже используют этапы №213–220:

- локальный каталог evidence bundle с NRO, исходными CSV и `audio-evidence-manifest.json`;
- отдельный **заполненный человеком** операторский JSON по схеме `vh-switch-audio-first-run-operator/v2` (либо старый v1, который по-прежнему считается неполным для H05).

Он заново выполняет строгую проверку SHA-256 файлов, структурный разбор CSV, [триаж PCM/HOME](../tools/report_switch_audio_hardware.py) и [проверку противоречий с карточкой](../tools/assess_switch_audio_first_run.py). Доверять вручную подготовленным «готовым отчётам» не нужно: данные считываются **непосредственно из исходных файлов**.

## Применение

```sh
python3 tools/report_switch_audio_acceptance_matrix.py \
  switch-audio-real-run-219 \
  --observations /path/outside-bundle/operator-v2.json \
  --format json > /path/outside-bundle/hardware-review-221.json

python3 tools/report_switch_audio_acceptance_matrix.py \
  switch-audio-real-run-219 \
  --observations /path/outside-bundle/operator-v2.json \
  --format markdown > /path/outside-bundle/hardware-review-221.md
```

**Не сохраняйте отчёт внутрь папки с проверяемыми NRO/CSV**, чтобы не смешивать первичные измерения и их интерпретацию.

По умолчанию оцениваются H01–H05, H06 и H07 честно отмечаются необязательными/неприменимыми. Если отдельно запланирован безопасный изолированный тест сбоя записи, добавьте `--require-h06`. Если делаете вывод об отсутствии регрессии **между двумя сборками**, добавьте `--compare-builds`: H07 получит `INCOMPLETE` до отдельного проверенного сравнения двух наборов CSV. Этот инструмент **не** принимает вторую сборку и **никогда не засчитывает** H07 автоматически.

```sh
python3 tools/report_switch_audio_acceptance_matrix.py \
  switch-audio-real-run-219 \
  --observations /path/outside-bundle/operator-v2.json \
  --require-h06 --compare-builds --format markdown
```

## Матрица и значения

| ID | Источник и критерий | Если данных нет / есть дефект |
| --- | --- | --- |
| **H01** | Минимум 2 разных CSV с `>=1000` наблюдаемыми PCM-страницами каждый и `EXIT`; заполнены наблюдения о физической Switch, слышимой музыке, выходе | `INCOMPLETE` при недостающих сеансах/данных; `INVESTIGATE` при подтверждённых PCM/выходных ошибках |
| **H02** | Оператор записал `>=10` HOME → возвратов, журнал проверен на `home_fail` и исторические ошибки | `INCOMPLETE` при недостатке/необъяснённых приращениях; `INVESTIGATE` при ошибках и заявленных дефектах |
| **H03** | Оператор записал `>=5` физических циклов сна | `INCOMPLETE` при отсутствии ручных наблюдений; `INVESTIGATE` при проблемах звука/возобновления |
| **H04** | Записан хотя бы один непрерывный музыкальный прогон продолжительностью `>=30` минут | `INCOMPLETE` при коротком/неизвестном сеансе; `INVESTIGATE` при слышимых/PCM-дефектах |
| **H05** | Сохранённый CSV первой сессии связан с конкретным путём и SHA-256 до/после повторного запуска; хеш согласован с первичным evidence | `INCOMPLETE` при отсутствии привязки; `INVESTIGATE` при несовпадении хешей |
| **H06** | Необязательный **безопасный** изолированный тест ошибки экспорта | По умолчанию `NOT_REQUIRED_FOR_THIS_REVIEW`, при `--require-h06` — `INCOMPLETE` до испытания; **не отключать питание** |
| **H07** | Отдельная проверка **двух** сборок (по 2 независимые CSV на версию, сопоставимое аудио и условия) | По умолчанию `NOT_REQUIRED_FOR_THIS_REVIEW`, с `--compare-builds` — `INCOMPLETE`; см. [сравниватель](../tools/compare_switch_audio_sessions.py) |

Для каждой строки выдаётся `status`, `reason`, `observed`, `manual_confirmation` и, если нужно действие, `next_action`. Массив `retests` отсортирован: сначала `INVESTIGATE`, потом `INCOMPLETE`, затем по номеру сценария. Таким образом, исправлять документированные сбои важнее, чем механически добирать статистику.

## Интерпретация и пределы доказательств

- `MANUAL_CONFIRMATION_REQUIRED` — только данные *заявлены как достаточные* для независимой человеческой оценки. Это **не PASS**.
- `INCOMPLETE` — не хватает необходимых записей или независимых измерений; повторить указанный сценарий.
- `INVESTIGATE` — наблюдаемая неисправность, изменение старого CSV, противоречивый выход или сбой аудиовосстановления; прежде расследовать и воспроизвести.
- `NOT_REQUIRED_FOR_THIS_REVIEW` — сценарий не требуется для первичной приёмки единственной сборки или не был безопасно запрошен.

Общий `result` — `INVESTIGATE`, `INCONCLUSIVE` либо `READY_FOR_INDEPENDENT_MANUAL_REVIEW`, но `hardware_status` **всегда** `HARDWARE NOT TESTED`. `0` как код выхода означает лишь успешное формирование отчёта. Если нарушены структура или хеш NRO/CSV, схема карточки или SHA сборки, вернётся **код 2** и `INVALID_EVIDENCE` без ложной матрицы приёмки.

Физические HOME и сон не выводятся однозначно из `home_resumes`. CSV имеет 128 строк и не доказывает продолжительность прослушивания. Отмеченные `operator_* = YES` по-прежнему **самозаявленные**. Согласованные SHA-256 старого CSV не доказывают независимое чтение SD после перезапуска.

Инструмент не выполняет запись на консоль/SD, не модифицирует файлы и не генерирует звуковые материалы. Для окончательного `PASS` требуются **реальные** результаты на Switch и подписанная ручная карточка с датой, моделью консоли, условиями вывода звука, выводами о слышимых дефектах, исходными CSV и порядком действий.

## Тестирование

[20 синтетических регрессионных тестов](../tests/test_report_switch_audio_acceptance_matrix.py) проверяют все семь строк, требования HOME/сна/длительности, старые схемы H05, ошибки PCM/выхода, неактуальные хеши, Markdown/JSON, приоритет повторных испытаний и неизменность исходных файлов, а также неполные сведения о слышимом звуке и режиме запуска. Тесты включены в `make test` и `make test-audio-stream`; ни один из них не использует физическую Nintendo Switch.

Продолжение: [протокол первого запуска №219](SWITCH_AUDIO_STAGE219_FIRST_RUN_PROTOCOL.md), [проверки согласованности №220](SWITCH_AUDIO_STAGE220_CONSISTENCY_GATES.md), [пакет H01–H07 №212](SWITCH_AUDIO_STAGE212_ACCEPTANCE_PACK.md).

## Этап №222 — передача полного пакета

Для окончательной передачи результатов одного NRO используйте [инструкцию №222](SWITCH_AUDIO_STAGE222_HARDWARE_HANDOFF.md): она описывает локальную папку исходных доказательств, отдельные JSON-карточки каждого запуска, SHA-256-инвентаризацию и проверку соответствия собранным сценариям H01–H07. Запуск `tools/audit_switch_audio_handoff.py` **не** заменяет аппаратную проверку; ни одна успешная карточка не считается физической аттестацией без независимого оператора.
