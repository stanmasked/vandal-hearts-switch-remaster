# MAP02 — локальное диагностическое изображение конечного VRAM

Инструмент `tools.export_map02_native_vram_preview` принимает **уже
записанные приватные** окна нативного GPU от одного запуска оригинального
PC-кода. Он повторно проверяет весь журнал пар `before/after`, номера кадров,
связность между окнами, SHA-256 полного конечного снимка видеопамяти и
неизменность файлов в ходе чтения.

Выход: **один локальный PNG** `map02-native-vram-preview.png` с правами
`0600` в **существующем** отдельном каталоге `0700`, без перезаписи файлов.
Имена путей и игровые пиксели в публичный отчёт не включаются. Пример
локального вызова с собственными диагностическими данными:

```bash
mkdir -m 700 /private/path/map02-preview
python3 -m tools.export_map02_native_vram_preview \
    /private/path/map02-native-windows \
    /private/path/map02-preview \
    --frame 7 --x 0 --y 0 --width 320 --height 240
```

Параметры `x,y,width,height` задают **только прямоугольник в адресном
пространстве VRAM 1024×512**. По умолчанию экспортируется весь VRAM. Эти
координаты **не** определяют игровое окно вывода. Протокол
`vh.map02.cycle-order.v5` добавляет отдельное наблюдение возвращённого
вызова `PC_GpuPresent` или `HiresPresent` и исходного прямоугольника
`display_source_rect`, но локальный экспортер PNG **не принимает**
эту квитанцию как разрешение автоматически объявлять свои пиксели
представленным кадром. Ветвь `HiresPresent` использует отдельный буфер,
не совпадающий с исходным 1-МиБ VRAM.

## Привязка к одной сессии и наблюдённой области вывода (v5)

Для локального подтверждения, что прямоугольник PNG соответствует
`display_source_rect` реально **возвращённого вызова** `PC_GpuPresent`,
передайте папку квитанции порядка CD→GPU:

```bash
mkdir -m 700 /private/path/map02-native-present-preview
python3 -m tools.export_map02_native_vram_preview \
    /private/path/map02-native-windows \
    /private/path/map02-native-present-preview \
    --frame 7 --cycle-directory /private/path/map02-cycle-gate
```

Экспортёр независимо читает **обе** запечатанные квитанции v5 (основную
и clean-exit, с различными inode), проверяет номер кадра, nonce-сессию
относительно индекса GPU-окон, точное число DRAW-пар и границы области
вывода. Ручные параметры `--x/--y/--width/--height` при таком режиме
запрещены: будет использован только наблюдённый прямоугольник. Синхронно
проверяются все GPU-снимки до и после чтения конечной точки; перед
созданием PNG также заново проверяются обе CD→GPU-квитанции.

При `present_backend_is_hires=true` создание PNG отклоняется: нативный
VRAM **не соответствует** отдельному supersampled framebuffer.
Приватные каталоги исходных снимков, квитанций и PNG должны быть разными
и не вложенными друг в друга; существующий PNG не перезаписывается.

Такое сопоставление доказывает **внутреннюю согласованность локальных
наблюдений**, а не подлинность игрового содержимого, окончательный
результат операционной системы или эквивалентность PlayStation. В
частности, оно не выполняет независимый аудит оригинального диска —
для этого необходим полный `verify_map02_cycle_cd_gpu_join`.
Запрещено прикреплять настоящий PNG, дампы VRAM или закрытые журналы
к публичным GitHub Actions.

## Независимое сравнение с PC RGB24 (до OSD)

В `platform/pc/src/pc_gpu_window.c` закреплённого PC-порта
`PC_GpuPresent` преобразует видимый BGR555-прямоугольник в
`s_rgbaScratch` **в перевёрнутом порядке строк**. После преобразования
в этот же scratch могут добавляться субтитры, сообщения камеры, индикатор
ускорения боя и меню. Итоговый скриншот окна дополнительно зависит от
масштабирования и SDL/GL.

Новый локальный верификатор строго сравнивает **внешне предоставленный**
приватный RGB24-буфер `map02-pc-present-preoverlay-rgb24.bin` с:
(1) независимой реконструкцией пикселей последнего проверенного 1-МиБ
VRAM в порядке PC scratch, и (2) PNG, созданным из наблюдённой области
в `cycle-order.v5`. Сначала должны существовать четыре раздельных
закрытых каталога (каждый `0700`):

- проверенные нативные GPU-окна со снимками VRAM;
- две идентичные по байтам, но отдельные по inode запечатанные
  квитанции `cycle-order.v5`;
- уже созданный приватный `map02-native-vram-preview.png`;
- закрытый `map02-pc-present-preoverlay-rgb24.bin` (`0600`)
  с **точно** `width*height*3` байтами, ещё до OSD/меню/субтитров.

```bash
python3 -m tools.verify_map02_pc_present_rgb24 \
    /private/path/map02-native-windows \
    /private/path/map02-cycle-gate \
    /private/path/map02-native-present-preview \
    /private/path/map02-pc-preoverlay-rgb24 \
    --frame 7
```

Для локального закрытого захвата подготовлен исходно-закреплённый
наблюдатель `map02_pc_preoverlay_capture.c`. Он включается **только** в
приватную сборку `prepare_map02_cycle_build`: в оригинальный
`pc_gpu_window.c` перед добавлением субтитров, OSD и меню вставляется
строго ограниченный вызов с `s_drawFrame` и `s_rgbaScratch`. В него
передаются признаки FMV и `HiresActive()`, которые обязательно должны
быть ложными, иначе наблюдатель отказывает в создании квитанции.

Для контролируемой приватной сессии используйте **отдельный ранее
созданный каталог `0700`**, не вложенный в остальные каталоги захвата,
и переменные окружения:

```bash
VH_MAP02_PROBE_FRAME=7
VH_MAP02_PC_PREOVERLAY_OUTPUT_DIR=/private/path/map02-pc-preoverlay-rgb24
```

В выбранном кадре создаются исключительно owner-only `0600` файлы
`map02-pc-present-preoverlay-rgb24.bin` и
`map02-pc-present-preoverlay-receipt.jsonl`. Квитанция содержит
**сгенерированный внутри того же процесса** nonce, кадр, размеры и
зафиксированные признаки native BGR555 → RGB24. Запрещены перезапись,
повторный кадр, FMV и supersampled framebuffer. При невыполнении условий
открытый наблюдатель останавливает тестовый процесс без фиктивной
квитанции. Закрытые игровые пиксели никуда не выгружаются.

Верификатор `tools.verify_map02_pc_present_rgb24` теперь требует **оба**
файла. Он проверяет, что SHA-256 процессного nonce равен nonce из
отдельной чисто завершённой квитанции `cycle-order.v5`, и связывает
кадр, размеры и количество RGB24-байтов с выводимым прямоугольником
VRAM. Два файла и их inode перечитываются после дорогого GPU-аудита.

**Ограничение:** отметка в квитанции `source_pinned` сама по себе не
является криптографическим доказательством происхождения дампа; изъятые
байты можно подделать вне процесса. Полный независимый аудит локального
исполняемого файла и привязка к оригинальным дисковым данным остаются
отдельными необходимыми шагами. Публичный CI использует лишь искусственные
RGB24-байты, а не оригинальную сцену игры.

Перед сравнением проверяются общая сессия GPU/cycle, количество DRAW-пар,
нормальный выход процесса, точный SHA-256 конечного VRAM и оба снимка
доказательств; после сравнения все источники проверяются повторно. Если
`HiresPresent` активен — сравнение отклоняется: эта ветка читает
отдельный hi-res буфер. Самостоятельные кино-оверлеи (FMV) также не
сопоставимы с нативным VRAM, и их должен исключать захват. Новый
проверяющий файл не изменяет исходные данные; отчёт содержит только
метаданные и SHA-256 и **не удостоверяет** ни подлинность источника RGB24,
ни изображение системного окна, ни сцену MAP02 на PS1.

## Отдельная приватная квитанция успешного завершения

После успешного выполнения `finalize_map02_private_capture` можно
создать долговременную контрольную квитанцию. Заранее создайте **новый,
пустой, отдельный** каталог `0700`, который не совпадает с каталогами
захвата и не вложен в них. Команда `seal` повторяет **два полных
независимых read-only аудита**, и только при полном совпадении
эксклюзивно записывает файл `0600`:

```bash
mkdir -m 700 /private/map02/final-seal

python3 -m tools.seal_map02_private_finalization seal \
  /private/map02/source /private/map02/native-windows \
  /private/map02/scoped /private/map02/handoff \
  /private/map02/cycle /private/map02/native-preview \
  /private/map02/preoverlay /private/map02/owned-disc.bin \
  /private/map02/final-seal \
  --upstream-checkout /private/map02/VandalHearts-PcPort \
  --pc-binary /private/map02/instrumented-pc-port --frame 7
```

В закрытом каталоге появится только
`map02-postcapture-final-seal.jsonl`. Его SHA-256 связывает
process receipt, original CD/GPU свидетельство, RGB24, PNG, сессию и
целевой кадр. Никакие игровые ресурсы или бинарные скриншоты в файл не
входят. Существующую квитанцию невозможно перезаписать этой командой.

После эксклюзивной записи `seal` дополнительно **открывает
записанную квитанцию заново** и выполняет третий независимый
read-only аудит исходного CD/GPU/process, RGB24 и PNG. Положительный
статус возвращается только после совпадения SHA-256 и номера кадра.
Непосредственно перед положительным ответом дополнительно сверяется
**полная идентичность опубликованного inode**: подмена файлом с теми
же байтами и SHA-256 не считается успешным захватом. Квитанция должна
иметь строго каноническое JSONL-представление (одна строка,
отсортированные ключи, компактные разделители, завершающий LF).
Если этот последний проход завершился ошибкой, процедура не сообщает
об успехе и удаляет квитанцию **только если inode и полные метаданные
совпадают с созданным ею файлом**. Чужой или заменённый файл не
удаляется. При ошибке первоначальной записи изменённый inode
также сохраняется вместо рискованного удаления. Защита снижает риск
подмены свидетельств между чтением и публикацией, но не заменяет
изоляцию каталога от других процессов того же владельца.

Для независимого контроля выполняется **та же команда с действием
`verify`** вместо `seal`. Она заново проверит оригинальную
CD/GPU/process/RGB24/PNG-цепочку, затем сравнит её с неизменной
квитанцией по байтам и inode. Если хотя бы один исходный файл или
квитанция изменились, положительного результата не будет.

Команда не запускает оригинальную игру, не помещает ничего на GitHub
и не удостоверяет реальную сцену MAP02: для этого всё ещё
необходимы оригинальные приватные данные и фактический запуск.
При успешной проверке `original_map02_rendering_proven=false`
остаётся обязательной границей достоверности.

## Одна команда для локального завершения захвата

После **заранее выполненного** строго проверенного PC-запуска (и
`--stop-after-target-present` при необходимости) используйте локальный
постпроцессор. Он не исполняет игру и не копирует оригинальные файлы:

```bash
python3 -m tools.finalize_map02_private_capture \
  /private/map02/source /private/map02/native-windows \
  /private/map02/scoped /private/map02/handoff \
  /private/map02/cycle /private/map02/native-preview \
  /private/map02/preoverlay /private/map02/owned-disc.bin \
  --upstream-checkout /private/map02/VandalHearts-PcPort \
  --pc-binary /private/map02/instrumented-pc-port \
  --frame 7 --complete-missing
```

Семь каталогов должны быть существующими, отдельными и владельческими
`0700`. В каталоге PNG допускается только
`map02-native-vram-preview.png` либо полная пустота. Каталог source
содержит заранее проверенные original GTE/GPU-свидетельства. Флаг
`--complete-missing` **явно разрешает** создать только отсутствующие
`gpu-native-map02-cd-process-source-witness.json` (в source) и
`map02-native-vram-preview.png` (в native-preview), строго в этом
порядке. Без флага команда **только проверяет существующие файлы**.

До публикации проверяются штатная квитанция процесса v3, clean-exit
cycle v5 и квитанция RGB24 той же сессии, кадра и размера. CD-свидетельство
сверяется после записи независимым переоткрытием, PNG строится из
подтверждённого конечного VRAM и наблюдённой native display-области.
После этого повторно выполняются полный original CD/GPU/process join
и независимое побайтовое RGB24/VRAM/PNG сравнение. Исходные
квитанции перепроверяются на bytes/inode после полного аудита.

При ошибке **нет положительного отчёта**. Уже созданные в приватном
каталоге файлы остаются локальными, не выдаются за завершённую проверку
и могут быть независимо проверены при повторном запуске без флага.
Ничего не отправляется в CI, облако или GitHub. Единственный печатаемый
результат содержит SHA-256, кадр, число DRAW и флаги границ
достоверности; ни пути, ни оригинальные пиксели не выводятся.

Даже полностью успешный запуск этого помощника не доказывает
оригинальный MAP02-геймплей, показ конечного окна ОС или аппаратную
эквивалентность PlayStation. Публичные CI-тесты используют
**искусственные** свидетельства; проверки розничного образа
в них имитируются и не выдают ложную аутентификацию.

## Финальная независимая связь CD/GPU/process с RGB24/PNG

Команда `tools.verify_map02_final_pc_frame_join` ничего не запускает
и не публикует. Она принимает семь **раздельных непересекающихся**
приватных каталогов: source CD/GPU/GTE witness, GPU VRAM windows,
scoped CdRead/PutPixel, process handoff, cycle-order v5, PNG и RGB24.
Отдельно указываются проверенный собственный диск, закреплённый
PC-upstream и исходно-подтверждённый диагностический ELF.

```bash
python3 -m tools.verify_map02_final_pc_frame_join \
  /private/map02/source /private/map02/native-windows \
  /private/map02/scoped /private/map02/handoff \
  /private/map02/cycle /private/map02/native-preview \
  /private/map02/preoverlay /private/map02/owned-disc.bin \
  --upstream-checkout /private/map02/VandalHearts-PcPort \
  --pc-binary /private/map02/instrumented-pc-port --frame 7
```

Проверка требует process receipt **v3**, содержащую
`pc_preoverlay_image_sha256` и `pc_preoverlay_receipt_sha256`.
Оба хеша должны совпасть с приватным дампом и квитанцией RGB24 ещё
**до** дорогостоящей полной проверки. Старая v2 (без захвата RGB24)
отклоняется. SHA-256 `gpu-local-executed-process.json`
должен действительно совпасть с `observed_process_receipt_sha256`
из уже сформированного оригинального CD/GPU/process-witness; номера
кадров и хеш nonce должны совпасть с обеими отдельными квитанциями.
Затем **заново** запускаются полноценный CD/GPU/GTE/OS-process
верификатор и независимое побайтовое сравнение native VRAM ↔
RGB24 (bottom-up) ↔ PNG. Файлы обеих цепочек до и после проверяются
на байты, inode и метаданные. Отклоняются вложенные каталоги, чужие
квитанции, заменённые файлы, неполные GPU-команды, hi-res и неверная
цветовая конверсия.

Это **сводный отчёт о согласованности**, а не подпись производителя,
не снимок окна ОС и не подтверждение настоящей сцены MAP02. В отчёте
нет текстовых путей, бинарных игровых ресурсов или пикселей, только
выбранный кадр, границы, количество DRAW-примитивов и SHA-256.
Все тесты публичного CI используют искусственные данные; неподтверждённое
происхождение изображения явно помечено как `false`.

Формат каждого исходного пикселя — 16-битный little-endian PS1/PC
BGR555: пять младших битов — красный, следующие пять — зелёный,
следующие пять — синий. Каналы расширяются до RGB888 без фильтрации;
старший бит STP является признаком полупрозрачности исходного GPU и
не интерпретируется как альфа готового изображения.

В отчёте остаются лишь выбранный номер кадра, координаты, SHA-256
конечного 1-МиБ VRAM и SHA-256 локального PNG. В отчёте явно указано,
что **подлинная сцена MAP02, состав представленного framebuffer и
эквивалентность аппаратному PS1 не доказаны**. Публичный CI использует
исключительно искусственные пиксели и события. Исходный диск, VRAM
реальной игры и полученный PNG не загружаются в репозиторий и не
прикрепляются к артефактам GitHub Actions.
