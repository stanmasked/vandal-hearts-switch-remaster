# Vandal Hearts Remake — этап №230: единый контроль перед физическим запуском NRO

**HARDWARE NOT TESTED.** Утилита не запускает Nintendo Switch, не копирует файлы на SD, не проверяет звук и не изменяет доказательства. Она устраняет риск случайно испытывать **не тот NRO** после скачивания CI-сборки.

## Что проверяется

[Скрипт `tools/verify_switch_audio_launch_gate.py`](../tools/verify_switch_audio_launch_gate.py) последовательно выполняет:

1. **GitHub HTTPS-проверку №217:** подтверждает успешный запуск `Switch toolchain readiness` для указанного коммита, исходной ветки и артефакта, который **на момент проверки** принадлежит текущему HEAD тестовой ветки. Проверяется возраст и срок действия артефакта, SHA-256 ZIP и его внутренний NRO.
2. **Квитанцию CI №229:** требует, чтобы рядом с NRO в скачанном ZIP была `vandal-hearts-prototype.build.json`. Полный SHA, ветка, номер CI-запуска и попытки должны соответствовать **полученной по HTTPS записи GitHub**. **Старые NRO-only артефакты сознательно отклоняются** в этом конкретном предзапусковом режиме.
3. **План копирования №218:** повторно сверяет исходный NRO, неподписанный манифест и отдельно сохранённый на компьютере план записи. Прежний NRO на SD не заменяется.
4. **Прочитанную заново копию NRO в указанном SD-каталоге:** размер, SHA-256, структурный NRO-заголовок и относительный путь должны согласоваться с GitHub ZIP, CI-квитанцией и исходной сборкой.

Инструмент возвращает `READY_FOR_MANUAL_DEVICE_LAUNCH` **только** при совпадении этих слоёв. Это означает «готово для выполнения настоящего испытания человеком», **не** успешное испытание.

## Инструкция оператору

### Шаг 1 — получить именно текущую сборку

Скачайте артефакт `vandal-hearts-switch-prototype` успешного запуска `Switch toolchain readiness` из GitHub Actions, сохраните **оригинальный ZIP**, а для будущего манифеста выпишите **реальные** полные Git SHA, run ID и artifact ID. Не смешивайте NRO и квитанции из разных запусков. В CI-артефакте этапа №229 оба файла находятся рядом.

### Шаг 2 — подготовить локальный источник и план

Создайте проверенный evidence bundle №214 на основе **извлечённого NRO того же самого ZIP**. До реальных испытаний bundle может содержать **нулевое** количество CSV; это не означает, что тесты H01–H05 уже выполнены. Укажите точный Git SHA и URL CI-запуска.

```sh
python3 tools/verify_switch_audio_bundle.py create ./source-bundle \
  --git-sha ACTUAL_FULL_COMMIT_SHA \
  --ci-run-url https://github.com/stanmasked/vandal-hearts-switch-remaster/actions/runs/ACTUAL_RUN_ID \
  --nro nro/vandal-hearts-prototype.nro
```

Перед ручным копированием NRO на SD создайте план **вне каталогов исходных материалов и SD**:

```sh
python3 tools/verify_switch_audio_sd_transfer.py plan ./source-bundle \
  --sd-root /path/to/mounted-sd \
  --output /path/outside/sd-transfer-plan.json
```

Теперь вручную скопируйте NRO в каталог:

`switch/vandal-hearts-remake/vandal-hearts-prototype.nro`

Не копируйте квитанцию как исполняемую игру. Не извлекайте работающую SD и не выключайте питание ради теста записи.

### Шаг 3 — единый финальный контроль перед запуском

```sh
python3 tools/verify_switch_audio_launch_gate.py ./source-bundle \
  --artifact-zip /path/to/original-github-artifact.zip \
  --run-id ACTUAL_RUN_ID \
  --artifact-id ACTUAL_ARTIFACT_ID \
  --sd-root /path/to/mounted-sd \
  --transfer-plan /path/outside/sd-transfer-plan.json \
  > /path/outside/launch-gate-230.json
```

Команда использует HTTPS для получения **актуальных** данных с GitHub. Интернет требуется при проверке; сохранённые оператором JSON-метаданные для этого недостаточны.

Сохраните вывод и, если `result: READY_FOR_MANUAL_DEVICE_LAUNCH`, **только теперь** переходите к настоящему запуску на консоли. Перед началом фактического испытания при существенной задержке повторите preflight: HEAD ветки и статус артефакта могут измениться.

## Что входит в отчёт

| Поле | Значение |
| --- | --- |
| `git_sha_confirmed_by_github_at_check_time` | Git-коммит, подтверждённый по HTTPS на момент запроса |
| `run_id`, `artifact_id`, `run_attempt` | Конкретный запуск и попытка CI |
| `artifact_zip_sha256` | SHA-256 **скачанного ZIP целиком** |
| `installed_nro_sha256`, `installed_nro_size` | Повторно считанные байты NRO на указанном SD-root |
| `sd_destination_relative` | Путь проверенного NRO относительно каталога SD |
| `verified_layers` | Какие программные границы проверки пройдены |
| `physical_sd_medium_attested: false` | Путь может оказаться обычной локальной папкой, а не реальной SD |
| `physical_launch_attested: false` | Фактического запуска на консоли ещё не было |
| `audible_music_attested: false` | Качество музыки невозможно определить по SHA-256 |
| `csv_diagnostics_attested: false` | Сырые журналы текущего аппаратного теста ещё не получены |

На ошибку утилита отвечает `INVALID_EVIDENCE` и кодом `2`: например, если изменилась ветка, скачан старый ZIP, отсутствует CI-квитанция, NRO на SD повреждён, в плане сохранён другой SHA или повреждён манифест. **Никакой ошибочный вход не возвращает «готово».**

## После проверки

Нужна настоящая [процедура первого запуска №219](SWITCH_AUDIO_STAGE219_FIRST_RUN_PROTOCOL.md) на Nintendo Switch: слышимая музыка, HOME и возврат, сон и пробуждение, непрерывное прослушивание, два независимых диагностических CSV и контроль сохранности старого CSV при следующем запуске. Для финального пакета используйте [аудит №222](SWITCH_AUDIO_STAGE222_HARDWARE_HANDOFF.md).

Результат №230 не доказывает, что NRO реально был скопирован на съёмную SD: он **только читает** файл по указанному пути. Он не удостоверяет сброс файловой системы на носитель, долговечность данных, отсутствие помех или правильность звука на физическом оборудовании.

[17 синтетических регрессионных сценариев](../tests/test_verify_switch_audio_launch_gate.py) покрывают корректный комплект, устаревшую сборку, неподходящую попытку CI, legacy-ZIP без квитанции, отсутствие/повреждение/символьную ссылку SD-файла, повреждение исходника/плана, неподтверждённый запуск и отсутствие изменения файлов. Тесты входят в `make test` и `make test-audio-stream`. Реальной консоли в тестах нет.

## Этап №231 — повторное чтение SD после безопасного переподключения

После успешной проверки GitHub → NRO → SD №230 можно выполнить [протокол №231](SWITCH_AUDIO_STAGE231_SD_REINSERT_READBACK.md) через `tools/verify_switch_audio_sd_reinsert.py`: команда `record` заново проверяет текущую CI-сборку и сохраняет вне SD исходную JSON-карточку с SHA-256. Затем оператор **вручную и безопасно** отключает/подключает SD, а `recheck` по независимо сохранённому SHA-256 этой карточки сравнивает идентичность исходного ZIP, Git SHA, NRO, плана и манифеста после повторного чтения. Работа ОС с извлечением карты программно **не наблюдается**. Никакой результат не подтверждает настоящий носитель, запуск Switch или качество звука — статус `HARDWARE NOT TESTED` сохраняется.
