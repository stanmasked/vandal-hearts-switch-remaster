# MAP02 v185 — synthetic PS1 RAM persistence between real VBlank windows

Base: fully green [MAP02 v184 Draft PR #214](https://github.com/stanmasked/vandal-hearts-switch-remaster/pull/214) (77/77 GitHub Actions, real pinned PCSX ReARMed/Unai GCC and Clang). The prior v183/v184 native tests validated actual synthetic MIPS `SW → LW → XORI → SW` RAM values and wrong-instruction refusals, but **v183 pre-seeded both scratch words before every phase**: that proves each phase's guest computation, not that completed data survives until the next phase.

v185 adds a completely independent diagnostic flag family `--vh185-ram-persist-0..3` atop the same nine-instruction synthetic `V183_RAM_CORRECT.EXE` and the inherited genuine four-VBlank/2380-pixel Unai oracle. The positive case (`0`) seeds once, at phase zero, three distinct RAM values: initial source and destination sentinels at `0x001e0000` and `0x001e0004`, plus a guard `0xa1b2c3d4` at `0x001e0008` outside all signed guest SW writes. The guest computes the documented final values `0x51a7c3d9` and `0x51a73c26`. At each of the **three following phase boundaries**, the native frontend reads all three words with real `psxMemRead32` **before** executing the guest wait-padded MIPS again. A mismatch fails with native exit **86** before guest code can overwrite and mask it; the final positive marker requires three correctly preserved pre-execution boundaries, four genuine emulator-internal VBlanks and 2380 Unai samples. The repeated guest writes in phases 1–3 are not claimed to be suppressed; the *pre-execution snapshots* establish persistence independently of those repeated writes.

Three negative modes deliberately flip one low bit **in the test harness immediately after phase zero completes**, without changing the source-authored guest executable: mode `1` corrupts the first guest-computed word, mode `2` the derived word, and mode `3` the unrelated neighbor guard. All three must refuse at **phase one** with `VH185_NATIVE_RAM_PERSISTENCE_REFUSED` and precisely one `*_ok=0`, native exit 86, and no final positive v185/v183/Unai marker. This mutation is **test-only host corruption**, deliberately disclosed, not a simulated game feature or an inference that the guest mutated memory. No host-forged VBlank events, source game ROM or GPU pixel injection are introduced.

An independent GCC/Clang source/phase-model test checks seed-once source placement, three pre-execution checks, native failure wiring and four strict CLI variants. The existing v184 positive and five cumulative negative synthetic guest tests are retained by the stacked native workflow. Nothing here verifies original retail Vandal Hearts MAP02, native Nintendo Switch display parity or a finished remake.
