# Vandal Hearts Remake — этап №231: контроль NRO до и после ручного переподключения SD

**`HARDWARE NOT TESTED`.** Этот этап не заменяет испытания на Nintendo Switch и не утверждает, что программно обнаружено физическое переподключение носителя. Утилита не размонтирует SD и никогда не пишет на неё.

## Зачем добавлен этот контроль

[Предзапусковая проверка №230](SWITCH_AUDIO_STAGE230_PRELAUNCH_GATE.md) подтверждает совпадение исходного NRO из GitHub Actions и файла, который в момент проверки виден по указанному пути SD. Однако единственного чтения до безопасного извлечения носителя недостаточно даже для простого практического контроля повторной доступности и неизменности NRO.

Новая [`tools/verify_switch_audio_sd_reinsert.py`](../tools/verify_switch_audio_sd_reinsert.py) предоставляет **двухэтапный read-only протокол** с независимым SHA-256 исходной карточки.

- `record` заново выполняет **весь** этап №230 по актуальным HTTPS-метаданным GitHub, проверяет NRO в локальном каталоге SD и записывает на **компьютер, вне SD и evidence bundle**, исходную JSON-карточку с Git SHA, run/attempt, artifact ID, SHA-256 ZIP и NRO, SHA-256 манифеста и плана SD-переноса.
- Пользователь сохраняет возвращённый SHA-256 **карточки целиком** в независимом доверенном месте. После этого вручную, штатными средствами ОС, безопасно извлекает SD, отключает её, подключает снова и дожидается монтирования. **Не вынимайте SD во время работы консоли, записи или незавершённой операции ОС.**
- `recheck` требует старую карточку и независимо сохранённый SHA-256, явное утверждение оператора о выполненном переподключении и повторно выполняет **весь** этап №230. Результаты сравниваются по Git SHA, run, attempt, ZIP, NRO, манифесту, плану и относительному пути установки. Изменение любого параметра приводит к отказу.

Эта схема помогает отследить случайную замену NRO или повреждение файлов при копировании и повторном подключении. Она **не** доказывает физическое извлечение, долговечность записи при потере питания, подлинность пользователя и работоспособность аудио на Switch.

## Подготовка

Нужны те же реальные файлы, что в №230: скачанный из GitHub Actions ZIP с NRO и `build.json`, каталог `source-bundle` с проверенным манифестом, отдельно сохранённый `sd-transfer-plan.json`, читаемая SD-папка и действительные GitHub run/artifact ID.

Для корректной работы у компьютера должен быть HTTPS-доступ к GitHub. Старые NRO-only артефакты не принимаются — необходима квитанция CI №229.

## Шаг 1 — прочитать NRO до отсоединения

```sh
python3 tools/verify_switch_audio_sd_reinsert.py record ./source-bundle \
  --artifact-zip /path/to/github-artifact.zip \
  --run-id ACTUAL_GITHUB_RUN_ID \
  --artifact-id ACTUAL_GITHUB_ARTIFACT_ID \
  --sd-root /path/to/mounted-sd \
  --transfer-plan /safe/outside/sd-transfer-plan.json \
  --output /safe/outside/before-reinsert-231.json
```

При успехе ответ содержит `result: PRE_REMOUNT_SD_READBACK_RECORDED`, `baseline_sha256` и `hardware_status: HARDWARE NOT TESTED`. Сохраните **`baseline_sha256` отдельно** от JSON и SD. Если выходной файл уже существует, команда откажется его заменять.

## Шаг 2 — безопасно переподключить карту

Вручную, после окончания операций чтения и записи, выполните штатное **Eject / Safely Remove** через ОС, отсоедините SD-карту и подключите обратно. При работе с консолью действуют инструкции Nintendo для безопасного извлечения карты — не экспериментируйте с горячим извлечением и не выключайте питание ради проверки.

Поскольку программа не имеет права управлять аппаратной SD-картой, повторное подключение отмечается **лишь заявлением оператора**. Даже успешно прочитанный после этого файл может находиться в обычной папке компьютера.

## Шаг 3 — проверить повторное чтение

```sh
python3 tools/verify_switch_audio_sd_reinsert.py recheck ./source-bundle \
  --artifact-zip /path/to/github-artifact.zip \
  --run-id ACTUAL_GITHUB_RUN_ID \
  --artifact-id ACTUAL_GITHUB_ARTIFACT_ID \
  --sd-root /path/to/remounted-sd \
  --transfer-plan /safe/outside/sd-transfer-plan.json \
  --baseline /safe/outside/before-reinsert-231.json \
  --expected-baseline-sha256 ACTUAL_INDEPENDENT_BASELINE_SHA256 \
  --operator-confirmed-reinsert \
  > /safe/outside/reinsert-review-231.json
```

Значение `ACTUAL_INDEPENDENT_BASELINE_SHA256` замените **точными 64 символами из доверенно сохранённого результата первого шага**. Не копируйте хеш из потенциально подменённого файла рядом с ZIP.

## Результаты и ограничения

| Результат | Интерпретация |
| --- | --- |
| `PRE_REMOUNT_SD_READBACK_RECORDED` | До ручного извлечения считаны байты NRO и сохранена контрольная карточка |
| `POST_REINSERT_LOCAL_NRO_BYTES_MATCH` | Повторное чтение указанной папки, живые GitHub-метаданные и ранее закреплённые хеши совпадают |
| `INVALID_EVIDENCE` | Карточка повреждена/изменена, не заявлено ручное действие, устарела сборка, поменялся ZIP/план/манифест/NRO, отсутствует файл или иная строгая проверка не пройдена |

Код завершения `0` не означает физическую аппаратную приёмку. При отказе возвращается код `2`. Любое несовпадение следует расследовать на исходных файлах, а не исправлять редактированием CSV или подменой доказательств.

Даже при успешном повторном чтении итоговый JSON **обязательно** сохраняет `operator_reinsert_claim: SELF_REPORTED_NOT_INDEPENDENTLY_ATTESTED`, `physical_sd_medium: NOT_ATTESTED`, `sd_power_loss_durability: NOT_TESTED` и `audible_music: NOT_TESTED`. Одна только эта проверка не устанавливает реальное физическое переподключение.

Следующий реальный этап — [аппаратный протокол №219](SWITCH_AUDIO_STAGE219_FIRST_RUN_PROTOCOL.md): физический запуск NRO, слышимая музыка, HOME, сон, два независимых CSV и проверка старого файла после повторного запуска.

[21 синтетический regression-тест](../tests/test_verify_switch_audio_sd_reinsert.py) проверяет точные байты, отсутствие SD-копии, подмену NRO того же размера, плохие SHA/JSON, неверные CI run/attempt, устаревшую ветку, повреждённые ZIP/план/манифест, смену времени, read-only исходники, обязательность явного заявления оператора и запрет автоматической аппаратной приёмки. Тесты выполняются в `make test` и `make test-audio-stream`; все SD-каталоги тестов являются локальными временными папками.
