# MAP02 — ограниченные окна нативных GPU-событий (PC-порт)

Этот экспериментальный режим предназначен для локальной приватной
диагностики оригинального PC GPU-кода, когда 64 события недостаточно.
Он **не включается автоматически** и не публикует игровые ресурсы.

## Один запуск, два последовательных окна

Новый генератор сохраняет два окна **одного и того же выполнения**
оригинальных `libgpu.c` и `pc_raster.c`. Не допускается склейка
двух повторных запусков игры с предположением, что кадры совпали.

На Linux/POSIX собрать приватную копию инструментированного
`libgpu.c` с двумя флагами:

- `-DVH_MAP02_GPU_CAPTURE`
- `-DVH_MAP02_POSIX_CAPTURE_WINDOWS`

В отдельной пустой директории владельца с разрешениями 0700 запустить
собранный локально PC-порт с собственными легально полученными данными:

```sh
export VH_MAP02_GPU_CAPTURE_DIR=/private/map02/native-windows
export VH_MAP02_GPU_CAPTURE_FRAME=<real-gpu-draw-frame>
export VH_MAP02_GPU_CAPTURE_WINDOW_COUNT=2
# Запустить собственный инструментированный PC-порт локально.
```

`<real-gpu-draw-frame>` — номер выбранного вызова DrawOTag, а не
номер исходного кадра MAP02. Значение определяется только из
фактического запуска. При недопустимой переменной, плохих разрешениях
корневой папки или отсутствии явного выбора кадра запись не включается.
Без второго компиляционного флага режим окон недоступен.

Нативный регистратор записывает только настоящие рисующие команды
F4/FT4/SPRT/TILE (не DR_MODE), а также операции LoadImage, MoveImage,
ClearImage. Глобальный порядок событий и число попыток записей
сохраняются в квитанции после завершения выбранного DrawOTag.

## Файлы и пределы

```text
/private/map02/native-windows/
  gpu-native-window-index.json          # явная квитанция, не сертификат MAP02
  window-000/
    gpu-native-events.jsonl             # локальные step 0..63
    gpu-0000-vram.bin
    ...
    gpu-0063-vram.bin
  window-001/
    gpu-native-events.jsonl             # локальные step 0..N
    gpu-0000-vram.bin
    ...
```

Обе подпапки создаются с правами 0700. Индекс содержит
`observed_hooks`, `before_hooks`, `after_hooks`,
`indexed_hooks`, `written_hooks`, число окон, состояние завершения
OT и явные признаки переполнения или ошибки. Если запись доходит
ровно до **128 событий**, приёмка консервативно отклоняется:
отсутствие следующей команды само по себе не доказано.

Один снимок VRAM занимает 1 МиБ. Максимальная ёмкость режима —
**128 МиБ необработанных снимков**, плюс ограниченные данные загрузки
и журналы. Выбирать этот режим следует только при достаточном
приватном свободном месте. Никакие снимки или игровые ресурсы
нельзя отправлять в публичный GitHub/Actions.

## Проверка непрерывности

```sh
python3 -m tools.verify_map02_native_gpu_windows \
  /private/map02/native-windows \
  --frame <real-gpu-draw-frame>
```

Валидатор отвергает пропущенные окна и файлы, изменённый порядок,
неполные пары before/after, символьные ссылки, несовпадение счётчиков,
достигнутый лимит, недопустимые разрешения и незавершённый обход
DrawOTag. Он повторно использует существующий аудит исходных
1-МиБ снимков для **каждого окна**. Затем сравнивает SHA-256
последнего VRAM-снимка каждой GPU-операции с полным снимком
непосредственно перед следующей операцией — **включая стык между
окнами**. Пиксели и исходные игровые данные в отчёте не выводятся.

Если 34 синтетических примитива дают 68 событий, окно 0 содержит
64, окно 1 — 4 события, а проверка выполняет 33 сопоставления
соседних пар. Гарантия относится к наблюдаемой последовательности
одного PC-процесса и не доказывает отсутствие неинструментированных
событий до первого или после последнего захвата.

## Что ещё не подтверждено

Схема `vh.map02.native-windows.v1` **намеренно отделена**
от прежнего `gpu-native-events.jsonl` и его манифестов.
`check_map02_private_capture_ready` и финальные
источниково-привязанные PutPixel/BlendG1/VRAM-проверки пока ожидают
старый единый формат. Успешный оконный отчёт **нельзя** подставлять
вместо доказательства полного исходного кадра, исходных GTE/OT-событий
или подлинной MAP02.

Дальнейший этап — отдельная источниково-привязанная сверка оконных
свидетельств с оригинальным MAP02 и приватный итоговый SHA-манифест.
HD-подмена остаётся отключённой до независимого подтверждения
оригинальной сцены.

## Независимая исходная MAP02 и SHA-свидетельство окон

Добавлена **отдельная** проверка
`tools.verify_map02_source_native_windows`. Она не склеивает окна
с прежним однофайловым валидатором и не принимает номер DrawOTag за
номер исходного кадра. Для неё нужны два собственных приватных
каталога: исходная карта MAP02 с `bundle.json`, декодированными
данными, исходной VRAM, `gpu-events.jsonl), и уже закрытый каталог
окон GPU.

В каталоге исходного комплекта необходимо **независимо предоставить**
`gpu-native-window-source-claim.json` формата
`vh.map02.native-window-source-claim.v1`. Поля обязательны:

```json
{
  "schema": "vh.map02.native-window-source-claim.v1",
  "source_frame": 1,
  "gpu_draw_frame": 1,
  "source_bundle_manifest_sha256": "<64 lowercase hex chars>",
  "source_events_sha256": "<64 lowercase hex chars>",
  "native_window_index_sha256": "<64 lowercase hex chars>",
  "source_events_in_addprim_order": true,
  "one_clear_otag_one_draw_otag": true
}
```

**Числа 1 в примере — только пример формата, а не установленные
счётчики настоящей MAP02.** При реальном захвате пользователь должен
указать фактические разные часы игры и GPU и подписанные им самим
утверждения об источнике. Указанные SHA-256 являются контрольными
суммами байтов соответствующих файлов. Эти утверждения не являются
доказательством игровой подлинности.

```sh
python3 -m tools.verify_map02_source_native_windows \
  /private/map02/source-bundle /private/map02/native-windows

# Только после успешной полной проверки:
python3 -m tools.publish_map02_native_window_source_witness \
  /private/map02/source-bundle /private/map02/native-windows --publish

# Повторная полная проверка после закрытия исходных данных:
python3 -m tools.publish_map02_native_window_source_witness \
  /private/map02/source-bundle /private/map02/native-windows
```

Новый проверяющий модуль:

- обязательно запускает `verify_bundle`: SHA исходных MAP02/VRAM,
  исходную геометрию и скомпилированный PC GTE;
- повторяет `verify_native_windows`: каждое исходное native-окно,
  все полные снимки VRAM и непрерывность между ними;
- требует однозначного совпадения каждого исходного FT4 по всем
  координатам, UV, tpage, CLUT и окну текстуры; не выбирает
  «наиболее похожий» пакет;
- сопоставляет все исходные слова текстур и CLUT с VRAM именно
  **перед соответствующим GPU-примитивом**;
- восстанавливает относительный порядок исходных FT4 согласно
  исходному AddPrim и глубинам OT;
- повторно проверяет исходные файлы и хеш всех данных окон после
  выполнения дорогой проверки.

При успехе публикуется `gpu-native-window-source-witness.json`
**только в приватный исходный каталог**, с исключительным созданием
без перезаписи. Он связывает SHA-256 пользовательского claim,
проверенных исходных GTE-событий и bundle, native индекс и
детерминированную контрольную сумму **всех файлов всех окон**
(включая сами снимки VRAM). Последующий запуск снова выполняет
исходную и GPU-проверку: наличие одного JSON-манифеста без файлов
никогда не считается успехом.

Ограничения сохраняются: до 32 исходных FT4, максимум 2 native-окна,
только однозначная проверенная подпоследовательность MAP02 FT4 в
глобальном DrawOTag. Полное игровое происхождение, отсутствие других
GPU-вызовов вне окна, физическая точность PS1 и полная HD-подмена
**не подтверждены**.

## Подтверждённый этап интеграции — 17 октября 2026 года

[Успешный GitHub Actions — исходный FT4 + оконный GPU](https://github.com/stanmasked/vandal-hearts-switch-remaster/actions/runs/39022767471)
для коммита `3326f9dd` подтвердил **96 из 96 тестов** и выполнение
оригинального PC GPU-кода.

Синтетические тесты проверяют:

- корректную привязку user-supplied source/GPU frame clocks, SHA-256
  исходного `bundle.json`, GTE-журнала и индекса окон;
- однозначность FT4-сигнатур, включая отказ на дублирующихся
  исходно-подобных полигонах;
- **два** отдельных FT4-пакета с проверкой исходного относительного
  порядка AddPrim по глубине OT и отказ при его перестановке;
- соответствие исходных текстурных слов и CLUT значениям VRAM
  непосредственно перед тем GPU-примитивом, которому они принадлежат;
- приватную публикацию манифеста с правами 0600, защитой от перезаписи,
  проверкой полного SHA-256 дерева файлов окон и отказом после
  изменения даже последнего VRAM-снимка.

В тестовом наборе проверка скомпилированного исходного GTE
**подменена тестовым результатом**; настоящих игровых данных нет.
В рабочем инструменте эта проверка вызывается обязательно
и не заменяется тестовой заглушкой. Зеленый CI подтверждает
согласованность и защиту программного механизма, не подлинность
MAP02, не все игровые команды за пределами окон и не физическую
точность PlayStation.

## Один DrawOTag — глобальные примитивы и PutPixel/BlendG1/VRAM

Добавлена новая **структурная** проверка
`tools.verify_map02_window_scoped_join`. Она связывает два
ограниченных окна нативного GPU-снимка с отдельными приватными
журналами **того же запуска** оригинального PC-порта:

- `putpixel-native-events.pending.jsonl` — выбранный пиксель;
- `blendg1-native-events.pending.jsonl` — фактические вызовы
  BlendG1 этого пикселя;
- `vram-edges-native-events.pending.jsonl` — слова VRAM до/после
  **каждого рисующего примитива**, включая операции, которые не
  затронули выбранный пиксель.

Оконный каталог и каталог scoped-наблюдателя должны быть
**разными** пустыми приватными каталогами с разрешениями `0700`;
смешанные и посторонние файлы отклоняются. Примитивы нумеруются
глобально от 0 до N−1 только среди F4/FT4/SPRT/TILE,
включая переход от `window-000` к `window-001`.
`DR_MODE` и отдельные операции переноса VRAM не создают
рисующих порядковых номеров.

```sh
python3 -m tools.verify_map02_window_scoped_join \
  /private/map02/native-windows /private/map02/scoped \
  --frame <real-gpu-draw-frame>

# При наличии предварительно опубликованного и проверенного
# источниково-привязанного манифеста окон:
python3 -m tools.verify_map02_window_scoped_join \
  /private/map02/native-windows /private/map02/scoped \
  --frame <real-gpu-draw-frame> \
  --source-bundle /private/map02/source-bundle
```

Перед сопоставлением повторно запускается полная проверка
каждого окна, SHA-256 всех записанных файлов и непрерывности
полных VRAM-снимков. Затем проверяется **каждая** записанная
граница примитива: её тип и глобальный ordinal должны
совпадать с командой в окне GPU, а независимо прочитанные
16-битные слова из полного снимка VRAM — со значениями
до и после из scoped-наблюдателя.

Это отдельно проверяет согласованность PutPixel/BlendG1 и
неизменённые примитивы, для которых вообще не было вызовов
PutPixel в выбранных X/Y. Даже согласованная подмена всех
трёх scoped-журналов обнаруживается, если она противоречит
нативному снимку VRAM. Слишком длинная запись PutPixel
(лимит 63 событий) и 8192 граничных примитивов по-прежнему
приводят к отказу, а не к потере поздних записей.

`--source-bundle` — дополнительный строгий барьер:
он требует **уже опубликованного** и повторно верифицированного
SHA-256-манифеста источниковой MAP02/GTE-привязки окон.
Без него результат содержит
`source_gte_subsequence_verified=false`.
Этот ограниченный наблюдатель не доказывает покрытия всех
координат, аппаратной PS1-точности или происхождения
оригинального игрового кадра. HD-подмена остаётся выключенной.

### Проверка настоящего программного GPU

`tools.check_map02_joint_window_scoped_runtime` компилирует
**одни и те же реальные исходники** `libgpu.c` и
`pc_raster.c` с независимыми генераторами обоих типов
наблюдения, затем исполняет их в одном процессе. В 34
синтетических рисующих операциях первые 32 не касаются
выбранной координаты, а последние F4 и FT4 рисуют её
после перехода в `window-001`. Это проверяет как глобальные
ordinals 0–33, так и отсутствие ложных выбранных пикселей
при 32 незатрагивающих рисованиях.

### Проверенный этап — общий оригинальный DrawOTag

[GitHub Actions, 106 успешных тестов](https://github.com/stanmasked/vandal-hearts-switch-remaster/actions/runs/39023758976)
для коммита `5c080fb9` подтвердил:

- одновременную инструментализацию настоящих `libgpu.c` и
  `pc_raster.c` двумя независимыми генераторами;
- исполнение 34 рисующих примитивов: 32 незатрагивающих выбранный
  пиксель F4, затем F4/FT4 после границы `window-000` и
  `window-001`;
- совпадение глобальных ordinal с реальными GPU-снимками,
  выбранным PutPixel, BlendG1 и 34 напрямую снятыми границами VRAM;
- отрицательные проверки, где совместно подменённые selected-pixel
  свидетельства отвергаются по независимым **полным** VRAM-снимкам;
- повторную проверку приватных трёх JSONL-журналов и полного
  SHA-256 дерева GPU-окон **после** сопоставления;
- отсутствие ложного подтверждения `source_gte_subsequence_verified`
  без дополнительного проверенного приватного источника.

Графические данные в CI синтетические; настоящий игровой MAP02,
физический PS1 GPU и полный игровой кадр по-прежнему не
подтверждены. Не включать HD-подмену до независимой проверки.
