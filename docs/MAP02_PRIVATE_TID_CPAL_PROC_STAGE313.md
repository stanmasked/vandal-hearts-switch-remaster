# MAP02 Stage313 — live private Linux TID bridge to CPAL/ALSA TLS alias

**Experiment only; Draft / DO NOT MERGE.** This is a child of [Stage312 PR #428](https://github.com/stanmasked/vandal-hearts-switch-remaster/pull/428), [successful real 21/22ms Actions #39598206476](https://github.com/stanmasked/vandal-hearts-switch-remaster/actions/runs/39598206476).

## Reason for a new experiment

Stage312's unprivileged anonymous `/proc` Linux task aliases are a different namespace from the anonymous CPAL/ALSA `__thread` aliases registered in the successful Stage310/311 C shim. At 21ms a sample of a name-hinted audio task was observed sleeping in coarse `poll` in all **93/93** guest-window task snapshots, with zero CPU tick growth, while the generated guest CPAL callback P/L counter had **0** *post-input* increments. It cannot be called the CPAL thread without an exact same-process identity join. The original Stage312 raw **CPAL marker source actually shows one pre-input callback marker at 21ms**, making the missing link experimentally testable without assuming callback activity during the later silent interval. This pre-input event by itself does NOT prove the callback thread must keep running or that any sleep is wrong.

## Exact private identity bridge

Only the **new research-only ALSA `LD_PRELOAD` shim** is modified. It preserves all Stage311 13 exported PCM function begin/end/error counters and the Stage308 CPAL marker, with their previous private mmap schema and offsets. Appended 64 × 8-byte private kernel task identity slots begin at mmap offset **53760** (within the original bounded 65536-byte map). When a new anonymous C `__thread` ALSA/CPAL alias is **first assigned**, the shim performs **one** `syscall(SYS_gettid)` and atomically writes that raw native TID to its pre-existing **private** memory map. It does NOT collect process paths or stack traces, log the TID or execute a kernel call for subsequent callbacks on the same native thread.

**Important intrusive difference:** The one-time syscall can occur on the first CPAL realtime callback and can affect the first scheduling decision. This is a *new* instrumented run and does not have the same scheduling behavior as Stage312. A present early callback and blocked-looking task do not by themselves establish a scheduler bug or a production fix.

A separate unprivileged Python observer starts on the live NeXium process before input. It reuses the unchanged Stage302 task sampler (anonymous identity based on private `(tid,starttime)` source), samples `/proc` state, CPU ticks and allowlisted coarse `wchan` wait categories every ~250ms, and reads the private mmap only in its own process. Raw TIDs are used **only in RAM** to match the Linux task to the Stage308 TLS alias. The two emitted CSV files are: original seven-column `linux-task-state-samples.csv` and a newly anonymized `linux-task-private-tls-join-anonymous.csv` with exactly `sample, observed_ns, anonymous_proc_task_alias, anonymous_tls_alias, cpal_tag_cumulative`. **Neither source CSV records native PID/TID, original thread names, actual wait symbols, process paths or pointers; the original private mmap is NEVER uploaded.**

## Fail-closed source audit

Two independent GitHub Actions jobs request Pulse hints 21ms and 22ms, reusing the verified Stage309 compiled new host ELF SHA-256 `e5ddfc61ac9435dc5a6e2dcd569766db0c444bbdeef8a3fa6a65c9c2e9fc6f25` and unchanged generated ROM-free NRO SHA-256 `371c9fd9f1f41ad87cbb5f7f96a3e5e9d56878f8cfff2bf7fea2c17120c2611b`. The source-only Stage313 auditor **first replays all of Stage312**: host and guest exact SHA checks, original CPAL callback tag/P/L telemetry, Stage311 ALSA exported begin/return phases, original Stage302 anonymized `/proc` source. Then it validates one and only one join row per observed `/proc` task sample; the same TLS alias must never be assigned to two different native task aliases in that run. The CPAL counters must not regress, and any joined CPAL marker must have an audited original later CPAL source sample with at least that value. No exact identity is guessed from thread name or accidental alias numeric equality.

The verified joined result for **any** early pre-input CPAL marker can report its *true anonymous Linux task alias*, CPU tick growth, task state and coarse wait histogram *during the guest window* even when there were no subsequent callbacks. It does NOT establish which events should have awakened that thread, the exact blocked syscall, a permanent deadlock, a causal latency threshold, licensed PS1 game ROM/music fidelity, a completed remake, or physical Nintendo Switch DAC output. If the extra first-use syscall changes the 21ms behavior or causes zero observable early markers, the auditor reports exactly that without forcing a particular result.

Existing `main`, original ELF/NRO, Stage312 C shim, game implementation, NeXium upstream and any licensed game assets remain unchanged. New files are research-only in a stacked Draft PR; no merge.
