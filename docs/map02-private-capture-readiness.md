# MAP02 private real-capture readiness preflight

This **read-only** preflight runs **before** the source-keyed
MAP02 GTE/DrawOTag/VRAM verification and the staged PutPixel/BlendG1
and independent VRAM-edge witness publishers. It does not create,
change or upload original game files, hash manifests or capture logs.

## Read-only original-disc sector integrity gate (before runtime capture)

Before launching the instrumented original-PC executable, validate the
locally owned **raw 2352-byte, single data-track US image** against the
pinned upstream `CDF_M_MAP02_PRS` sector extent:

```sh
python3 -m tools.check_map02_owned_disc_extent \
  /private/owned-original/track-01.bin \
  --upstream-checkout /private/pinned-original-pc-port
```

The tool reads the pinned source's sector table, checks the source US boot
marker, and validates all twelve `M_MAP02.PRS` resource sectors for
synchronization, BCD sector address, Mode 2 Form 1, duplicate XA
subheaders, and each sector's **stored 32-bit CD-XA EDC**. EDC is also
checked for the boot sector. Only sector counts and hashes are returned;
no original game bytes, raw sectors, executable paths, or images are
printed or uploaded. The raw image must be owner-private.

**Important:** This gate assumes the pinned US CD layout, including
`M_MAP02.PRS` at LBA `0x1bcc` for 12 sectors. It must not be applied as
proof that a translated, Japanese, multitrack, or otherwise rearranged
release matches the US PC-port layout. For split archives, assemble and
verify the user's own data track *privately* before invoking the audit;
do not feed a compressed `.zip.001` volume to the sector reader.

A successful Form 1 EDC verifies sector-level integrity only, not
authentic retail provenance. It does not check PS1 ECC parity, certify a
byte-exact US executable, prove an original `CdRead` occurred, or
establish any GPU-frame/pixel equivalence. A separate pinned-executable
and live same-session capture are still mandatory.

## Local invocation

With independently captured, private source and native GPU directories:

```sh
python3 -m tools.check_map02_private_capture_ready \
  /private/map02/source-bundle /private/map02/native-capture
```

The two directories must already exist, not be symlinks, and have
owner-only permission (typically `0700`). Do not upload them to
GitHub or copy their contents into CI logs.

This checks, without doing a complete expensive compiled-GTE verification:

- original MAP02 source bundle schema, pinned PC source revision, source
  frame, decoded-map/VRAM/GTE event SHA-256 digests;
- independently supplied PutPixel/OT and original native-overdraw
  manifest SHA-256 links, and matching source/GPU frame labels;
- full recorded native GPU event pairs with valid before/after metadata,
  strict JSONL framing and a refusal at the existing **64-event
  truncation limit**;
- mandatory `gpu-native-capture-status.json` generated by the instrumented
  PC-port recorder: exact reconciliation of observed/recorded hooks,
  DRAW-versus-transfer counts, successful end of the original OT walk,
  and explicit exclusion of any record that reached the capture limit;
- canonical, bounded private **pending** PutPixel, BlendG1 and
  directly observed DrawOTag VRAM-edge JSONL, including cross-stream
  frame/coordinate/primitive consistency;
- equality of the count of recorded native GPU **draw pairs** and
  separately observed DrawOTag VRAM edges;
- selected-pixel `before` and `after` words for every draw,
  read independently from the real 1024×512×16-bit native VRAM
  snapshots (without printing or saving raw pixels).

The output is a small aggregate-only readiness report. A passing
preflight asserts **structural integrity only** and explicitly reports
that actual original game origin, complete GPU-frame coverage,
compiled-GTE correctness and PS1 physical GPU behavior remain unproven.
Even a synthetic local fixture can pass.

## Important bounded-recorder blocker

The current source-authenticating native GPU event recorder allows
**64 events**, which is at most **32 before/after pairs**, and its
source FT4 evidence capture admits up to **32 submitted faces**. The
new independent DrawOTag VRAM-edge recorder, however, can retain
up to **8192** draw primitives. That asymmetry means simply enabling
all three probes is **not sufficient** to prove the complete original
MAP02 scene: a full scene exceeding the smaller native recorder
capacity must be rejected or safely captured in smaller
source-keyed windows. The preflight rejects the 64-event cap as
potential truncation and rejects draw-count disagreement, rather
than silently marking missing primitives as verified.

Do **not** increase event limits blindly without also adjusting the
full-VRAM snapshot recorder, manifest formats, source-keyed matching,
memory/disk budgets and explicit truncation detection. No genuine
MAP02 capture has been authenticated yet.

## After preflight

Once actual independent inputs exist and preflight succeeds, run the
full private verification chain (which compiles and validates the
original PC GTE/reference geometry, AddPrim OT order and exact native
VRAM snapshots):

```sh
python3 -m tools.promote_map02_putpixel_stage \
  /private/map02/source-bundle /private/map02/native-capture
python3 -m tools.publish_map02_blendg1_witness \
  /private/map02/source-bundle /private/map02/native-capture
python3 -m tools.publish_map02_vram_edges_witness \
  /private/map02/source-bundle /private/map02/native-capture
python3 -m tools.verify_map02_vram_edges_witness \
  /private/map02/source-bundle /private/map02/native-capture
```

A passing hash chain is still not evidence of actual retail game
provenance or physical PlayStation pixel equivalence. HD replacement
remains disabled pending independent real MAP02 verification.


## Verified integration checkpoint (17 October 2026)

The [readiness test run](https://github.com/stanmasked/vandal-hearts-switch-remaster/actions/runs/38991048927)
at commit \`e8fb5e8d\` completed successfully:

- **66/66 Python/C regressions**, including synthetic positive
  read-only readiness and negative missing/linked VRAM snapshots,
  transfer snapshot and upload file omission, incorrect source frame,
  incomplete pending JSONL, broken SHA-256, source FT4 count exceeding
  native draw-pair count and public-permission directories;
- actual pinned original-PC \`libgpu.c\` / \`pc_raster.c\` compilation
  and relocatable-link of all three GPU diagnostic variants;
- original raster and DrawOTag execution with the baseline and
  complex transparent/overdraw synthetic scenarios.

The current preflight is intentionally strict: all referenced native
snapshot names, including load/move/clear pairs, must resolve to regular
full-size VRAM files. Any explicitly staged bounded upload must also
be present with its declared rectangle extent. The gate reads only
two bytes at the chosen coordinate from each full-size VRAM snapshot,
not entire raw frames (except for the two separately SHA-checked
original source-bundle files).

**The test's game data are synthetic.** Success here does not claim
a retail MAP02 capture, physical console accuracy or authenticated
full-frame coverage; those all remain outstanding.

## Tested original PC-port recorder

The [real native GPU recorder run](https://github.com/stanmasked/vandal-hearts-switch-remaster/actions/runs/39020415897)
successfully compiled and executed the pinned original `libgpu.c` and
`pc_raster.c` with asset-free OT input, verifying:

- `DR_MODE` does not create a drawing snapshot;
- a two-draw OT creates four native events and a balanced closing receipt;
- a deliberately overfull 34-draw OT attempts 68 events, writes at most
  64 snapshots, reports the extra four callbacks and **fails** the receipt
  verifier rather than silently accepting the truncated prefix.

The completion receipt is a self-report by the source-instrumented
emulator, and cannot authenticate original retail gameplay, completeness
outside the observed frame window, or physical PlayStation hardware.

New private capture sessions must use an empty owner-only directory so
that existing snapshots and receipts cannot silently mix across runs.
