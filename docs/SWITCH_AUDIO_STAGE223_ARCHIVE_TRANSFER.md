# Vandal Hearts Remake — этап №223: архивная передача аппаратных доказательств

> **`HARDWARE NOT TESTED`:** это инструкции для переноса **первичных** NRO, CSV и операторских карточек, а не результаты испытания на физической Nintendo Switch. Ни GitHub Actions, ни SHA-256, ни удачная распаковка не доказывают качество звучания и независимость реальных запусков.

## Что добавлено

[Инструмент `archive_switch_audio_handoff.py`](../tools/archive_switch_audio_handoff.py) создаёт переносимый ZIP **только** из файлов, которые уже проверяются [аудитом №222](SWITCH_AUDIO_STAGE222_HARDWARE_HANDOFF.md). ZIP содержит:

- исходный `bundle/audio-evidence-manifest.json` (неподписанный манифест);
- **точно** указанный в нём `bundle/nro/*.nro` и зарегистрированные `bundle/.../*.csv`;
- отдельный `operator.json` с исходными заявлениями испытателя;
- отдельные `cards/*.json` для существующих карточек сессий;
- `archive-index.json` — индекс точных относительных имён, размеров, SHA-256 каждого файла, полного Git SHA, исходного результата аудита и флагов H06/H07.

Оригиналы **только читаются**. На машине-источнике ZIP записывается во временный файл, полностью проверяется отдельным повторным чтением и публикуется без перезаписи уже существующего пути. В архив не добавляются посторонние JSON, скриншоты, личные файлы или результаты внешних утилит. Их можно передавать отдельно после проверки приватности.

## На первом компьютере: сформировать ZIP

Пусть реальный каталог данных соответствует [схеме №222](SWITCH_AUDIO_STAGE222_HARDWARE_HANDOFF.md) — `verified-bundle`, `operator-v2.json`, `session-cards`. Вне исходного каталога выполните:

```sh
python3 tools/archive_switch_audio_handoff.py create \
  hardware-evidence-222/verified-bundle \
  --observations hardware-evidence-222/operator-v2.json \
  --cards-dir hardware-evidence-222/session-cards \
  --output /path/outside-evidence/switch-audio-handoff-223.zip \
  > /path/outside-evidence/archive-create-223.json
```

В ответе `ARCHIVE_CREATED_AND_REVERIFIED` поле `archive_sha256` — SHA-256 **ZIP целиком**, а не только NRO и не ZIP-индекса. **Сохраните эти 64 шестнадцатеричных символа отдельно от ZIP и передайте получателю другим доверенным способом** — например, через согласованный канал связи или ранее проверенный протокол. Запись контрольного хеша рядом с ZIP удобна для инвентаризации, но **не защищает** от одновременной подмены ZIP и хеша.

При отсутствующей карточке архив можно создать, но результат базового аудита будет `INCONCLUSIVE` — он не станет аппаратным `PASS`. Сценарии `--require-h06` и `--compare-builds` можно явно запросить при создании, чтобы зафиксировать неполные дополнительные проверки в ZIP-индексе, но они не засчитываются автоматически.

## На другом компьютере: проверить архив

Скопируйте ZIP **без модификаций**. Возьмите контрольный SHA-256 из **независимого сообщения отправителя**. Выполните:

```sh
python3 tools/archive_switch_audio_handoff.py verify \
  /path/to/received/switch-audio-handoff-223.zip \
  --expected-sha256 ACTUAL_64_HEX_SHA256_FROM_INDEPENDENT_CHANNEL \
  > /path/outside-evidence/archive-verify-223.json
```

Процедура проверяет, что:

1. Переданный ZIP побайтно соответствует независимому SHA-256. При расхождении — `ARCHIVE_SHA256_MISMATCH` и `INVALID_EVIDENCE`, код `2`.
2. В архиве нет небезопасных абсолютных путей, `..`, символических ссылок, повторяющихся имён, скрытых лишних файлов, зашифрованных или неподдерживаемых типов записи.
3. Индекс `archive-index.json` содержит **только** ожидаемые поля и по одному имени на файл. Размеры ограничены: ZIP — до 256 МиБ, один файл — до 128 МиБ, индекс — до 64 КиБ, число элементов — до 150. Проверяются длины и SHA-256 **каждого** внутреннего файла.
4. Для окончательного подтверждения байтов программа распаковывает только разрешённые элементы в **изолированную временную папку** (не на SD, не в папку исходника), после чего **заново** запускает аудит №222, в том числе строгий разбор NRO/CSV и сверку ручных карточек.
5. Повторно вычисленный Git SHA из манифеста и результат аудита совпадают с записанными в ZIP-индексе. В случае несогласованности архив не считается проверенным.

Успешный результат `ARCHIVE_BYTES_AND_EVIDENCE_REVERIFIED` означает только совпадение переносимого набора файлов с независимо сохранённым хешем и повторную проверку внутренней согласованности. `handoff_review` может быть `INVESTIGATE`, `INCONCLUSIVE` или `READY_FOR_INDEPENDENT_MANUAL_REVIEW` — **даже при успешно перенесённом ZIP**. Код `0` говорит только об успешной проверке архива, **не** о положительной аппаратной приёмке.

## Ограничения и безопасное использование

- **Не доверяйте самоподписанному списку хешей как подтверждению происхождения.** Если злоумышленник изменит архив и передаст новый контрольный хеш по тому же недоверенному каналу, SHA-256 не докажет оригинальность. Нужен отдельно сохранённый SHA-256 либо криптографическая подпись/независимое внешнее заверение.
- Архиватор не получает сами артефакты из GitHub. Проверку GitHub run/артефакта/NRO выполняйте отдельно по [этапам №216–218](SWITCH_AUDIO_STAGE214_DEVICE_HANDOFF.md), фиксируя фактически испытанную сборку.
- Карточки запусков и свидетельства H05 по-прежнему **самозаявленные**. Хронология, реальные пробуждения HOME/сон, отсутствие слышимых дефектов и сохранность старого CSV после перезапуска должны быть подтверждены независимым испытателем на физической консоли.
- Если перенос выполняется на чужом компьютере, учитывайте, что NRO/CSV и записи оператора могут содержать чувствительные сведения. ZIP **не шифруется**. Для безопасной передачи используйте отдельный защищённый канал, а не публичный репозиторий.
- Оригинальные CSV **не редактируйте** ради прохождения теста. При повреждении оставьте оригинал и передайте его отдельно для расследования.

## Тестирование

[Host-only регрессии](../tests/test_archive_switch_audio_handoff.py) охватывают успешное копирование, потерю независимого хеша, усечённый ZIP, подменённые CSV/операторские JSON, неправомерные пути, символьные ссылки, лишние/отсутствующие/дублированные файлы, несовпадение индекса, невозможность перезаписи архива, read-only исходники, неполные карточки и необязательные H06/H07. Тесты включены в `make test` и `make test-audio-stream`; они не работают с реальной Switch.
