# MAP02 — наблюдаемые причины пропуска пикселя в оригинальном растеризаторе

Этот этап продолжает
[синхронную привязку DrawOTag → PutPixel](MAP02_PUTPIXEL_DRAWOTAG_CORRELATION.md),
но фиксирует **конкретные исполненные ветки** исходного
`platform/pc/src/pc_raster.c` публичного PC-порта.

Два диагностических инструмента:
`tools/instrument_map02_raster_skips.py` и
`tools/verify_map02_raster_skips.py`.
Генератор принимает только **два закреплённых оригинальных Git-блоба**
из коммита PC-порта
`14552fffa0e0b47e02b57592e274fc6e7a649923`.
Он создаёт отдельные `libgpu.skip.c` и `pc_raster.skip.c`,
не изменяя исходные файлы или обычный рендерер.

## Четыре наблюдаемые причины

| Код | Оригинальная ветка | Что доказано |
|---|---|---|
| 1 | DDA: `if (draw)` → `else` | Для конкретного адреса и примитива выбранный 16-битный текстурный цвет был равен нулю; `PutPixel` на этом шаге не вызван |
| 2 | DDA: исходный half-open span `[x_start, x_bound)` против `clipL/clipR` | Выбранный X входил в горизонтальный диапазон DDA-строки, но находился за пределами горизонтальной области рисования |
| 3 | Резервный barycentric: `if (texel == 0) continue` | Выполнен непосредственный пропуск из-за нулевого текстурного цвета |
| 4 | DDA: восходящая/нисходящая строка вне `clipT/clipB`, при выбранном X внутри half-open интервала строки | Наблюдалось вертикальное отсечение конкретного DDA-span; не доказано окончательное покрытие треугольником |

Это именно **BGR555-цвет после выборки текстуры**, а не
безусловно нулевой четырёхбитный индекс палитры.
Каждое событие получает номер GPU-кадра,
`primitive_ordinal`, тип примитива, точные координаты
**одного заранее выбранного слова VRAM** и код причины.

**Ни горизонтальный код 2, ни вертикальный код 4 не доказывают
покрытия всей FT4.** Проверяется горизонтальный интервал
конкретной DDA-строки; точное покрытие
по треугольнику, ABR/STP и операция GPU-mask остаются
отдельными вопросами.

## Генерация и локальная сборка

Из корня репозитория ремейка:

```sh
python3 -m tools.instrument_map02_raster_skips \
  /private/VandalHearts-PcPort/platform/pc/src/libgpu.c \
  /private/VandalHearts-PcPort/platform/pc/src/pc_raster.c \
  --output-dir /private/map02-raster-skip-build
```

Используйте `libgpu.skip.c` и `pc_raster.skip.c` вместо двух
обычных файлов локальной сборки PC-порта. Все три
флага компиляции обязательны:

```text
-DVH_MAP02_GPU_CAPTURE
-DVH_MAP02_PUTPIXEL_SCOPE
-DVH_MAP02_RASTER_SKIP_TRACE
```

Настройка локальной инструментированной игровой сессии:

```sh
export VH_MAP02_GPU_CAPTURE_DIR=/private/map02-native-capture
export VH_MAP02_GPU_CAPTURE_FRAME=12
export VH_MAP02_PUTPIXEL_DIR=/private/map02-native-capture
export VH_MAP02_PUTPIXEL_FRAME=12
export VH_MAP02_PUTPIXEL_X=30
export VH_MAP02_PUTPIXEL_Y=30
```

Все каталоги должны существовать. Номера и координаты
в этом примере **не получены из подлинной игры**.

В одном процессе формируются ранее описанные файлы
`gpu-native-events.jsonl`, `gpu-NNNN-vram.bin`,
необязательный `putpixel-native-events.jsonl` и новый
`putpixel-native-skips.jsonl`. Журнал вызовов `PutPixel`
может **отсутствовать**, если в наблюдаемой точке были
только пропуски; это не ошибка диагностической цепочки.
Все исходные игровые данные остаются приватными.

Лимит **64 события каждого типа**, а регистрация
после исчерпания лимита прекращается. Валидатор
не принимает заполненный до предела журнал пропусков
как доказательство полноты.

## Манифест и проверка

Создайте `gpu-raster-skips.json` в локальной приватной папке
исходного MAP02-комплекта:

```json
{
  "schema": "vh.map02.native-raster-skip.v1",
  "source_frame": 411,
  "gpu_draw_frame": 12,
  "overdraw_manifest_sha256": "<sha256 gpu-native-overdraw.json>",
  "native_events_sha256": "<sha256 gpu-native-events.jsonl>",
  "raster_skip_events_sha256": "<sha256 putpixel-native-skips.jsonl>"
}
```

Примерные номера выше не удостоверяют происхождение
кадра. SHA-256 следует вычислять из точных байтов локальных
файлов; этот хеш гарантирует **целостность предоставленных данных**,
а не их подлинность.

Запуск из корня ремейка:

```sh
python3 -m tools.verify_map02_raster_skips \
  /private/map02-source /private/map02-native-capture \
  > /private/map02-raster-skips-report.json
```

Проверка заново проходит всю предшествующую последовательность:
декодированная структура MAP02, оригинальные грани, GTE,
`FT4` и `CLUT`, снимки VRAM и порядок OTZ/LIFO.
После этого каждый пропуск проверяется по реальному
порядку **каждого не-bucket примитива в DrawOTag**,
номеру кадра, типу пакета, координатам и непосредственно
исполненной ветке. Для двух случаев нулевого текселя
отклоняются пакеты, которые вообще не используют текстуры.

Отчёт содержит только хеши и агрегированные количества
каждого основания, включая события, привязанные к
конкретным исходным граням MAP02. Сырые координаты,
значения цветов и игровые текстуры не выводятся.

## Ограничения

Отсутствие события не означает, что пиксель должен
был быть записан. Возможны другие причины, в том числе
высота и границы треугольника, drawing offset,
поздние эффекты и отсутствие записи из-за проверки маски.

Нулевой цвет может быть получен из содержимого палитры,
поэтому это не всегда доказательство индексного нуля.
События не удостоверяют точность физического PS1 GPU,
режимов STP/ABR и аппаратного mask-test.

В CI выполняются **только синтетические тесты**
и компиляция публичных исходников PC-порта
с диагностическими макросами и без них. Ни реального
игрового кадра Vandal Hearts, ни его аппаратного
отображения на Nintendo Switch этот этап не предъявляет.
