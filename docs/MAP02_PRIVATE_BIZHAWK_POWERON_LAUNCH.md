# MAP02 — приватный запуск EmuHawk с BK2 и Lua

Этот этап устраняет необходимость вручную начинать просмотр фильма и
подключать скрипт в правильный момент. Запуск выполняется только
локально на компьютере владельца, вне GitHub Actions.

## Требования

Установлены совместимый BizHawk/EmuHawk, ядро PSX Octoshock и
оригинальная локальная PS1 BIOS. Исходный BK2, образ диска, план
кадров и будущие изображения хранятся вне Git-репозитория.
Само наличие системы PSX не подтверждает использование Octoshock:
выбор ядра нужно проверить в настоящем EmuHawk.

Сначала создайте приватный план из ранее найденного BK2:

    umask 077
    python3 -m tools.map02_private_bk2_capture_plan \
      /private/vandalhearts.bk2 \
      --private-plan-output /private/vh-map02-review-plan.txt \
      --max-windows 4

Создайте новую пустую папку для PNG. На Linux/macOS явно задайте права
каталога: локальный запускатель откажется работать с правами шире `0700`.:

    mkdir -p /private/vh-map02-run1-png
    chmod 700 /private/vh-map02-run1-png

## Проверка без запуска

    python3 -m tools.map02_private_bizhawk_poweron_launch \
      /absolute/path/to/EmuHawkMono.sh \
      /private/Vandal_Hearts.cue \
      /private/vandalhearts.bk2 \
      /private/vh-map02-review-plan.txt \
      /private/vh-map02-run1-png

На Windows используйте абсолютный путь к EmuHawk.exe. Все пути —
только условные примеры, не реальные данные владельца.

По умолчанию команда НЕ запускает эмулятор. Она открывает исходный
приватный BK2, проверяет агрегаты записи, заново рассчитывает
предполагаемый план кадров и требует точного совпадения с файлом
плана. Она также отклоняет приватные файлы в Git-дереве, отсутствующие
пути, символические ссылки и существующие целевые PNG. Консоль
показывает только обезличенный статус.

## Дополнительная проверка полного образа (рекомендуется)

Если известна контрольная сумма ранее проверенной личной копии BIN,
поместите её в отдельный файл вне Git и задайте файлу режим `0600`
на Linux/macOS. Добавьте к команде локальной проверки или запуска:

    --private-full-bin-sha256-file /private/vh-full-bin.sha256

Это запрашивает потоковое сравнение SHA-256 всех байтов BIN с
приватной контрольной суммой **до** подготовки плана и запуска процесса
EmuHawk. При несовпадении запуск блокируется, а хеш не печатается.
Режим требует времени для чтения полного файла (примерно 665 МБ);
без указанного параметра сохраняется только быстрая структурная проверка.
Хеш из приватного файла удостоверяет ранее проверенную локальную копию,
но не доказывает подлинность игры или совместимость BK2 с русской версией.

## Запуск

Добавьте --launch в конец той же команды. Это создаст процесс
EmuHawk напрямую, без оболочки. В аргументах используются
официальные ключи BizHawk --movie= и --lua=, затем последним
аргументом идёт путь к исходному образу PS1.

Файл Lua выбирается автоматически из каталога tools текущей
установки проекта. Переменные окружения VH_PRIVATE_CAPTURE_PLAN,
VH_PRIVATE_PNG_DIR, VH_PRIVATE_CAPTURE_LOG и VH_PRIVATE_PROCESS_LOG
задаются автоматически.

Внутри скрипта проверяются система PSX, непрерывный счётчик кадров,
read-only PLAY, первое нажатие Start на индексах BK2 1660–1661
и наличие запланированных PNG. Если текущий EmuHawk загрузил Lua
не в момент начала фильма, скрипт откажет: это правильное поведение,
а не подтверждение неисправности BK2.

Перед запуском программа эксклюзивно создаёт два приватных файла
с режимом `0600` на Unix: `vh_private_capture.log` и
`vh_emuhawk_process.log`. При ошибке Lua закрывает структурированный
журнал и, если API доступен, немедленно завершает EmuHawk с кодом 1,
чтобы не проигрывать оставшуюся часть длинного BK2. Если API завершения
отсутствует, ошибка фиксируется до начала захвата; эмулятор может
потребовать ручного закрытия. Первый — структурированный журнал Lua:
строки Start-зонда, захвата, завершения и ошибок записываются и в Lua
Console, и в файл. Он не содержит абсолютных путей, сырых данных кнопок
или хешей снимков. Второй — stdout/stderr EmuHawk. Это важно, потому что
BizHawk выводит переданные аргументы командной строки в stderr; в
диагностическом журнале могут встречаться приватные пути. Оба файла
остаются локальными и не должны отправляться в GitHub или пересылаться
вместе с публичными отчётами. Если EmuHawk завершится до запуска Lua,
структурированный журнал может остаться неполным — аудит должен
отклонить такую запись.

После последнего запланированного снимка Lua вызывает документированный
BizHawk API `client.exitCode(0)`: EmuHawk закрывается, не проигрывая
оставшиеся сотни тысяч кадров фильма, а локальный запускатель записывает
маркер завершения процесса.

Аудитор также требует ровно один маркер `VH_PRIVATE_BIZHAWK_LOCAL_PROCESS_EXITED`
с `exit_success=1`, расположенный после маркера полного завершения Lua.
Отсутствующий маркер, ненулевой код процесса, ошибка запуска или маркер
до завершения захвата отклоняют запись. Если установленная версия BizHawk
не предоставляет `client.exitCode`, Lua-зонд отказывает до захвата. Это
подтверждает лишь успешный выход процесса EmuHawk, но не аутентичность
диска/BIOS, ядро Octoshock, доставку ввода, идентичность MAP02 или
совпадение GPU/VRAM.

Проверьте цепочку исходный BK2 → план → журнал → PNG локально:

    python3 -m tools.verify_map02_private_neutral_capture_chain \
      /private/vandalhearts.bk2 \
      /private/vh-map02-review-plan.txt \
      /private/vh-map02-run1-png/vh_private_capture.log \
      /private/vh-map02-run1-png

Затем вручную проверьте приватные снимки/контактный лист. Используйте
новую папку при повторном запуске. Код возврата процесса 0 сам по себе
НЕ доказывает наличия снимков или корректного воспроизведения.

## Два независимых локальных захвата

Для второй попытки обязательно закройте EmuHawk и запустите его заново
с тем же CUE/BIN, BK2, Lua и планом, но с **другим пустым каталогом**.
План и оригинальный BK2 не изменяйте. На Linux/macOS:

    mkdir -p /private/vh-map02-run2-png
    chmod 700 /private/vh-map02-run2-png

Повторите команду запуска из предыдущего раздела, заменив только путь
к каталогу PNG на `/private/vh-map02-run2-png`. После завершения обеих
попыток выполните полностью локальный аудит:

    python3 -m tools.map02_private_two_capture_audit \
      /private/vandalhearts.bk2 \
      /private/vh-map02-review-plan.txt \
      /private/vh-map02-run1-png \
      /private/vh-map02-run2-png

Аудитор **отдельно** проверяет обе цепочки BK2 → план → журнал → PNG,
требует разные каталоги и файлы-снимки, затем сравнивает байты PNG для
одинаковых индексов кадров. На экран выводятся только количества
совпадений и расхождений, без исходных путей, хешей или изображений.
Код выхода `0` означает отсутствие байтовых расхождений в проверенных
файлах; код `2` означает, что один или более PNG имеют разные байты и
требуют локального просмотра. Различие байтов может быть следствием
кодирования или метаданных PNG, а не пикселей. Сходство байтов тоже
не удостоверяет два независимых холодных старта, исходное ядро,
идентичность MAP02, синхронизацию ввода/кадра или GPU-эквивалентность.

Результаты нельзя выдавать за подтверждение сцены без независимой
визуальной проверки. Папки, журналы и снимки остаются только у владельца.

В официальном BizHawk README документированы аргументы командной
строки, а командный парсер содержит отдельные --movie и --lua.
Данный CI только проверяет построение аргументов и приватность;
он не содержит оригинальную игру, Octoshock или BIOS и никогда
не запускает настоящий EmuHawk.

Исходный BK2, личные образы игры/BIOS, планы кадров, реальные
PNG, журналы и локальные результаты анализа НЕ публикуются.
Начало MAP02, видеозадержка кадров и GPU/VRAM остаются неустановленными.

## Дополнительная проверка приватности плана BK2

Перед разбором архива генератор плана теперь требует абсолютный обычный
файл BK2, не символическую ссылку, и проверяет все разрешённые
родительские каталоги на Git checkout/worktree. Проверка выходного
каталога плана выполняется **до чтения BK2**; путь каталога разрешается
в реальный путь, и генератор отказывается создавать план внутри Git,
в том числе когда исходный путь к папке был символической ссылкой.
Тесты используют только вымышленные файлы и не содержат настоящего BK2.
