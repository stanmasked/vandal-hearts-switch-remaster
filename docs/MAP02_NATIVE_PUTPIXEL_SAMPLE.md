# MAP02 — локальное наблюдение действительных вызовов PutPixel

В проект добавлены два диагностических инструмента:

- `tools/instrument_map02_native_putpixel.py` создаёт отдельную,
  опционально инструментированную копию **закреплённого исходного**
  `platform/pc/src/pc_raster.c` публичного PC-порта.
- `tools/verify_map02_native_putpixel.py` проверяет ограниченный
  приватный журнал результатов исполняемой функции `WritePixel`
  и создаёт отчёт только из агрегированных счётчиков и SHA-256.

## Зачем это нужно

Предыдущий [анализ наложения](MAP02_NATIVE_OVERDRAW_EVIDENCE.md)
обнаруживал только **изменение значения VRAM** между двумя снимками.
Но оригинальный код может вызвать `WritePixel` с цветом, который
уже записан в VRAM. Вызов состоялся, а в разнице снимков его не видно.

Новый наблюдатель размещён строго вокруг **уже существующего**
`WritePixel(&s_vram[y][x], ...)` в `PutPixel`; он не меняет его
входы или режим смешивания. Логируются:

- выбранные координаты одного слова VRAM;
- значение BGR555 до вызова, переданный цвет и результат после;
- номера последовательных вызовов, ABR (0–3), `semiTrans`,
  `textured` и фактически выбранный PC-режим `VH_ACCURATE`.

Выполняется только **нативный** путь `s_vram`; отдельный
суперсэмплированный `s_hires` не трогается. Для приватности
и производительности ограничение — **64 вызова** одного
конкретного адреса. Если лимит достигнут, полнота
последующего наблюдения неизвестна.

## Генерация и локальная сборка

Имея локальный checkout публичного PC-порта ровно на коммите
`14552fffa0e0b47e02b57592e274fc6e7a649923`:

```sh
python3 -m tools.instrument_map02_native_putpixel \
  /private/VandalHearts-PcPort/platform/pc/src/pc_raster.c \
  --output /private/map02-pixel-probe/pc_raster.sample.c
```

Указанный файл генерируется **без перезаписи исходного**.
В локальной сборке PC-порта компилировать его вместо
обычного `pc_raster.c`, добавив флаг
`-DVH_MAP02_PUTPIXEL_SAMPLE`. Без этого флага диагностический
наблюдатель полностью исключается из объектного файла.

Для выполнения понадобятся законно полученные игровые данные
**локально**, существующий приватный каталог и три переменные:

```sh
export VH_MAP02_PUTPIXEL_DIR=/private/map02-pixel-output
export VH_MAP02_PUTPIXEL_X=32
export VH_MAP02_PUTPIXEL_Y=24
# Запустить свою локальную инструментированную сборку PC-порта.
```

Значения `32` и `24` — иллюстрация, не координаты
достоверной игровой сцены. Координаты должны попадать
в VRAM 1024×512. Без всех трёх переменных или при
неверных координатах журнал не создаётся. Путь к каталогу
обязан быть абсолютным; каталог необходимо создать заранее.

Сохранённый локальный файл:
`putpixel-native-events.jsonl`.

## Проверка журнала

Из корня репозитория:

```sh
python3 -m tools.verify_map02_native_putpixel \
  /private/map02-pixel-output \
  > /private/map02-putpixel-summary.json
```

Аудитор отклоняет повреждённый JSON, дублирующиеся ключи,
пропущенные номера, неправильный BGR555, смену выбранных
координат, слишком большой журнал, символические ссылки
и несовместимый с исходной функцией непрозрачный результат.
В закреплённом `WritePixel` при `semiTrans=0` цвет
**непосредственно копируется**, поэтому `after` должен
строго совпасть с `front`. При `semiTrans=1` теперь
строго проверяется результат **именно исходного PC-кода**
по `tools/map02_pc_writepixel_reference.py`. Для
`accurate=1` эталон воспроизводит `BlendG1` с точной
5-битной арифметикой ABR (0–3) и обработкой бита 15; для
`accurate=0` — отдельную legacy-ветку с усечением и
насыщением цветовых каналов. Некорректный результат
отклоняется даже при пересчитанном журнале.

Исходная функция `AccurateEnabled()` сохраняет свой режим
один раз в статическом состоянии процесса. Поэтому попытка
сменить `accurate` посреди одного журнала отклоняется.
Аудитор публикует лишь число проверенных вызовов для
каждого PC-режима, а не исходные цвета.

В итоговом отчёте есть количество:

- действительных вызовов `PutPixel`;
- непрозрачных копирований и запросов смешивания;
- вызовов, которые оставили **то же значение VRAM**;
- вызовов, изменивших слово и бит 15;
- разрывов преемственности между двумя зафиксированными
  вызовами (например, другая операция меняла слово);
- событий при включённом PC accurate mode.

Сырые цвета и координаты в итоговый отчёт не попадают.

## Важные ограничения

**Этот инструмент фиксирует вызовы, которые реально дошли до
`PutPixel`, но не причины, по которым другие пиксели его
не вызвали.** Пропущенный вызов может быть связан с нулевым
текселем, DDA-покрытием, отсечением или иной логикой.
Следовательно, отсутствие записи **не доказывает**
прозрачность или отклонение GPU-маской.

`semiTrans=1` показывает реальный запрос PC-кода на
смешивание; без отдельного сравнительного исполнения
этот инструмент не доказывает точность ABR по отношению
к физической PlayStation. Закреплённая версия оригинального
публичного PC-порта не равна аппаратному PS1 GPU.

Журнал не содержит доверенной метки номера кадра или
идентификатора конкретного `AddPrim`. Поэтому его нельзя
автоматически приписывать одной грани MAP02 без дополнительной
синхронной привязки к
[журналу GPU](MAP02_NATIVE_GPU_CAPTURE.md).

Проверки GitHub компилируют закреплённый исходный GPU
с включённым и выключенным наблюдателем и запускают
**только синтетические тесты**. Они не запускают оригинальную
игру и не включают пользовательские игровые ресурсы.
