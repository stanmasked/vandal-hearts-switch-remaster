# MAP02 — последовательность снимков VRAM для одного игрового кадра

Инструмент `tools/verify_map02_vram_timeline.py` расширяет
`verify_map02_frame_bundle.py` случаем, когда VRAM может меняться между
отправками полигонов на GPU. Он проверяет **локально предоставленные**
пользователем файлы; не создаёт снимки, не запускает игру и не получает
оригинальные игровые ресурсы самостоятельно.

## Локальные файлы

В приватной папке:

- `map02.decoded.bin` — 187264 байта исходных декодированных клеток MAP02.
- `gpu-events.jsonl` — 1–32 последовательных события нормальных
  полигонов FT4 (поля `source`, `gte`, `texture` из
  [описания формата одного кадра](MAP02_PRIVATE_FRAME_BUNDLE.md)).
  Каждое событие дополнительно содержит
  `"submission_index": 0` и `"vram_snapshot_index": 0` для первой
  отправки, далее оба значения возрастают на единицу.
- `gpu-vram-000.bin`, `gpu-vram-001.bin`, ... —
  **отдельный снимок 1048576 байт** для каждой отправки в том же
  порядке. Файлы привязаны к индексам, имена нельзя задавать из JSON.
- `timeline.json` — контрольные суммы и заявленный номер кадра:

```json
{
  "schema": "vh.map02.vram.timeline.v1",
  "frame": 411,
  "ot_size": 1024,
  "pc_source_commit": "14552fffa0e0b47e02b57592e274fc6e7a649923",
  "decoded_map_sha256": "<64 lowercase hex>",
  "events_sha256": "<64 lowercase hex>",
  "snapshots": [
    {"index": 0, "frame": 411, "sha256": "<64 lowercase hex>"},
    {"index": 1, "frame": 411, "sha256": "<64 lowercase hex>"}
  ]
}
```

Указанные номера — пример, а не данные настоящей игровой сессии.
Допускается необязательный `pc_game_binary_sha256`. Его наличие
не доказывает происхождение исполняемого файла: проверяется только
формат хеша.

Команда из корня репозитория:

```sh
python3 -m tools.verify_map02_vram_timeline /private/map02-timeline \
  > /private/map02-vram-timeline-report.json
```

Контрольные суммы можно получить локально командой `sha256sum`
или `hashlib.sha256`. Не следует публиковать полные `*.bin`,
сырые `gpu-events.jsonl` и полный `timeline.json` в открытом CI:
они могут содержать данные игры.

## Что проверяется

Сначала проверяются длины, SHA-256 и последовательные индексы всех
снимков, отсутствие символических ссылок, номера кадра и хеш
журнала. Затем для **каждой** отправки выполняются прежние проверки
реальной 304-байтовой структуры клетки, локальных координат всех
четырёх вершин, программы GFX, освещения, скомпилированной модели GTE
(`RTPT/NCLIP/RTPS/AVSZ4`), исходного `tpage`, палитры `CLUT`,
texture window и необязательных наблюдаемых 16-битных проб цвета.
Каждое событие проверяется именно по `gpu-vram-NNN.bin` с его индексом.

В агрегированном отчёте отображаются:

- число проверенных снимков и переходов между ними;
- число изменившихся 16-битных слов **во всей VRAM**;
- число слов текстуры и CLUT, изменившихся в адресах,
  используемых **следующим** полигоном;
- число переходов, затронувших данные следующего полигона;
- число проверенных граней, пиксельных выборок и наблюдаемых проб;
- хеши входных файлов и явные флаги ограничений доказательности.

Отчёт не содержит геометрию, координаты камеры, сырые цвета или
байты пользовательских снимков.

## Что этот результат не доказывает

Различие двух снимков **достоверно устанавливает лишь то, что их
содержимое различается**, если они предоставлены без подмены. Оно не
доказывает, какая GPU-команда изменила память и когда именно.
Совпадение двух снимков также **не исключает**, что VRAM была изменена
и затем восстановлена между моментами захвата.

Номера кадров, контрольные суммы и даже полное соответствие
портированной модели GTE не удостоверяют происхождение кадров из
оригинальной игры. Это не PS1-GPU эмуляция и не проверка точности
финального аппаратного растеризатора. До реального графического
доказательства остаются доверенная инструментированная запись GPU,
обработка command ordering/VRAM uploads и визуальное сопоставление
с оригиналом. CI использует исключительно синтетические входы.
