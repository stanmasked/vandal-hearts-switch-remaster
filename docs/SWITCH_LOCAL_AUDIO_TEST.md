# Nintendo Switch — локальная проверка аудио SEQ/VH/VB

**Статус:** диагностическая SDL2-проба, не законченный порт музыкального
движка Vandal Hearts. Пользовательские игровые файлы никогда не входят в
исходники, CI или готовую NRO-сборку.

## Рекомендуемая NRO-проба: штатный libnx audout

Теперь поддерживаются **два диагностических аудиобэкенда**:

- `audout-audio-switch-probe.nro` — собирается только с devkitPro/libnx,
  без SDL2. Музыкальный синтезатор сохраняет точность внутреннего
  тайминга 44 100 Гц; потоковый линейный ресемплер преобразует готовый
  стерео-PCM в 48 000 Гц — частоту устройства `audout`.
- `sdl2-audio-switch-probe.nro` — прежняя SDL2-проба с теми же
  SEQ/VH/VB/SPU и прямым буфером 44 100 Гц. Зависит от установленного
  `switch-sdl2`; загрузка пакета в GitHub Actions может быть недоступна
  из-за ответа сервера зеркала HTTP 403.

Без дополнительных portlibs можно собрать первую пробу:

```sh
make audout-audio-probe
```

Успешный GitHub Actions запуск `Switch libnx audout music NRO`
содержит артефакт `native-audout-music-nro` — проверенный
как NRO-контейнер бинарный файл. Содержимое игры в нём отсутствует.

Выполненные до настоящего времени тесты подтверждают **создание
бинарного NRO**, но ещё не подтверждают слышимый звук или
совместимость с конкретным набором из оригинальной PlayStation.
Для реальной аудиопроверки запускайте пробу на своей Switch
в поддерживаемой homebrew-среде.

## Протокол физической проверки audout / HOME (PR №7)

**Проверка на реальной Nintendo Switch пока не проводилась.** Готовый
`audout-audio-switch-probe.nro` — исследовательская программа для
Homebrew Menu, а не законченная игра. Без пользовательских файлов она
использует самостоятельно созданные синтетические SEQ/VH/VB; игровые
ресурсы не требуются и не входят в сборку.

1. Возьмите артефакт **`native-audout-music-nro`** из
   [проверенной сборки с ZL-инъекцией ошибки таймера и защитой PCM от повторной отправки](https://github.com/stanmasked/vandal-hearts-switch-remaster/actions/runs/39071790824)
   ([артефакт NRO с SHA-256 №12115293510](https://github.com/stanmasked/vandal-hearts-switch-remaster/actions/runs/39071790824/artifacts/12115293510))
   либо из более нового успешного запуска
   [Switch libnx audout music NRO](https://github.com/stanmasked/vandal-hearts-switch-remaster/actions/workflows/switch-audout-nro.yml),
   содержащего эти же изменения. Коммиты только с документацией
   **не пересобирают NRO автоматически**. Извлеките файл
   `audout-audio-switch-probe.nro` и запустите в поддерживаемой
   homebrew-среде, не путая его с графическим прототипом.
   В новой сборке рядом с NRO находятся
   `audout-audio-switch-probe.nro.sha256` и
   `audout-source-commit.txt`. Перед копированием на SD извлеките
   все три файла в одну папку и выполните в ней
   `sha256sum -c audout-audio-switch-probe.nro.sha256`.
   Содержимое `audout-source-commit.txt` должно совпадать с
   полным `Git source` на четвёртой странице отчёта;
   короткая версия коммита и состояние checkout показаны
   в заголовке каждой из четырёх страниц. Для опубликованной
   CI-сборки состояние ожидается `CLEAN`; `MODIFIED` и
   `NO-GIT` не следует путать с проверенным бинарным артефактом.
   Это связывает снимок экрана, исходный коммит и контрольную
   сумму конкретного NRO, но **не является цифровой подписью**
   и не доказывает успешное воспроизведение звука.
2. Для первого запуска **не кладите музыкальные файлы** в
   `sdmc:/switch/vandal-hearts-remake/audio/`: синтетический режим
   исключает влияние непроверенного оригинального банка.
3. Во время проигрывания нажмите **X** несколько раз с интервалами.
   Это безопасно на границе PCM-страниц проверяет `stop → start`
   **без повторной записи музыки**. **Y** проверяет
   `stop → close → open → start`, то есть переоткрытие `audout`.
   После каждого нажатия слушайте наличие звука и щелчков.
   Одновременное нажатие X+Y не выполняет операцию и учитывается
   отдельно. Диагностический сеанс длится примерно **42 секунды**
   музыкального времени (3600 блоков по 512 кадров, 44,1 кГц).

   **Отдельная управляемая проверка ошибки таймера:** в новом запуске
   (не смешивая с X/Y, HOME и отметками A/B) кратко нажмите **ZL**
   после начала воспроизведения. Одновременное ZL с X/Y/A/B отклоняется
   как неверная команда (`Result=30`): искусственная ошибка в таком
   случае не активируется. Следующая *действительно возвращённая*
   PCM-страница получит искусственно недопустимую частоту таймера
   только в диагностическом счётчике. Никакие PCM-данные и команды
   сервиса аудиовывода не подменяются. Если предыдущий дескриптор
   ошибочный, запрос остаётся активен до корректного возврата.
   Ожидаемый итог: `Result=28`, `PCM accounting=INVALID`,
   `timing=INVALID`, `untimed=1`, `ZL=INJECTED`, без повторной
   отправки уже принятой страницы из-за этой искусственной ошибки.
   Если ZL нажали слишком поздно и страница так и не вернулась,
   `ZL=ARMED`, `Result=31`: тест **не завершён**. Успешный
   исход этого теста означает только корректность обработки ошибочной
   телеметрии, а не слышимое восстановление звука.
   Дополнительная проверка сверяет `ZL=INJECTED` с действительно
   возвращённым PCM-дескриптором, `timing=INVALID` и ненулевым
   `untimed`. Противоречивые данные приводят к `Result=32` и
   `PCM accounting=INVALID`; такой отчёт нельзя считать
   успешной инъекцией. Проверка не симулирует отказ службы `audout`
   и не подтверждает слышимый звук.
4. При повторном запуске отдельно попробуйте **HOME → возврат в
   приложение** в начале и середине проигрывания. Это настоящий
   эксперимент со сворачиванием, **не эквивалент** проверок X и Y.
   В сборке с наблюдателем applet-сообщений **четвёртый экран**
   содержит `HOME bg/returns`, `OnResume`, `Focus duplicate/error`,
   `First PCM after HOME`, `pending`, `merged` и
   `HOME focus notify`. Счётчик `First PCM after HOME`
   увеличивается только после возврата конкретного дескриптора
   `audoutPlayBuffer` и успешной записи статистики страницы,
   уже после зарегистрированного возврата приложения на передний план.
   `pending` означает, что такого дескриптора ещё не наблюдали,
   а `merged` — несколько возвращений без промежуточной PCM-страницы.
   Строка `HOME timed returns avg/peak` измеряет средний/максимальный
   интервал (мкс) между уведомлением о возвращении на передний план и
   первой возвращённой PCM-страницей `audout`, используя один и тот же
   `armGetSystemTick()`. Строка `HOME lag bins <=1/2/4/>4x` группирует
   такие интервалы по отношению к длительности одной фактически возвращённой
   PCM-страницы в 48 000 Гц: не более 1×, от 1× до 2×, от 2× до 4×,
   свыше 4×. Границы 1×, 2× и 4× включены в предыдущий интервал.
   `HOME banded/timed` показывает число пригодных для этой классификации
   измерений и всех измерений с временной меткой. Строка
   `Undelivered submits all/pending` считает неудачные завершённые
   вызовы логической отправки PCM (все / пока ожидается первая
   страница после HOME). Такие вызовы **не засчитываются как возврат
   аудиостраницы**; ожидание остаётся активным даже после ошибочного
   дескриптора и неудачной остановки устройства. Последующая успешная
   повторная отправка той же PCM-страницы может завершить это ожидание.
   Число таких неудач не означает количество потерянных или
   неслышимых аудиокадров. Неизвестный бюджет страницы, отсутствующий
   timestamp или отсутствие возвращённой страницы не записываются
   как быстрый интервал. Если временная метка недоступна,
   переход **не включается** в среднее.
   Часы могут не учитывать время сна, а блокирующий системный вызов не
   эквивалентен моменту воспроизведения через динамики.
   Даже возврат PCM-дескриптора **не является доказательством звука**.
   Это только **наблюдавшиеся события libnx и сервиса audout**.
   При запуске как обычное Application проба запрашивает
   `SuspendHomeSleepNotify`; если запрос отклонён, показывается
   `UNAVAILABLE`. При запуске из Homebrew Menu в applet-режиме
   показывается `APPLET MODE`: сообщение о смене фокуса может не
   поступить, поэтому нулевые счётчики **не доказывают, что HOME
   не нажимали**. `OnResume` не гарантирован для каждого HOME.
   Не заключайте из успешного X/Y или наличия событий, что
   звук после HOME обязательно восстановился.
5. В процессе используйте **A** для субъективного замеченного дефекта
   звука и **B** для контрольной отметки «звучит нормально»; отпускайте
   обе кнопки между отметками. Это отметки человека, а не запись звука
   и не автоматический детектор заиканий.
6. После 3600 возвращённых страниц программа показывает **четыре
   экрана**: (1) сервис/DSP, (2) PCM и границы сцен, (3) отметки
   прослушивания A/B, (4) HOME и подтверждённые возвраты PCM.
   **LEFT/RIGHT** листают, **PLUS** завершает. Сфотографируйте все
   четыре страницы. На первой найдите `X stop/start ok/attempts`,
   `Y reopen ok/attempts`, `unsafe`, `mismatch` и `timing=VALID`.
   Если `timing=INVALID`, приложение обнаружило невозможность
   достоверно учесть время вызова `audoutPlayBuffer` (например,
   недоступную частоту таймера или переполнение). Поле
   `untimed` показывает число **подтверждённо возвращённых**
   PCM-дескрипторов, у которых время передачи измерить не удалось.
   Это значение не включает отказы `audout` с неверным дескриптором.
   Итоговая проверка дополнительно отклоняет невозможный учёт, при
   котором `untimed` превышает количество действительно успешно
   отправленных логических PCM-страниц, либо ненулевой `untimed`
   сочетается с `timing=VALID`.
   **Ошибка диагностики не равна ошибке возврата PCM:** уже
   переданная аудиостраница не должна отправляться повторно.
   Программа прервёт диагностику с кодом `Result=28` и
   `PCM accounting=INVALID`, не выдавая недостоверные временные
   измерения за подтверждённый звук.
   На четвёртой
   найдите `HOME bg/returns`, `First PCM after HOME`, `pending`,
   `HOME focus notify` и `Undelivered submits`. Норма для
   успешно выполненных команд — равные пары `ok/attempts`,
   `unsafe=0`, `mismatch=0`. При аппаратном отказе программа
   может прекратить проигрывание раньше и показать
   `INCOMPLETE`/`INVALID`; не интерпретируйте это как PASS.
   Значение `PCM accounting` и код `Result` повторены на четвёртом
   экране, чтобы показатели HOME можно было проверить по одному снимку.
   Если после HOME `pending=1` и не появился новый
   `First PCM after HOME`, устройство могло не вернуть PCM-страницу;
   это требует отдельного расследования и прослушивания.
7. Повторите пробы отдельно со звуком через динамики и наушники, если
   оба варианта доступны. Запишите версию Atmosphère/libnx или
   другого окружения, прошивку консоли, хеш/коммит NRO, число попыток
   X/Y, наблюдения при HOME, заметные щелчки и номера/фото страниц.
   Пользовательские игровые файлы, дампы содержимого SD и PCM
   выкладывать не нужно.

**Ограничения свидетельств:** X/Y вызывают сервисные операции только
после подтверждённого возврата дескриптора `audoutPlayBuffer`.
Они проверяют целостность музыкального времени и неизменность
уже возвращённой PCM-страницы. Обработчик applet-событий **только считает**
смены фокуса и сообщения OnResume; он не останавливает, не возобновляет
и не перезапускает `audout`. Подсчёт событий и возврат первого PCM-дескриптора не означают
ни успешное слышимое восстановление звука, ни факт нажатия HOME
при отсутствии сообщений. Статус `FULL` относится только к внутренней
согласованности диагностического учёта, а не к физическому аудиовыводу.
Реальные HOME/sleep, потеря устройства, ошибки ОС, слышимое качество
и длительные игровые сцены без физической проверки остаются непроверенными.
NeXium в CI проверяет графические кадры и сборку, **не записывает звук**.

## Установка файлов

Из собственной законно полученной копии игры подготовьте совместимую
тройку файлов: одну PlayStation `pQES`-последовательность и относящиеся
к ней банк `pBAV` (VH) и тело сэмплов (VB). Проба пока не извлекает
ресурсы автоматически из BIN/CUE и не угадывает соответствие банку.

Разместите **ровно эти три файла** на SD-карте (нижний регистр имён):

```text
sdmc:/switch/vandal-hearts-remake/audio/
    music.seq
    music.vh
    music.vb
```

Пути в исходном коде зафиксированы — данные читаются только локально.
Никаких записей обратно на карту, сетевых запросов или загрузки файлов
в GitHub нет. Дополнительные файлы в этой папке не используются.

## Сборка и запуск

Альтернативную SDL2-пробу при установленном SDL2 для Switch можно собрать командой:

```sh
make sdl2-audio-probe
```

Ожидаемый выход: `build/sdl2-audio-switch-probe.nro`. Его следует
перенести на консоль обычным для homebrew способом и запустить через
Homebrew Menu. Нужна практическая проверка наличия звука на
телевизоре/наушниках, отсутствия артефактов и показаний callback;
сам факт открытия SDL-аудиоустройства её не заменяет.

До начала звука приложение:

1. Ищет **все три файла** в указанной папке.
2. Ограничивает размеры (SEQ не более 256 КиБ, VH не более 68 128 байт,
   VB не более 8 МиБ) и отвергает пустые файлы.
3. Проверяет заголовки, упакованные программы/тоны, размеры VAG,
   целостность блоков SPU-ADPCM и события SEQ.
4. Декодирует используемые VAG в память на основном потоке.
5. Запускает нативный планировщик и синтезатор
   (512 кадров, 44,1 кГц, стерео, Gaussian, ADSR).

Отдельная память для PCM может потребовать до **28 МиБ** при
максимальном VB, плюс исходный VB до 8 МиБ и другие структуры.

**Важное правило отказа:** если все три файла отсутствуют,
проба использует полностью искусственные SEQ/VH/VB — это штатная
самопроверка. Если присутствует хотя бы один файл, но комплект
неполный, повреждён или превышает лимиты, запуск аудио прекращается
с ошибкой. Приложение **не** подменяет тихо неисправный пользовательский
набор синтетическим.

Загруженные PCM-буферы остаются действительными всё время работы
аудиоустройства. Освобождение происходит только после его закрытия.

## Проверка до копирования на Switch

Проверка пары VH/VB на компьютере:

```sh
python3 tools/inspect_vab_header.py /local/music.vh --vb /local/music.vb
python3 tools/inspect_ps1_seq.py /local/music.seq
```

Нативные хостовые тесты и санитайзер в GitHub Actions (без оригинальных
ресурсов) проверяют полностью синтетические файлы, в том числе неполный
набор, повреждённый VH/VB/SEQ, слишком большой SEQ и неизменность
исходных файлов:

```sh
make test-audio-stream
```

## Измерение производительности на Nintendo Switch

В варианте через `libnx audout` NRO теперь выводит каждые **128 блоков**
три аппаратных показателя для DSP-конвейера:

- `DSP compute avg` — средняя вычислительная стоимость SEQ → SPU →
  STUDIO_C → преобразование 44,1/48 кГц, в микросекундах;
- `peak` — максимальная стоимость одного блока с начала запуска;
- `over budget` — число блоков, вычисление которых заняло больше
  временного бюджета **512 / 44100 секунды (около 11,61 мс)**.

Измерение использует аппаратный монотонный счётчик AArch64
`armGetSystemTick()` и его реальную частоту. Блокирующее ожидание
`audoutPlayBuffer` и обновление консоли **не входят** в вычислительное
время. Это оценка нагрузки синтезатора, а не счётчик фактических
прерываний/пропусков аудио в сервисе Switch. Для диагностики на
консоли важно дополнительно слушать звук и отмечать щелчки и
заикания. Сильные пики при включённой STUDIO_C помогут выбрать
направление оптимизации.

## Ограничения

Это самостоятельная аудиопроба, а не подключение саундтрека к игровым
сценам. Продолжают требовать проверки: точность PS1-таблицы высоты,
эффекты и реверберация SPU, особенности реального управления голосами,
соответствие громкости эталонной PlayStation, совместимость разных
музыкальных банков и многосекционных композиций. В этом режиме
воспроизведение SEQ циклическое до окончания времени пробы.

На дату добавления функциональности ни успешная NRO-сборка именно с
этой загрузкой, ни аудиотест на физической Switch не подтверждены.


## STUDIO_C: нативная реверберация SPU

Нативный синтезатор дополнен `source/vh_spu_reverb.c` и
`source/vh_spu_reverb.h`, повторяющими программную схему
**STUDIO_C** из референсного PC-порта:

- внутренний буфер `0x37F0` сэмплов, сеть отражений, comb- и all-pass-фильтров;
- 39-коэффициентный FIR-фильтр и обработка на 22 050 Гц с восстановлением
  результата до рабочего потока 44 100 Гц;
- отдельный посыл в эффект только для тонов с `VagAtr.mode & 4`,
  передающийся `VH → VhSeqTone → SEQ → SPU`;
- продолжение вычисления эффекта после `Note Off` и при нулевом входе,
  чтобы хвост затухал самостоятельно.

Режим по умолчанию у `VhNativeSpu` остаётся **сухим** и совместимым
с предыдущими числовыми PCM-тестами. В обеих диагностических пробах
музыки ревербератор явно включается с глубиной `0.5` (половина
wet-уровня), чтобы тестировать новую цепочку без изменения законов
громкости сухого сигнала. Значение 0.5 — **диагностическая настройка**,
а не утверждение о точной глубине эффекта в оригинальной игре.

Хостовая проверка `tests/test_vh_spu_reverb.c` покрывает
детерминированность, сохранение состояния, ненулевой хвост после
отключения посыла, отсутствие непрошеного эффекта, граничные
значения глубины и сброс. Проверки включены в `make test-audio-stream`
и GitHub Actions под UBSan. Отдельный AArch64-модуль ревербератора
добавлен в сборку.

Сравнение звучания с физической PlayStation и измерение времени
затухания на реальной Switch остаются необходимыми для окончательной
калибровки. Успешная CI/NRO-сборка не является доказательством
аппаратно-точного звучания.
