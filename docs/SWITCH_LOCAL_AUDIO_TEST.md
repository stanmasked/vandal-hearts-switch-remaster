# Nintendo Switch — локальная проверка аудио SEQ/VH/VB

**Статус:** диагностическая SDL2-проба, не законченный порт музыкального
движка Vandal Hearts. Пользовательские игровые файлы никогда не входят в
исходники, CI или готовую NRO-сборку.

## Рекомендуемая NRO-проба: штатный libnx audout

Теперь поддерживаются **два диагностических аудиобэкенда**:

- `audout-audio-switch-probe.nro` — собирается только с devkitPro/libnx,
  без SDL2. Музыкальный синтезатор сохраняет точность внутреннего
  тайминга 44 100 Гц; потоковый линейный ресемплер преобразует готовый
  стерео-PCM в 48 000 Гц — частоту устройства `audout`.
- `sdl2-audio-switch-probe.nro` — прежняя SDL2-проба с теми же
  SEQ/VH/VB/SPU и прямым буфером 44 100 Гц. Зависит от установленного
  `switch-sdl2`; загрузка пакета в GitHub Actions может быть недоступна
  из-за ответа сервера зеркала HTTP 403.

Без дополнительных portlibs можно собрать первую пробу:

```sh
make audout-audio-probe
```

Успешный GitHub Actions запуск `Switch libnx audout music NRO`
содержит артефакт `native-audout-music-nro` — проверенный
как NRO-контейнер бинарный файл. Содержимое игры в нём отсутствует.

Выполненные до настоящего времени тесты подтверждают **создание
бинарного NRO**, но ещё не подтверждают слышимый звук или
совместимость с конкретным набором из оригинальной PlayStation.
Для реальной аудиопроверки запускайте пробу на своей Switch
в поддерживаемой homebrew-среде.

## Установка файлов

Из собственной законно полученной копии игры подготовьте совместимую
тройку файлов: одну PlayStation `pQES`-последовательность и относящиеся
к ней банк `pBAV` (VH) и тело сэмплов (VB). Проба пока не извлекает
ресурсы автоматически из BIN/CUE и не угадывает соответствие банку.

Разместите **ровно эти три файла** на SD-карте (нижний регистр имён):

```text
sdmc:/switch/vandal-hearts-remake/audio/
    music.seq
    music.vh
    music.vb
```

Пути в исходном коде зафиксированы — данные читаются только локально.
Никаких записей обратно на карту, сетевых запросов или загрузки файлов
в GitHub нет. Дополнительные файлы в этой папке не используются.

## Сборка и запуск

Альтернативную SDL2-пробу при установленном SDL2 для Switch можно собрать командой:

```sh
make sdl2-audio-probe
```

Ожидаемый выход: `build/sdl2-audio-switch-probe.nro`. Его следует
перенести на консоль обычным для homebrew способом и запустить через
Homebrew Menu. Нужна практическая проверка наличия звука на
телевизоре/наушниках, отсутствия артефактов и показаний callback;
сам факт открытия SDL-аудиоустройства её не заменяет.

До начала звука приложение:

1. Ищет **все три файла** в указанной папке.
2. Ограничивает размеры (SEQ не более 256 КиБ, VH не более 68 128 байт,
   VB не более 8 МиБ) и отвергает пустые файлы.
3. Проверяет заголовки, упакованные программы/тоны, размеры VAG,
   целостность блоков SPU-ADPCM и события SEQ.
4. Декодирует используемые VAG в память на основном потоке.
5. Запускает нативный планировщик и синтезатор
   (512 кадров, 44,1 кГц, стерео, Gaussian, ADSR).

Отдельная память для PCM может потребовать до **28 МиБ** при
максимальном VB, плюс исходный VB до 8 МиБ и другие структуры.

**Важное правило отказа:** если все три файла отсутствуют,
проба использует полностью искусственные SEQ/VH/VB — это штатная
самопроверка. Если присутствует хотя бы один файл, но комплект
неполный, повреждён или превышает лимиты, запуск аудио прекращается
с ошибкой. Приложение **не** подменяет тихо неисправный пользовательский
набор синтетическим.

Загруженные PCM-буферы остаются действительными всё время работы
аудиоустройства. Освобождение происходит только после его закрытия.

## Проверка до копирования на Switch

Проверка пары VH/VB на компьютере:

```sh
python3 tools/inspect_vab_header.py /local/music.vh --vb /local/music.vb
python3 tools/inspect_ps1_seq.py /local/music.seq
```

Нативные хостовые тесты и санитайзер в GitHub Actions (без оригинальных
ресурсов) проверяют полностью синтетические файлы, в том числе неполный
набор, повреждённый VH/VB/SEQ, слишком большой SEQ и неизменность
исходных файлов:

```sh
make test-audio-stream
```

## Измерение производительности на Nintendo Switch

В варианте через `libnx audout` NRO теперь выводит каждые **128 блоков**
три аппаратных показателя для DSP-конвейера:

- `DSP compute avg` — средняя вычислительная стоимость SEQ → SPU →
  STUDIO_C → преобразование 44,1/48 кГц, в микросекундах;
- `peak` — максимальная стоимость одного блока с начала запуска;
- `over budget` — число блоков, вычисление которых заняло больше
  временного бюджета **512 / 44100 секунды (около 11,61 мс)**.

Измерение использует аппаратный монотонный счётчик AArch64
`armGetSystemTick()` и его реальную частоту. Блокирующее ожидание
`audoutPlayBuffer` и обновление консоли **не входят** в вычислительное
время. Это оценка нагрузки синтезатора, а не счётчик фактических
прерываний/пропусков аудио в сервисе Switch. Для диагностики на
консоли важно дополнительно слушать звук и отмечать щелчки и
заикания. Сильные пики при включённой STUDIO_C помогут выбрать
направление оптимизации.

## Ограничения

Это самостоятельная аудиопроба, а не подключение саундтрека к игровым
сценам. Продолжают требовать проверки: точность PS1-таблицы высоты,
эффекты и реверберация SPU, особенности реального управления голосами,
соответствие громкости эталонной PlayStation, совместимость разных
музыкальных банков и многосекционных композиций. В этом режиме
воспроизведение SEQ циклическое до окончания времени пробы.

На дату добавления функциональности ни успешная NRO-сборка именно с
этой загрузкой, ни аудиотест на физической Switch не подтверждены.


## STUDIO_C: нативная реверберация SPU

Нативный синтезатор дополнен `source/vh_spu_reverb.c` и
`source/vh_spu_reverb.h`, повторяющими программную схему
**STUDIO_C** из референсного PC-порта:

- внутренний буфер `0x37F0` сэмплов, сеть отражений, comb- и all-pass-фильтров;
- 39-коэффициентный FIR-фильтр и обработка на 22 050 Гц с восстановлением
  результата до рабочего потока 44 100 Гц;
- отдельный посыл в эффект только для тонов с `VagAtr.mode & 4`,
  передающийся `VH → VhSeqTone → SEQ → SPU`;
- продолжение вычисления эффекта после `Note Off` и при нулевом входе,
  чтобы хвост затухал самостоятельно.

Режим по умолчанию у `VhNativeSpu` остаётся **сухим** и совместимым
с предыдущими числовыми PCM-тестами. В обеих диагностических пробах
музыки ревербератор явно включается с глубиной `0.5` (половина
wet-уровня), чтобы тестировать новую цепочку без изменения законов
громкости сухого сигнала. Значение 0.5 — **диагностическая настройка**,
а не утверждение о точной глубине эффекта в оригинальной игре.

Хостовая проверка `tests/test_vh_spu_reverb.c` покрывает
детерминированность, сохранение состояния, ненулевой хвост после
отключения посыла, отсутствие непрошеного эффекта, граничные
значения глубины и сброс. Проверки включены в `make test-audio-stream`
и GitHub Actions под UBSan. Отдельный AArch64-модуль ревербератора
добавлен в сборку.

Сравнение звучания с физической PlayStation и измерение времени
затухания на реальной Switch остаются необходимыми для окончательной
калибровки. Успешная CI/NRO-сборка не является доказательством
аппаратно-точного звучания.

## События игровых сцен и музыкальные переходы

Добавлен самостоятельный C11-контроллер `source/vh_music_scene.h/.c`.
Это граница между игровой логикой и уже существующими
SEQ/VH/VB/SPU, пригодная для будущих сцен меню, боя и итогового экрана.

Команда `vh_music_scene_request(scene, cue, fade_blocks)`
принимает идентификатор сцены, заранее загруженный SEQ,
callback разрешения инструментов, адрес музыкального банка и
число 512-кадровых блоков для затухания. `NULL` вместо `cue`
означает тишину. Повторная команда с тем же активным идентификатором
не перезапускает музыку. Повреждённый SEQ отвергается **до**
изменения текущего воспроизведения. Во время уже выполняемого
перехода возвращается `-2`, чтобы не возникал резкий скачок
громкости из-за перезапуска огибающей.

`vh_music_scene_render()` каждый раз производит ровно
512 PCM-кадров 44,1 кГц, применяет плавную покадровую
огибающую в формате Q15, сбрасывает старые голоса и состояние
STUDIO_C **после** исчезновения их звука, а новую SEQ запускает
на границе следующего блока. Интерполяция Gaussian и настройки
реверберации сохраняются. Декодирование VAG и обращение к
файловой системе при переключении отсутствуют.

При затухании источник SEQ/VH/VB и декодированный PCM старой
сцены обязаны оставаться в памяти. Освобождать их безопасно
только после окончания перехода; контроллер не владеет файлами
или памятью пользовательских ресурсов. Вызовы управления и
рендеринга должны быть синхронизированы вызывающим кодом:
эта версия не предоставляет межпоточный lock-free mailbox.

Диагностическая `audout-audio-switch-probe.nro` теперь
использует этот интерфейс. Только в синтетическом режиме
после 384 блоков отправляется команда на вторую искусственную
SEQ, а после 768 — обратно на первую, оба раза с
8-блочной огибающей (около 93 мс в каждом направлении).
Когда найдены пользовательские файлы `music.seq/music.vh/music.vb`,
они воспроизводятся без этих демонстрационных переключений.

`tests/test_vh_music_scene.c` проверяет неизменность активного
воспроизведения при ошибке, отсутствие повторного key-on для
того же scene ID, точную 512-сэмпловую огибающую, два
последовательных fade-блока, отсутствие старых голосов после
переключения, сброс ревербератора и явную остановку в тишину.
Хостовый CI выполняет строгую сборку C11 и UBSan, а отдельная
сборка AArch64 компилирует новый контроллер.

**Граница функциональности:** пока подключение сделано в
самостоятельной диагностической аудио-NRO, а не в главном
тактическом renderer/NRO. Это инфраструктура для событий
игровых сцен, не полноценный игровой интерфейс с
несколькими оригинальными музыкальными треками.
