# Vandal Hearts Remake — Stage299: captured virtual PCM stream indicators

Following [successful Stage298 NeXium CI 39125903692](https://github.com/stanmasked/vandal-hearts-switch-remaster/actions/runs/39125903692),
the next diagnostic goal is distinct from `audoutPlayBuffer` **API
blocking-time** measurements: inspect the actual PCM bytes recorded
by the host's isolated virtual PulseAudio sink.

The Stage299 tool `tools/analyze_nexium_pcm_stream_integrity.py`
reads TWO independently captured virtual-stereo 48-kHz s16le streams
from the current NeXium run:

- `runtime-evidence/nexium-monitor-s16le-48k.pcm` — the general
  45-second virtual-sink capture, pinned against
  `pcm-quality-report.json`;
- `runtime-evidence/nexium-scenes-s16le-48k.pcm` — the music-scene
  A/B capture, pinned against `scene-audio-report.json`, with actual
  host-recorded `scene-events.csv` offsets.

Both source reports are independently generated by the pre-existing
CI chain. Stage299 re-reads the PCM bytes, validates exact SHA-256,
format, frame alignment, duration, source type, and prior diagnostic
scope and refuses aliases/symlinks. It checks five strictly ordered
frame-aligned host *approximate* scene event markers.

It records transparent, reproducible **indicators**:
- Total 4-byte stereo frames and 10-ms block count, including partial
  tail block;
- SHA-256 commitment of every original 10-ms PCM block digest,
  exact-zero stereo frames and runs and low-RMS 10-ms blocks;
- Longest exact-zero run and jumps of ≥4096 sample units across
  adjacent frames, including jumps aligned to a 10-ms block boundary;
- Whether both independent monitor/scene raw captures remain bound
  to the prior reports and whether they differ.

**These are NOT gap/dropout verdicts.** Zero sections may be
ordinary musical rests, startup, or intentional silence; sharp sample
steps may be intentional transients. Raw PCM has no independent
per-frame production timestamp or byte-exact reference waveform, so
lost/duplicated samples cannot be proved by PCM bytes alone. The
host-captured music event offsets are buffered estimates rather than
guest-sample timestamps. No OS scheduler, Nintendo Switch hardware
DAC state, user headphones, physically audible music or original
soundtrack was measured.

The new JSON is
`runtime-evidence/pcm-stream-integrity-stage299.json`. It is archived
alongside the raw PCM, source-quality report and scene-event evidence.
The actual synthesis code, guest audout query frequency, NRO and
SPU/PCM generation are unchanged by this offline audit.
